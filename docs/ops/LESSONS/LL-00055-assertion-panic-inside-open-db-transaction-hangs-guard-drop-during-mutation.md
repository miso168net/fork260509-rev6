LL-00055｜判準變異令交易體內的斷言轉紅——panic 留下持列鎖的交易中連線、帶界守衛 Drop 永等，cargo 無聲卡 50 分鐘後被逾時殺並留序列殘值（006 刀 U7）

**徵狀**：006 刀 U7 implementer-1 做判準變異「受保護判定移到寫入之後」的首版時，撤銷路徑受保護列探針的斷言寫在交易收場之前。變異令撤銷先落寫、探針斷言轉紅＝panic；cargo 零輸出、無完成訊號，50 分鐘後被容器內 `timeout` 殺掉。殘留恰一項：授權表 id 序列前進一號（表面零差、schema-gate 之 seed 閘紅）。agent 以走查基準之現讀值單句還原該序列，其後走查 diff 全等、schema-gate 復綠；主線收尾再以走查 diff（基準含該序列）與 schema-gate 復核。

**成因**：與 LL-00037 同一機制——panic 展開時未提交的交易物件被丟棄、rollback 只排入佇列，連線停在交易中持列鎖；同一行程內帶界守衛 Drop 的回補寫入等這把鎖，永遠等不到。LL-00037 的守法只點名佔位（`todo!()` 等），而斷言、`expect`、`unwrap` 同樣會在交易體內 panic；判準變異的目的正是讓斷言轉紅，變異期因此是最易觸發的時點。序列殘值＝變異中新授 INSERT 已取的號（序列不隨 rollback 回退），守衛又來不及收尾。

**處置**：探針改為交易內只取計數、交易收場後才斷言（計數與斷言拆成兩步，斷言之 doc 載明須於收場後呼叫）；同檔八處用法全改，該發變異重跑正常轉紅、無卡死。

**晉升面**：none——守法寫進本檔與後續單元定義。

**再犯面與守法**：真庫案的斷言、`expect`、`unwrap` 一律放在交易收場（commit 或 rollback）之後；交易體內只收集結果，以 `Result` 或計數值帶出交易再判——判準變異期尤其承重。跑測試若零輸出長時間不動，先查 `pg_stat_activity` 的 idle in transaction 連線（同 LL-00037）；卡死被殺之後，以走查 diff 與 schema-gate 逐項指名殘值再處置。
