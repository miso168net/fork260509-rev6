LL-00088｜「新增圈界塊拔標記必紅」對夾在修改型替換塊裡的新增塊不成立：基線單行 `<script setup lang="ts"></script>` 拆成開閉兩行、新增塊夾其間，START 與 END 同拔時 lint 照綠（007 刀 U20）

**徵狀**：
- 007 刀 U20（T089）：`base-web/src/views/user-center/index.vue` 之基線 L1 為單行 `<script setup lang="ts"></script>`。改寫為「SFC 頂層修改型標記＋`<script setup lang="ts">`＋(vi) 圈界塊（圈 `import PasswordCard`）＋`</script>`」後，該塊 START 與 END 同拔，`python3 tools/fork-delta-lint.py` rc 0；只拔 START（孤 END）、只拔 END（未閉合 START）兩形照紅。
- 規格對照第 1 輪依本刀計畫契約碼面閘章 §1.5「本刀每一新增圈界塊逐塊暫拔必報未圈界」列 blocker。fix 輪查無合規修法、零改動升級：上移標記違反「修改型標記緊鄰新行之上」；以空行隔開會被 oxfmt 刪掉；改用非 setup 之 `<script>` 註冊元件會偏離 rev5 形。兩支 implementer 亦各自升級同一項。

**成因**：
1. `find_unmarked_additions` 只驗純新增塊；塊內含被移除之基線行者（替換塊）由其 `原行:` 標記涵蓋，工具 docstring 載為已知殘留①。
2. 基線單行被拆成開、閉兩行，新碼只能落在兩行之間，與該行之修改型同處一個 change-block。圈界標記行因此只是替換塊裡的普通新增行，拔掉也不改變「塊內有修改型標記」的判定。
3. 計畫期 §1.5 只把巢狀 (vii) 塊列為不適用形，沒有逐塊檢查其他新增塊是否也落在某個替換塊內。上游原因與 LL-00087 相同：計畫寫下的驗證法沒先對預期碼形實跑。

**處置**：U20 收尾照巢狀 (vii) 之先例，在 §1.5 增列此塊為不適用形，並在 §8.3、T092 DoD、T109② 補註。同拔形之機器守＝PATCH 實數化後之範圍欄對賬腿：主線以憲法副本把該列「預估」實數化後實跑，未變異 rc 0，同拔報「新增型：注記合計 1 塊 ≠ 實數 0 塊」。只拔 START、只拔 END 兩形由圈界首尾成對檢查（007 刀 U18b）判紅。承載單元出口以通則⑤字面計數恰 1 入 commit 訊息。

**晉升面**：none。判準本體已在碼面閘（對賬腿與成對檢查），守法落在 tasks 撰寫與單元定義審讀。

**再犯面與守法**：
- 計畫列「拔標記必紅」之射程時，逐塊判其 change-block：凡新增塊必夾在某修改型之替換塊內（基線單行被拆開而新碼落其間、或塊巢狀於既有塊內），即在計畫期列為不適用形並指定承載（成對檢查兩形＋通則⑤計數＋PATCH 後對賬腿）。
- 拿不準時，派發前以工具同法（`difflib` 對基線與預期碼形）實跑一次，看該塊是純新增塊還是替換塊。
