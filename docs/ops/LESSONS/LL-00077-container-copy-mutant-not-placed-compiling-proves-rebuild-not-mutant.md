LL-00077｜容器副本之變異植入命令帶無效旗標（`docker compose cp -q`）整句報錯、未核 rc，後三支變異全跑在前一支之上而同樣紅——RL-0085 之「見 `Compiling`」只證重編、不證所編為本變異（007 刀 U12）

**徵狀**：007 刀 U12 implementer-2 對 `cache::incr_with_window` 之原子形做副本變異（容器內副本＋獨立 `CARGO_TARGET_DIR`），M5a～M5e 五支依序植入。M5b～M5e 的首跑 log 全是同一則失敗（`multi：一呼之下須恰 +1` left 114／right 115）＝M5a 的紅；其中 M5e 是 doc 列為射程外、預期存活的形，也紅了才露餡。四支 log 改名 `*.INVALID-not-placed.log` 作廢，改為「植入後逐檔 `cmp` 核在位」再重跑：M5b～M5d 各紅於自身判準、M5e 存活，與宣告一致。

**成因**：①`docker compose cp` 沒有 `-q` 選項，整句以未知旗標報錯、檔案沒放上去；植入腳本未核該句 rc，接著照跑。副本裡留著的仍是 M5a。②每支照 RL-0085 自證重編：log 見 `Compiling server`。但重編的對象是副本裡現存的檔（M5a），不是本支變異——RL-0085 擋的是「沒重編」，擋不到「重編了錯的檔」。LL-00021 是同一族（執行物不是本變異：drvfs 上 `.pyc` 沿用前一支），其守法只寫了 python 快取一途。

**處置**：implementer-2 自察作廢、改「植入→`cmp` 副本檔對預期變異檔→跑→還原→`cmp`」重跑（log 與腳本留 gitignored 工作區）。重跑結果才入回報。主線收尾以 `docker compose cp --help` 核得無 `-q` 選項，坐實成因。

**晉升面**：none——守法句由主線自 007 刀 U13 起烤入單元定義 CONTEXT（關鍵字「植入在位」），組裝時依 LL-00072 守法以 grep 核在場。RL-0085 是否增「植入後核在位」一款，併入 007 刀收刀前提請 user 裁定之升 RULES 清單。

**再犯面與守法**：凡變異演練（就地或容器副本）植入後、執行前，先以 `cmp`（或 sha）核受測位置之檔＝預期變異檔；植入命令逐句核 rc（`set -e` 或逐句判），報錯即停、不往下跑。逐支變異之間先還原再植下一支，並核還原後＝原檔。判讀變異結果前另看對照：預期存活之射程外形若也紅、或多支變異紅於同一則訊息，先疑執行物不是本變異。
