LL-00083｜單元定義之主線裁定未逐條取證：列舉表值未標是否窮舉、未對齊凍結契約指定之承載者，預期態憑推想未實跑——fix 輪兩輪兩解多耗一輪審查、其後 12 支 agent 之回報皆列此預期差異（007 刀 U16）

**徵狀**：
1. 單元定義裁定④寫「`MAINLAND_TERMS`：初版必收詞全收、另收『常量』；具歧義之詞與非大陸專用語不入表」，沒寫這份清單是否窮舉。007 刀凍結契約 code-gates §2.1 腿①另有一句：Big5 內簡繁同形異用字「由腿③以詞境承擔」。implementer 與規格對照第 1 輪之 fix 都把裁定④讀成窮舉：不擴詞表，並在射程外段把于／后以外之同形異用字大陸用法寫成「審查兜底」；第 3 輪審查據契約承載句列 blocker，該輪 fix 改讀成非窮舉、補詞條 79 個。同一句裁定兩輪兩解，多耗一輪審查與修補。
2. 裁定⑥預期「新工具 `git add` 前 `python3 -B tools/docsync test` 恰一敗」，實得三敗（GT-09、GT-12 各有一支讀真 repo tracked 集之案，另加總案）。其後 12 支 agent（implementer 1、規格對照審查 4、fix 6、碼品質審查 1）之回報皆列出此差異，數支另以記憶體內模擬 tracked 重跑補證。

**成因**：
- 裁定是派發前寫進 prompt 的不可違反項，agent 只能照字面讀。列舉值不標窮舉性，每一輪 agent 就各自解讀；派發前也沒有逐條對照凍結契約，看該事項是否已指定承載者。
- 預期態沒有實跑：寫裁定時只想到總案，沒有枚舉哪些測試讀真 repo 的 tracked 集。

**處置**：U16 收尾，主線逐詞審過新增的 79 個同形異用字詞條後接受（契約腿①承載句因此成立）；裁定⑥之差異記入收單訊息。

**晉升面**：none。判準同 RL-0028（prompt 之事實接地每條附出處、不憑印象寫）；守法落在主線撰寫單元定義時。

**再犯面與守法**：
- 裁定列舉表值或允許項時，明寫「窮舉」或「至少含、本單元可增列」；並逐條對照凍結契約，已指定承載者之事項，裁定不得收窄成審查兜底。
- 裁定寫預期態（某閘幾錯、某測試幾敗）前，先在工作區模擬取證，寫實得值與所用命令；做不到就寫「預期非綠，確切數以實跑為準」。
