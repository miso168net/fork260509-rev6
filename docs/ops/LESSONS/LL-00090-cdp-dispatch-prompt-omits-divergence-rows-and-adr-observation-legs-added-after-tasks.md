LL-00090｜CDP 派工 prompt 只照 task 具名清單編寫：實作期新增之分岔列與 ADR 草稿宣稱之「CDP 實測」腿全數漏跑，到 ADR 親決前對帳才發現（007 刀 U22）

**徵狀**：
- 007 刀 U22 T099 之 CDP 三方對照（三支 agent）prompt 依 T099 文字之單邊增項與 quickstart §10 逐面編寫。spec 刻意分岔登記表於實作期（U17～U18d 碼品質審查升級、user 親決）新增 8 列（搜尋卡往返回收桶後之重置、確定鈕送出中、隨機密碼之政策讀取在途、抽屜送出在途關閉改開他列、兩頁回收桶開關快速切換、會話政策被拒後之重試、浮層送出在途關閉後重開），其承載 task 之 DoD 只有 typecheck／lint／fork-delta-lint，未要求行為觀察。T099「刻意分岔表各列之 rev6 側逐項判」這句總括句沒有展成 prompt 項目。
- 實作期起草之 ADR-00091 決定 7（對照腿、部分成功腿）與 ADR-00081 款 17 後半都寫明「本刀 CDP 實測」，T101 之已知態觀察 prompt 只列款 10／11／20 與並行編輯主腿。
- T103 親決前逐條對帳才發現。經 user 放行以 32080 單邊補跑（10 項、約 33 分；10／10 過、零新分岔），另重做一次走查還原。

**成因**：
1. prompt 項目只取 task 文字裡的具名清單。總括句（「各列」）沒有以機器枚舉展開；分岔表與 ADR 草稿是在 task 撰寫之後增列的，task 文字沒有同步。
2. 實作期新增 UI 時序修正的單元，DoD 只驗靜態閘，行為驗證默認交給 CDP 單元；CDP 單元的 prompt 卻不知道有這些列。兩邊各自以為對方會做。

**處置**：補跑 CDP（32080 單邊、22080 側以 rev5 凍結碼靜態對賬）；ADR-00081 款 17、ADR-00091 決定 7 寫入實測結果；T099／T101 落地註記記補跑。

**晉升面**：none。這是走查派工前的對賬紀律，不是碼面或文件之判準。

**再犯面與守法**：
- 任何走查（CDP、quickstart）派工前，先以機器枚舉「宣稱由本單元實測」的全部承載面：spec 刻意分岔表逐列、ADR 草稿中「CDP」「實測」之句、quickstart 對應節。再與 prompt 項目做集合對賬：每一面至少對到一個 prompt 項，或附具名排除理由。對不上就不發射。
- 實作期新增分岔列或 ADR 觀察義務時，同顆在承載走查的 task 補一條具名項（RL-0015 回填形），不靠總括句承接。
