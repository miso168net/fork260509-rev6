LL-00086｜圈界判定只問「新增塊內有沒有標記行」：塊尾 END 本身就是合法標記行，只拔 START、留下 END 時，該塊照樣算有標記，lint 照綠，半套圈界不被攔下（007 刀 U17 揭出，U18b 補成對檢查）

**徵狀**：
- 007 刀 U17 主線親跑 §1.5 逐塊暫拔時，多跑了一發「只拔 START、留 END」：`python3 tools/fork-delta-lint.py` rc 0。當時裁定㉒判為工具既有射程、另案評估，§1.5 之法暫定為 START 與 END 同拔。
- U18b 以真檔復現：只拔使用者頁 `index.vue` 某 (v) 塊之 START，改動前之工具（HEAD 版）rc 0。
- 反向的「只拔 END、留 START」雖然會紅，報出的卻是成串連帶的缺 `原行:`（使用者頁 31 條、抽屜 32 條），真因排在最後。該段補法還會引人去逐行補假 `原行:`。

**成因**：
- `find_unmarked_additions` 以 difflib 變更塊為單位判斷：純新增塊內只要任一行是合法標記行（`_block_has_marker`），整塊即算「有標記」。
- 塊尾 `… END]` 行本身就是合法標記行。只拔 START 時，塊尾與新增行仍落在同一個純新增變更塊內，於是照綠。
- `_outside_addition_blocks` 用深度計數，對孤 END 寬容，唯一的消費者是 `find_missing` 之計次，所以也攔不下。
- 只拔 END 時，未閉合之 START 會讓排除範圍一路延伸到檔尾。其後的基線行因此不計為存留，`find_missing` 便把它們全判成缺。這條紅是連帶出來的，不是對真因的診斷。
- 兩道判準都是「有沒有」的存在檢查；首尾成對、名稱相符這類結構性質，沒有一道在驗。

**處置**（007 刀 U18b、T113）：
- `tools/fork-delta-lint.py` 新增 `find_unpaired_edges`：合法標記行之 START／END 依出現序以堆疊配對；名取 `[rev6-inline` 之後到 START／END 之前之全文，逐字比對。
- 孤 END、到檔尾仍未閉合之 START、名不符之 END 皆 rc 1，逐處指名檔:行與兩端名。報出段排在缺原行段之前；同檔另有未閉合 START 時，加印連帶提示。
- self-test PR1～PR8 涵蓋合法巢狀、各註解臂、名逐字比之判別案、不牽連其外之塊，以及真 scan 接線。三判準與接線逐支停用，各有獨占紅案。
- 既有計法（`find_missing`、`_outside_addition_blocks`）零改。

**晉升面**：gate——判準住碼面閘本體，由 pre-commit fork-delta 段實跑。

**再犯面與守法**：
- ①標記類判準只做存在檢查時，先問兩件事：標記能不能只留半套，卻仍滿足判準？成對、巢狀、同名這類結構性質，要另立結構檢查來驗，不能靠「有標記」代驗。
- ②§1.5 逐塊暫拔分三發，各守一處：START 與 END 同拔（缺圈界腿）、只拔 START（成對腿：孤 END）、只拔 END（成對腿：未閉合 START，另有連帶缺原行）。
- ③新增報出段時，連帶錯誤若排在真因之前，真因就會被淹沒。報出順序與連帶提示，要用「只拔 END」這類會連帶出錯的變異實測過，才算定案。
- 同族：LL-00058、LL-00084（兩者都是「圈界落在含移除碼之變更塊內、拔標記照綠」）。本坑的機制不同（存在檢查把 END 計為標記），是 LL-00084 守法「lint 綠只證有標記，圈界受守與否以 §1.5 實得為準」所揭出，不是重犯。
