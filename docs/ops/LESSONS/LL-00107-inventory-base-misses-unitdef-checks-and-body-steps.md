LL-00107｜派發前清冊只切 tasks 粗體 DoD：單元定義另加之收尾必跑「`zh-tw-lint.py check` rc 0」對只改 RUNBOOK 之單元零判定力，task 內文編號步驟之斷言亦全數漏列（008 刀 U16）

**徵狀**：
- 008 刀 U16 之單元定義（主線所寫）在收尾必跑列 `python3 tools/zh-tw-lint.py check` rc 0。該工具只讀 base-web 之 `zh-tw.ts` 與 `zh-cn.ts` 兩支固定路徑，而本單元只改 RUNBOOK，這條恆綠、沒有判定力。同份單元定義另述「docsync 對 RUNBOOK 只讀 §12」，此說不實：GT-05、GT-06、GT-07、GT-12 皆讀全檔。
- 主線之首份派發前清冊照 RL-0008 當時字面，只切粗體 DoD 段。T146 內文①～⑥之斷言全數漏列，T147～T149 之內文斷言、派發前①～④與單元定義另加之命令也都不在冊上；結論句卻寫「零射程外子句、零須改 tasks 字面」。
- side agent 經 user 轉來提醒，指出首份清冊只切粗體 DoD。主線改以清冊 workflow 對三層全集重做，得 62 筆：blocker 2、major 27、minor 33。兩鏡確認 56 筆、駁回 6 筆，上述各形皆在其中。

**成因**：
1. RL-0008 當時字面為「清冊以該單元 DoD 子句全集為底（以「；」分開之子句一列）」，單元定義與主線腳本另加之驗證命令、task 內文編號步驟之斷言都不在基底內。這段字面照 user 首次裁定之選項寫成，但該選項所舉之例（T141①「八支新檔 eslint rc 0」）本身就在 task 內文、不在粗體 DoD：字面窄於意旨。
2. 主線自加之驗證命令沒有派發前核對。LL-00106 所述之「rc 0 類綠斷言逐檔核射程」只用在 tasks 字面上，同形換到單元定義層就沒人看。同根前四形為 LL-00082、LL-00085、LL-00105、LL-00106。

**處置**：
- user 2026-10-27 裁定清冊基底納入第三層。RL-0008 改寫為以驗收斷言全集三層為底：tasks 粗體 DoD 子句、task 內文編號步驟之斷言、單元定義與主線腳本另加之驗證命令；「指不出或屬射程外」之出口，由只改 tasks 擴為改 tasks 或單元定義。
- 同批改正 P-E7「DoD 判定脫節」列與 CLAUDE.md §2 單元收尾⑥之指針句，並更正 LL-00106 對 U15 eslint 斷言出處之誤述。
- U16 之 tasks T143～T149 依清冊確認各筆加★裁定註；主線演練腳本改為判 rc、加正向對照，jobs 檢查命令改自 RUNBOOK 抽取、逐字比對。
- 單元定義之兩處失實屬在飛工件，未改，記於 U16 收單訊息。

**晉升面**：rules（RL-0008 清冊基底擴三層；主線派發前 checklist）。

**再犯面與守法**：
- 派發前清冊涵蓋三層。第一層是 tasks 粗體 DoD 以「；」分開之子句。第二層是 task 內文編號步驟（①②…）之期望與斷言；粗體 DoD 只寫「逐項實得入 report」「期望全成立」者，展開至所指之每一步。第三層是單元定義與主線演練腳本另加之驗證命令，含收尾必跑、完工前自驗、fix 自驗句、審查面與其變異清單。一斷言一列，再逐列填判定點；不先分類再挑。
- 計數斷言分清行計與出現次數：`grep -c` 計的是行。全稱斷言（「皆」「全」「恰」「hunk 皆落某節」）另核量化對象非空，因為空集合會讓全稱句恆真。
- 單元定義寫「收尾必跑」前，逐條以該單元會改之檔集對照工具之讀面；讀不到改動檔之工具不列。
