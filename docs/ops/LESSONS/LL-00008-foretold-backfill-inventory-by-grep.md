LL-00008｜碼內具名預告的回填條靠審查員清單補、未自行機器枚舉——第二輪補四條、第三輪又抓一組

**徵狀**：002 刀 U1 碼內以「屆時／回填點／隨 002 刀 Un」形寫了多處具名預告。第二輪確認 run（wf_e7a8937d-539）規格審查指名四處缺 tasks 回填條，主線照清單補了 T021／T023／T024／T029；第三輪（wf_8bb6b498-929）又抓到 `rust-api/server/src/router.rs` ROUTES doc 與 `tools/docsync/tests/test_references.py` 同一義務（U3／U4 掛路由時真 repo 釘值須增列）在 T029／T033 零字對應、且該測所在檔不在 U3／U4 允許檔面（RL-0022）。碼品質輪因此第三次未跑到。第四輪（wf_396288a5-a84）碼品質審查以寬種子再抓七處（`error.rs:43`「隨 U3～U5 落」、`contract.rs:7／17／96／370`、`entity_access_lint.rs:5／7`）——其中 `observed_msgs`「發出點隨各單元進場逐條追加」是功能缺口（U5 移除 `#[ignore]` 前無人擴充即必紅）、非文字衛生。

**成因**：主線把「審查員找到的」當作預告全集，第二輪補條時沒有對本單元變更集跑 `grep -rn "屆時\|回填\|清單外\|隨 002 刀 U[0-9]\|尚無\|佔位"` 逐處對賬 tasks 條——RL-0015 條文只講「預告必附回填條」，清點法沒寫；且連動釘值測所在檔依 RL-0022 應**預先**納入後續單元允許檔面（research R12 表與 script ALLOWED 同步），第二輪也漏了這一腿。第三輪後主線改用的種子 `屆時|回填|清單外|隨 002 刀 U[0-9]|尚無|佔位` 仍是「列舉具體字面形」——「隨 U3～U5」（無世代刀號）、「待…落齊」「隨各單元進場」皆不命中；每多一種措辭就再犯一次。

**處置**：以上述種子 grep 枚舉 U1 變更集全部預告面，逐處對到 T021／T023／T027／T029／T033／T036／T038／T044 補條；research R12 表 U3 列與 U3／U4 單元定義 ALLOWED 納 `tools/docsync/tests/test_references.py`（限定＝只准增列釘值）與 `tests/common/mod.rs`（只准措辭改現在式）；router.rs／test_references.py 兩處「屆時走清單外→升級」措辭改指 T029／T033；第四輪七處補 T023／T024／T029／T033／T036 回填條、U2～U5 定義 ALLOWED 同步（`error.rs` 以限定式納 U5）。

**晉升面**：none——RL-0015 已含回填條義務、RL-0022 已含連動釘值測納清單；本坑＝清點法，記本檔守法即可。

**再犯面與守法**：單元收尾①復核時，對本單元變更集做**兩段式**清點——①寬種子取全集：`屆時|日後|將由|將於|未來|待 ?[UT][0-9]|待.{0,12}落齊|暫|尚未|尚無|預留|佔位|回填|清單外|隨.{0,20}(進場|落地|落|立|補|追加|填充|擴|生效|消費|定形)`；②逐行三分流＝未來刀形（本刀無義務）／已對到 tasks 條（寫出 T 號）／零命中（當場補條）——★「已對到」判準＝該 tasks 條**明寫改該句為現在式**、且承載單元的 script ALLOWED（含限定式）與 research R12 列真的准動該檔；描述性提及（如「obs.rs pre-register 已列」）不算（第五輪 wf_eeb9664a-bc1 再抓 obs.rs／lib.rs 兩處＝此判準缺口）——三分流表寫進收尾 commit 訊息，只靠列舉字面形的種子表必再犯；凡預告指名「某測所在檔不在 Un 允許檔面」＝當場把該檔以限定式納入 Un 的 research R12 列與 script ALLOWED，不留給屆時升級；凡預告句以他單元之名寫、而能力提前於另一單元落地（如 `send_with_headers` 於 U2 先有消費者），落地單元的 ALLOWED 須有通用條款准其改該句——限定式項不得擋 RL-0015 義務。審查員以同一種子掃。
