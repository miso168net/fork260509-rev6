LL-00078｜源碼次序釘之射程外段把某形歸給他案承載卻未以變異實證，加上區段取到生產區尾、處數只數被包件內的字面——LL-00076 守法句已烤入單元定義，碼品質審查仍三輪逐形打穿（007 刀 U13）

**徵狀**：007 刀 U13（T067／T068）把 unlockLogin 帳號維交易化並套包含規則。碼品質審查跑了 4 輪：fix 3 輪跑滿上限，確認輪零 blocker；共 9 支 agent，牆鐘約 5.1 小時。5 個 blocker 中有 3 個屬同一族，都出在源碼次序釘 `handler_source_order_resolve_operator_audit_then_marker` 的 doc 上：doc 把某形歸給他案承載，或宣稱某形判得出，變異實打卻全綠。
- ①射程外段寫「判定件內帳號鎖之 key 取何值＝行為案釘」，但行為案只覆蓋命中腿；查無腿改以操作者 uid 取鎖，變異存活。
- ②來源維案 doc 寫「經判定件即撞『包含規則判定恰一處』」，但恰一處只數被包件內的 `guard_no_escalation(` 字面；來源維臂經包裝件 `judge_account_unlock` 判定時，該字面仍只有一處。
- ③doc 寫「只剩本案會紅」，但 handler 區段取到生產區尾；把寫標記移進宣告在 handler 之後的輔助件、錯誤延到 commit 後才回，次序照過。

另兩個 blocker 不屬此族：拒腿與故障腿的顯式 rollback 沒有機器守（他寫端皆有 `(rollback, bail)` 判準）；解鎖標記 TTL 下界用固定餘裕（另記 LL-00079）。

**成因**：
1. LL-00076 的守法句（關鍵字「宣稱須有案實證」）已烤入本單元定義，implementer 也自跑了 9 支判準變異；但變異只配給 doc 正面列舉的形。射程外段每條「某形由 X 承載」的歸屬句沒有配變異，而歸屬句本身也是宣稱。
2. 源碼次序釘有兩個結構弱點，都是寫釘當下就能列出的反例形，卻是由審查逐輪打出：
   - 區段以「起點錨至生產區尾」取：步驟改由 handler 之外的他件承載時，錨照樣找得到。
   - 處數斷言數被包件內部的字面、不數包裝件的呼叫字面：改經包裝件轉呼就漏數。

**處置**：fix-1～fix-3 一律擴實作：
- 判定件四錨：查得閘逐字形＋綁定逐字形。
- 帳號維臂收場判準：commit 恰一處；失敗腿逐支 rollback，緊接 return Err；零 `?` 早退。
- 包裝件呼叫處數：扣掉宣告錨後恰一處。
- handler 本體截到首個行首 `}`。

合成反例逐形核判否訊息。射程外段改為逐形列舉：巢狀 fn item 形、別名或函式指標轉呼形，歸審查兜底。確認輪實跑 16 支變異，零存活。

**晉升面**：none。判準已在 RL-0080，本則補的是 LL-00076 守法的漏口，併入 007 刀收刀前對 LL-00036／LL-00076 的升 RULES 提請。

**再犯面與守法**：寫源碼次序釘（及同類源碼掃描案）時：
- (a) doc 射程外段的每條承載歸屬（「…＝某案釘」「…撞某判準」）也是宣稱，與正面列舉一樣配一支變異實證。
- (b) 區段截到函式體：起點錨至其後首個行首 `}`，不取到檔尾或生產區尾。
- (c) 處數斷言同時數被包件與其包裝件的呼叫字面。
- (d) 交易臂另釘收場形：失敗腿顯式 rollback 緊接回錯，commit 恰一處。

主線自 007 刀 U12b 起把 (a)～(d) 烤入單元定義的守法句，組裝時依 LL-00072 守法 grep 核關鍵字「承載歸屬亦須變異」在場。
