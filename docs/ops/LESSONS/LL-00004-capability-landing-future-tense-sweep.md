LL-00004｜能力落地的單元只掃了字面詞、沒掃「隨…刀進場／尚無…」形——現在式面留下五處假述，多花一輪審查與升級

**徵狀**：002 刀 U0 把三支碼面閘（rust-fmt／wire-schema／fork-delta）真的落進 `tools/` 與 pre-commit 後，碼品質審查員以 `python3 tools/docsync errata 隨子庫刀進場`／`errata "隨 wire 刀"` 掃出現在式面五處仍寫「fork-delta-lint 隨子庫刀進場」「碼面閘隨 wire 刀」「rev6 尚無該工具」（arc42 08 §8.4、arc42 10 守門欄、arc42 05 §5.1 `tools/` 內含欄、CLAUDE.md §1、`tools/entity-drift-gate.py` 註解）。五處全在該單元允許檔清單外，fix agent 依防呆⑥零改動升級主線——碼面工作早已全綠，卻多耗一輪審查、一支 fix、一次 unresolved 回主線。

**成因**：主線組 U0 prompt 時，RL-0011「集合改變＝全 repo 同語意逐處改齊」的掃描種子只列了 tasks T010 點名的兩個字面詞（`schema-frozen`、`快照缺席`），沒有把「這個單元讓什麼東西從『尚未進場』變成『已在』」當成一個集合改變來想。能力落地改變的是**存在性**，而文件對存在性的陳述長相不是工具名，是「隨 X 刀進場」「尚無 Y」這類未來式短語——用工具名去 `errata` 掃不到它們（`errata` 為字面子字串比對，「wire 地基刀」也掃不到「隨 wire 刀」）。RL-0015 當時的同義集只列「屆時／日後／將由」，這一形不在其中。

**處置**：主線於 U0 收尾同批改對五處（現在式、指名檔路徑與名冊去處）、契約 §1.3 rc 行改 as-built、tasks T043／T044 勘誤詞表補 `隨子庫刀進場`／`隨 wire 刀`／`尚無該工具`、RL-0015 同義集補「隨…刀進場／尚無…」並加一句「落地某能力的單元必以其名掃『隨…進場』形改現在式」；`base-web/x_fork.branch-origin.md` 同句留 U3 base-web 動刀時同批改（零子庫改動硬邊界）。

**晉升面**：rules——RL-0015 條文擴充（同義集＋能力落地掃描義務）；RL-0011 條文不動（它已要求逐處改齊、缺的是掃描種子）。

**再犯面與守法**：凡一個單元讓某工具／閘／模組／端點從「未來」變「現在」，主線組 prompt 時的 RL-0011 種子 MUST 含三形：①該物之名（`errata <名>`）②「隨…進場」「尚無…」「隨 <某刀>」等未來式短語（RL-0015 同義集）③相關活書家族的成員枚舉表（如 arc42 05 §5.1 各目錄內含欄、README 樹）——三形各掃一次、逐處分類「改／史料不動／accepted 不動」。審查員也照同一組掃；掃到才升級，而不是等審查來抓。
★第四形（LL-00006 再犯後補）：④舊**數量詞**字面（「三 crate」「三支」「14 項」等，中文與阿拉伯數字兩寫法）——元素數改變時必掃。
