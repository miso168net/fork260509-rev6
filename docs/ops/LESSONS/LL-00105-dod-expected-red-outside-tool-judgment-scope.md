LL-00105｜tasks DoD 預期「憲法 (ix) 列用途號改名→fork-delta-lint rc 1」，而新增型圈界標記之用途名依設計不入授權判定：變異結構上恆綠，到主線執行時才發現（008 刀 U14）

**徵狀**：008 刀 T132② 要主線把憲法 §III.2 (ix) 列首欄之用途號暫改為名冊外之 `(xi)`，預期 `python3 tools/fork-delta-lint.py` rc 1，並指名本單元五塊 (ix) 標記為授權外。U14 base-web commit 後實跑：rc 0、零指名；寫回後 cmp 相等、憲法零殘留。

**成因**：
1. fork-delta-lint 之三元組授權判定（軌道×用途×檔）只及修改型標記（同行含 `原行:`）；新增型圈界之軌道與用途名不判——憲法 §III.2 表外宣告 3 如此規定，工具之圈界配對檢查 docstring 也明列為射程外。U14 五塊全為新增型、零 `原行:`，用途號改名沒有任何判定點可觸發。
2. tasks 起草時寫下了預期結果，卻沒有指出工具內哪個判定會轉紅，也沒讀工具自述之射程外句。LL-00082（diff 預設上下文帶出未改行）與 LL-00085（字面計數含說明性出現）同根：DoD 字面沒有對照受測工具之實際行為。兩次之守法只住 LESSONS 與單元定義審讀，本次未擋住。

**處置**：主線於 tasks T132② 加裁定註，記實得 rc 0 與理由；(ix) 列被名冊載入之證據歸 T003／T179，收單訊息記實得。user 2026-10-27 裁定擴寫 RL-0008：派發前另核每條 DoD 之判定點與射程。

**晉升面**：rules（RL-0008 擴寫；主線派發前 checklist）。

**再犯面與守法**：
- 每單元派發前，對 DoD 中預期轉紅之變異、計數與零命中逐條寫出受測工具之判定函式或腿。屬工具自述射程外者，先改 tasks 字面：改為記實得與理由，或換一個有判定點之變異。
- 字面 grep 類另核三形：掃描面看不到未追蹤檔（LL-00101）、說明性出現被一併計入（LL-00085）、diff 預設上下文帶出未改行（LL-00082）。
