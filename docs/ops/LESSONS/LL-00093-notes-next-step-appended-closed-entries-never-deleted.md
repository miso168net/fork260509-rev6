LL-00093｜NOTES「下一步」多數只加不刪：歷次收刀與維護批收單多半只追加一句「＝已收單／已收刀」、不刪舊條，該節 14 條中 11 條是已完成之刀／批／輪，每個 session 啟動照樣注入（maint-backlog-142-146；2026-10-16 user 揭出）

**徵狀**：`docs/ops/NOTES.md` 之「## 下一步」節共 14 條，其中 11 條是已完成之刀、維護批與規格對照輪的收單述（001～007 刀總述、規格對照五輪、005 前至 007 前各維護批、006 與 007 已收刀），每條都指向 MILESTONES 查史（其中兩條另寫「本檔不重述」）；真正的下一步只剩 008 一條，另兩條是常駐接手指引。user 讀 session 注入內容時問：好幾輪已全數收單的段落為什麼沒清。

**成因**：
- 程序字面：CLAUDE.md §2 收刀步驟只寫「②NOTES 改下一步」，輕量軌程序（開分支→編排→merge→misc 收單）沒有 NOTES 這一步；主線收單時把「改下一步」做成「追加一句已收單、改寫下一步那條」，既有的已完成條除一次（`efea202` 刪「005 已收刀」條，見 LL-00064）外都留著。
- 機器面：RL-0048「完成即刪、git 即史」之承載閘 GT-06 只對活書家族掃時態禁詞；NOTES 只受引用形諸腿（連結、行號、deep-link、per-machine 路徑、tmp 具名路徑、spec 契約檔引用）與 GT-10 波標記，沒有時態或收單句腿，收單句不會紅。
- 每條追加時都附「查 MILESTONES」指針，看似合規；但既然史已在 MILESTONES，這正是該條不必留在本檔的理由。

**處置**：刪除 11 條已完成條與末條已兌現的預告句（外層 `47b3ebd`）；CLAUDE.md §2 收刀②與輕量軌收單兩處寫明「NOTES 下一步只剩未來式、已完成之刀／批／輪之條整段刪除、史查 MILESTONES」；GT-06 增 NOTES「## 下一步」收單句腿（已收單、已收刀、已全數收單、皆已收），該節缺席亦紅（maint-backlog-142-146 U2）。

**晉升面**：gate——GT-06 之 NOTES 下一步收單句腿。刀內進度句（「已收」「已定稿」「已完成」）依 user 裁定不入射程，靠 CLAUDE.md §2 收刀步驟字面守。

**再犯面與守法**：收刀簿記與維護批收單顆改 NOTES 時，先刪本刀／本批之條、再寫下一步；不以「查 MILESTONES」句留存已完成條。pre-commit 報 GT-06 NOTES 收單句時，補救＝刪掉已完成的部分：整條已完成即整段刪；命中處若為進行中條目內之已收子句，刪該子句、保留未來式部分——不是改措辭繞過。
