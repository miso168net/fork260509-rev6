LL-00064｜收刀簿記改 NOTES 只把「進行中」改成「已收刀」，漏了前一刀的「已收刀」條：該條仍把已被本刀 supersede 的 ADR 當現行承接點（006 刀收刀簿記 2410cd4、2026-10-04）

**徵狀**：006 刀收刀簿記 `2410cd4` 把 NOTES 的 006 條改成已收刀、下一步指 007，lint 全綠。perf 第四步那顆做 SC-014 簿記後驗（RL-0084）時，第⑤欄「活書與 NOTES 之假述零殘留」複掃 ADR-00045／ADR-00046 的續行改指，發現 NOTES「005 已收刀」條仍寫「已知態集中於 ADR-00045（角色與選單八款）與 ADR-00046（IP 域七款），其翻案觸發器即後續刀之承接點」；兩支在 006 刀已分別被 ADR-00068（十九款）／ADR-00069（八款）supersede。`efea202` 才補改。

**成因**：
- 簿記顆的心智範圍是「本刀那一條」：把本刀從進行中搬到已收刀、改下一步。前一刀的「已收刀」條被當成不會動的史述。
- 但「已收刀」條是現在式面，裡面的已知態指針（現行 ADR、款數）會被本刀的 supersede 打成假述。本刀 errata 的現在式複掃若只盯活書，就掃不到 NOTES 裡這種指針。
- 閘不擋：被 supersede 的 ADR 檔仍存在，指針不會斷鏈；只有語意失準。

**處置**：`efea202` 把該句改為「已知態現行集＝ADR-00068（角色與選單十九款；續行並 supersede ADR-00045）與 ADR-00069（IP 域八款；續行並 supersede ADR-00046）」；同顆把 SC-014 逐欄後驗結果寫進 commit 訊息。

**晉升面**：none——RL-0084 的後驗已能抓到；本檔記的是簿記當下就該做的那一步。

**再犯面與守法**：
- ①收刀簿記改 NOTES 時，除本刀條外，逐條檢查其餘「已收刀」條裡的現行 ADR、款數、承接點指針；本刀 supersede 過的 ADR 號一律以 `python3 tools/docsync errata <ADR 號>` 枚舉，NOTES 命中者同顆改指。
- ②本刀若翻案或續行了某支 ADR，把它的舊號也列進 errata 現在式複掃的種子（RL-0011）。
