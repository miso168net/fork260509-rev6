LL-00099｜AskUserQuestion 參數之中文偶發錯成鄰近碼位：送出後解碼核對抓得到，但 user 作答時已看到錯字；「刻意直寫」之文字守法亦未擋住（同根第四起；008 刀 U0；2026-10-23）

**徵狀**：
- 007 刀 2026-10-06 一天六起（頂→頭、搆→損、靜→靈、顯→顧、刻→刪、∪→∩），另有簡體字混入。
- 008 刀 plan 期 2026-10-21 一起（銜→銓）；2026-10-22 U0 開工題「銜接」送成「銃接」。
- 2026-10-23 U0 T003 銜接 diff 題四處「銜」（U+929C）送成「銃」（U+9283）：標頭、題面、選項一說明、預覽之 Amendment log 列各一。
- 每次都是送出後自 session transcript 解碼、對擬稿逐欄比對才抓到，於下一題題首揭露並記帳；user 作答時看到的是錯字版。

**成因**：擬稿檔逐字正確，錯在送出那一次重新生成工具參數——字元偶發錯成碼位相鄰之字（參數多以 `\u` 逸出送出，逸出碼錯一格即換字）。「刻意直寫、不要逸出」改變不了生成面：2026-10-06 晚兩題明知要直寫仍以逸出送出。送出後核對只能事後揭露，擋不住 user 看到。

**防法**：
- 送出前機器比對：`.claude/hooks/pre-auq-draft-gate.py`（PreToolUse，matcher AskUserQuestion）。
  - 擬稿：取 repo 根下工作區內、相對路徑含 `auq` 之 *.json 中 mtime 最新者。
  - 比對：題數、header、question、multiSelect、選項數，與各選項 label／description／preview。
  - 不符：exit 2，列欄位、首差字元碼位與上下文；無擬稿亦擋。
- 主線每題先把題目陣列寫成擬稿 JSON 再送；被擋即依擬稿改正參數重送。
- 擬稿本身之錯字（含簡體字）不在本閘射程：擬稿仍須自核，宜由腳本自原文抽字面生成。
- 落地驗證：以本 session transcript 重放。2026-10-23 銜接 diff 題被擋，四欄全列（皆 U+929C→U+9283）；同 session 其餘四題之實際送出參數全數放行（零誤擋）。
