LL-00089｜計畫把豁免面最後一個真實例改掉、只交代「語料面不動」：讀真檔斷言「豁免確有實例」的測試隨之轉紅，generate 解不掉（007 刀 U21）

**徵狀**：
- 007 刀 U21（T093）：活書 06 frontmatter `rev5_blueprint` 之「使用者域斷權與密碼三入口（007 落地）」值，依 research R22 自「隨刀：憲法 §I.7 島 I 進場刀（使用者域）」改為「承襲（…）」。這是活書家族最後一個 `隨刀：` 值。
- 改完後 `python3 -B tools/docsync test` 之 `test_real_book_face_zero_hits_and_exemption_has_real_instance` 轉紅（`AssertionError: False is not true : {}`）：該案後半讀真 repo 的 06 節檔，斷言 ADR-00006 決定 1 值形豁免確有「隨…進場」被免（RL-0067 之真實例前提）。兩支 implementer 與規格對照、碼品質兩鏡各自升級同一項。R22 只寫「`test_book_refs.py` 語料面不動」，指的是同檔合成語料兩行。

**成因**：
1. 該案之真實例斷言寫死單一檔（06）、沒有零實例出口：豁免面只剩一個實例時，任何把它改掉的計畫都會讓它轉紅。
2. 計畫盤點「誰引用這個字面」時只掃得到含該字面的行（合成語料），讀真檔、斷言實例存在的測試不含該字面，grep 找不到。上游原因同 LL-00087／LL-00088：計畫寫下的驗法沒先對改後的真檔實跑一次。

**處置**：U21 收尾由主線改寫該案後半：受守面擴為活書家族全檔 frontmatter 之 `隨刀：` 值；零實例時不斷言（紅證 vacuous，豁免機制由同類合成語料之正反案守），任一活書再出現 `隨刀：` 值即自動恢復「其中確有『隨…進場』被免」之斷言。修前紅（`{}`）→修後綠；變異自證：06 放回改前值＝綠、改放不含「進場」之 `隨刀：` 值＝紅（指名該檔該行）、還原後逐位元相等＝綠。

**晉升面**：none。零實例之判準本體在 RL-0067；本條是計畫盤點面的寫法。

**再犯面與守法**：
- 計畫要改掉或刪除某字面時，除了 grep 該字面，另把改動先套在副本上跑一次 `python3 -B tools/docsync test`（與該字面所屬子庫之全量測試），看有無讀真檔之案隨之轉紅。
- 寫「真實例」斷言時一併寫零實例出口（具名、帶自動恢復條件），不寫死單一檔之單一實例。
