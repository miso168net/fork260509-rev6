LL-00037｜先紅階段在交易體內放會 panic 的佔位（`todo!()`）——panic 留下持列鎖的「交易中閒置」連線，其後守衛 Drop 等那把鎖、整輪測試永久卡住（非終止型故障；005 刀 U7）

**徵狀**：005 刀 U7 implementer-3 先紅時，刪除家族的 facade 佔位寫成 `todo!()`；該佔位跑在已開交易、已鎖標的列之後。案一 panic，測試行程不退、零輸出、無完成訊號。容器內查得一條連線停在 idle in transaction 並持有 `sys_role` 列鎖；等待者是同一測試行程裡守衛 Drop 的還原 DELETE。

**成因**：panic 展開時未提交的交易物件被丟棄，rollback 只排入佇列、待該連線下次被取用才送出（sqlx 的 Drop 語意）；在此之前連線停在交易中、列鎖不放。而 U3 起每支寫庫案都掛帶界守衛、Drop 時要對同表做還原寫入——兩者同在一個行程、一把鎖，Drop 永遠等不到。`--test-threads=1` 下其後所有案一併停擺，且不屬「失敗」，不會有紅訊息可看。

**處置**：當場於容器內結束測試行程、實查庫面零殘列（seed 列、授權表 id 界、歸檔表、序列值皆回基準）後，把佔位改成回 `Err`（或 handler 回 `AppError::Internal`）再跑——得到 8 支真斷言紅，先紅照常成立。

**晉升面**：none——RL-0066（先紅後綠）已要求「跑到真的紅」；本坑＝佔位寫法，守法句寫進本檔與後續單元定義。

**再犯面與守法**：先紅階段凡會落在交易體內（`begin` 之後、`commit` 之前）的佔位，一律回錯誤值、不 `todo!()`／`unimplemented!()`／`panic!`；交易外的純函式佔位不受此限。跑先紅若出現零輸出長時間不動，先查 `pg_stat_activity` 之 idle in transaction 連線再動其他東西。
