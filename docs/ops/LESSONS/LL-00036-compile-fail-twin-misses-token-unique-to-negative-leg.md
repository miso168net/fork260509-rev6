LL-00036｜compile_fail 反段的「正面孿生」沒涵蓋反段獨有的 token——該 token 失效時反段因錯的理由照綠，doc「孿生會紅」之宣稱不成立（005 刀 U3、U4 連兩單元、回溯命中 004 域既有碼）

**徵狀**：005 刀 U4 碼品質審查四輪，每輪 blocker 都是同一族——doc 寫「某案釘住／某變異即紅／正面孿生會紅」，審查以判準變異實打仍全綠：`sys_casbin_archive` 具型交易守的五段 `compile_fail` 以 `&sea_orm::DatabaseConnection` 呼叫寫入入口，而正面孿生只以 `&DatabaseTransaction` 呼叫、連線型零出現；等待者觀測式的誘餌缺「同低半異高半」一形，「只比低半」變異存活。回溯同形命中 `sys_ip_rule` 模組 doc（U2 已審過）與 `request_context` 的「欄改名」半句；U3 亦兩度以「機器守射程超出實作」列 blocker（演練號段掃描、帶界守衛巢狀語意）。

**成因**：`compile_fail` 只斷言「編不過」、不管為何編不過；rustdoc 的錯誤碼比對（`compile_fail,E0xxx`）在釘版 stable 不生效。正面孿生的作用是讓「路徑／型名解析不到」這類錯的理由在同一次 `cargo test` 裡轉紅——但它只守得住**孿生裡也出現的** token；反段獨有的 token（此處＝連線型）失效時，反段照綠、孿生不受影響。誘餌型負向案同理：誘餌集只證得到「放進去的那幾形寫壞」。寫 doc 的人把「有孿生／有誘餌」讀成「全射程有守」。

**處置**：005 刀 U4 收尾主線把連線型帶進兩處正面孿生（`sys_casbin_archive` 由 fix 輪、`sys_ip_rule` 由主線以收泛型連線之讀端入孿生），`request_context` 的「欄改名」改指檔內四欄窮舉解構錨；誘餌補第三形；三處 doc 並寫明射程外（單一反段內的手誤）。變異自證：連線型全數拼錯→孿生紅、只比低半→誘餌案紅。

**晉升面**：none——RL-0051（一正一反自證、變異打在判準上）已涵蓋；本坑＝寫法。

**再犯面與守法**：寫 `compile_fail` 反段時，逐 token 核「反段用到的每個路徑、型名、fn 名都出現在正面孿生裡」；寫誘餌型負向案時，先列判準式所有「漏比一半／漏一條件」的寫壞形、每形配一誘餌，doc 只宣稱有誘餌的形、其餘明寫機器守不及。單元定義 CONTEXT 烤入「doc 宣稱須有案實證」一句（U4 起已烤）。
