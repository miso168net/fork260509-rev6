LL-00114｜設定頁數字框於送出被拒之回讀後以 key 重掛：仍有焦點之舊實例被移除時瀏覽器發失焦，naive-ui 失焦收尾以框內殘留之被拒值再發一次——自動重送一發，CDP 首跑因此真改出一列設定（008 刀 U18）

**徵狀**：T165 ④-h（Enter 送出被拒）實得 2 發 POST、2 發回讀（期望恰一發回讀）。CDP 首跑只把首發改寫成必拒值，第二發照原值送出，`password_min_length` 由 8 改成 9（同步驟改回）；暫時性拒絕時即會真寫入使用者輸入之被拒值。④-i（清空＋Enter）同機制多一發只回讀之 GET。

**成因**：U14 為使被拒或清空後框內回退，於回讀落定後遞增重掛序號、以新 key 重掛數字框。Edge 154 移除仍有焦點之 input 時對其發 blur／focusout；naive-ui 2.44.1 `InputNumber` 之失焦收尾以框內字串推導值、與受控值不等即呼叫 `onUpdateValue`，而舊實例之 props 仍掛著上一輪渲染之處理器。

**處置**：主線改發值處理器為渲染當下取得（`numberUpdateHandlerOf`：閉包記下該鍵重掛序號，序號過期之發值不處理）；CDP 重驗 ④-h 1 發 POST／1 發回讀、④-i 0／1、成功路徑 1／1。

**晉升面**：none。

**再犯面與守法**：
- 以 key 重掛受控輸入元件前，先想舊實例卸載時會不會再發事件（失焦、change）；處理器以渲染當下之世代號擋過期實例之發值，不靠時序（失焦可能在重掛之同步段或稍後才到）。
- CDP 驗「恰 N 發」類判準時，攔截規則把同端點之每一發都改寫成必拒值，避免意外之重送真寫入。
