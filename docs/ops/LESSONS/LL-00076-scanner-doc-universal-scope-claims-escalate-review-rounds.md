LL-00076｜源碼掃描案之 doc 以全稱句宣稱射程（「…皆因此報」）而實作判不出——審查七輪逐輪以規避形打穿，fix 每輪擴實作也擴宣稱；LL-00036 之守法句「doc 宣稱須有案實證」未烤入 007 刀單元定義（007 刀 U12a）

**徵狀**：007 刀 U12a（T111）只把 14 處抽取臂之 debug 事件改為兩欄形，handler 十一檔生產區淨增 106 行（含 doc 與兩支標籤件）；審查卻跑了規格對照 3 輪、碼品質 4 輪（fix 5 輪、確認輪零 blocker；13 支 agent、牆鐘約 7.2 小時）。9 個 blocker 有 8 個屬同一族：源碼掃描案 `production_code_never_puts_extractor_rejection_text_into_events` 之 doc 宣稱判得出、變異實打仍綠的形——取參照形 `%&`、臂內交他函式再換名入事件、關鍵字緊鄰綁定名、`RequestExt::extract` 等他種入口、全路徑型名、冒名標籤件、標籤件內以改名參數發 TRACE、match 前以組合子取用抽取 Result。掃描件連同自證案隨之長到 869 行。

**成因**：①掃描件 doc 寫的是全稱句（「交他函式、別名、原事件內添欄、臂內追加事件皆因此報」「標籤件本身由值域案承載」），射程寬於實作；審查依 RL-0080 以 doc 宣稱為判準植變異，每個判不出之形都成 blocker。②fix 對宣稱與實作之落差一律擴實作，新腿的 doc 又寫成全稱句，下一輪就有新宣稱可打——宣稱自我加碼，直到 fix 上限後的確認輪才收斂。③LL-00036 已記此族（doc「某變異即紅」實打仍綠，005 刀 U4 四輪），守法為單元定義 CONTEXT 烤入「doc 宣稱須有案實證」；005 刀 U12／U13、006 刀 U14 的單元定義都有這句，007 刀的單元定義範本沒帶（U1～U12a 全數零命中）。LL-00072 所定「組裝每支單元定義時以 grep 核守法在場」也沒對 LL-00036 執行。同次盤點另見 LL-00053（判準變異不得拆除真庫清理守衛）之守法句同樣未烤入 007 刀單元定義。

**處置**：本單元碼品質 fix-1～fix-3 逐形補腿（受審式形釘、他種取得途徑處數釘 0、型名詞元處數釘、標籤件定義全文腿），doc 增「射程外與其承載」段逐形列明；確認輪對已列射程外之登出具名綁定形，其變異存活判非 blocker。主線自 007 刀 U12 起在單元定義 CONTEXT 烤入 LL-00036 與 LL-00053 之守法句，並補一條 fix 準則：宣稱與實作不符時，無心回歸常見寫法擴實作，刻意規避形收窄宣稱並列入射程外。

**晉升面**：none——判準已在 RL-0080，本坑是寫法加上組裝漏烤。守法靠主線手動烤入而漏烤，與 LL-00072 同型；該條已列 007 刀收刀前提請 user 裁定是否升 RULES，本則併入同一提請。

**再犯面與守法**：寫機器守（源碼掃描案、負向案、`compile_fail`、誘餌案）的 doc 時，射程只寫逐形列舉、且每形有變異實證，不寫「…等皆」全稱句；判不出之形列「射程外」段並標承載（他腿、行為案或審查兜底）。主線組裝每支單元定義時，依 LL-00072 守法對全部「寫進單元定義」類 LESSONS 以 grep 核關鍵字在場（本則關鍵字＝「宣稱須有案實證」；LL-00053＝「守衛照掛」）。
