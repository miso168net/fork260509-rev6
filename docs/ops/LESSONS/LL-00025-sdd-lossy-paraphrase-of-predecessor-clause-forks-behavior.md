LL-00025｜SDD 轉述前代條文時壓掉限定語，實作照轉述施工，行為與既有拍板分岔而全鏈綠

**徵狀**：004 刀 U5 規格審查指出憲法島 F 之 F7 的理由句「來源維鍵為攻擊者自身位址」在現碼不成立——轉發鏈逾上界時 `real_ip` 被改成傳輸層對端（經反向代理時＝代理位址），被拒列全數記進代理那一桶、攻擊者自己的桶零計數，五十條超長鏈即可把回退腿的登入鎖在來源維。U1 的測試、U5 的測試、兩輪審查與全量測試此前全綠：測試的期望值與實作出自同一句錯的規格。

**成因**：前代條文是「`real_ip` 在該態下恆有值——**出處視判定腿而定**：層②③取自判定窗，直連腿／回退腿／通道覆蓋取對端或訪客標頭」，前代函式簽名只收只回信心、型別上就碰不到位址。rev6 的 data-model 轉述時把冒號後整段壓成括號「取自傳輸層對端」（只對其中三條腿為真），research R4、tasks、quickstart、contracts 逐檔沿抄；implementer 依 tasks 施工並在檔頭把它記成「與藍本的差異一處拍板」——一句沒有任何拍板紀錄的轉述，經三次轉手變成了「拍板」。brainstorm 的結論其實是「沿用前代終態」，分岔從未被任何人決定過。

**處置**：主線對讀前代 ADR 與函式 doc 查證後，未推送之 ADR-00037 重落、SDD 六處字面勘誤＋research R3 加勘誤註記、碼面交修單單元 U5e。防法三條：①SDD 引前代條文，凡帶「視…而定／除…外／僅當」的限定語一律逐字帶過來或指名出處，不以括號摘要取代；②research R3「拍板差異點清單」是 rev6 與前代行為差異的**唯一**入口——實作或碼註出現「與藍本不同」而該表查無對應列，即當缺陷升級、不當拍板沿用；③審查發現「權威面理由句在現碼不成立」時，先問「碼錯還是理由錯」並回前代查證，再談修憲或新 ADR。
