LL-00115｜單元收單 commit 訊息漏記 spec 指定之逐單元必記項（收刀計數三則）：五顆漏記經後顆補記後，同刀後段兩顆再漏——到收刀彙記前之派發前清冊才揭出（008 刀 U19）

**徵狀**：
1. 008 刀 spec FR-067 與 tasks 要求每一單元收單 commit 訊息記收刀計數三則（ADR-00011 翻案觸發器①、ADR-00084「zh-cn.ts 新字未分類之紅」、ADR-00052「一致性腿誤擋正常部分 commit」之本單元次數，含 0）。U2～U6 五顆收單訊息皆缺；U7 收單時發現，於 `188c07a` 以「★補記 U2～U6」句補記。
2. U16（`03e2e05`）、U17（`c4e9f0d`）兩顆收單訊息再缺。U19 派發前驗收斷言全集清冊逐顆核訊息字面時揭出，改由 U19 收攏顆訊息補記。
3. 彙總仍可閉合：各顆次數另有取證路（訊息 lint 段之 GT-12 警告、locale diff 是否為空、主線對話紀錄有無擋下事件）。代價是取證全落在收刀前，補記又只能寫進後顆訊息，讀史者須跨顆拼湊。

**成因**：單元收尾六步序之 commit 訊息由主線逐單元手擬。必記項散在 spec FR、tasks 節首與★裁定註，收單時沒有逐項核對的固定骨架。U7 補記只補了舊顆，沒有把該項加進後續單元的擬稿核對點，同根再犯。

**處置**：U7 補記 U2～U6（GT-12 各 1、zh-cn 新字紅各 0〔`9fe562d..88682f3e` 之 locale diff 為空〕、一致性腿誤擋各 0）。U19 收攏顆補記 U16／U17，同口徑：GT-12 各 1、zh-cn 新字紅各 0（U17 所帶新字已屬 `APPROVED_CHARS`）、誤擋各 0。T181 之彙總口徑＝全區間訊息 ∪ 兩處補記。

**晉升面**：none。判準屬單刀 spec 之必記項；跨刀常設化須另議。

**再犯面與守法**：
- 單元收單訊息擬稿前，先抽出 spec 與 tasks 中指定寫入「本顆 commit 訊息」「收單訊息」之字面全集，逐項核本顆訊息已載。
- 發現漏記而補舊顆時，同時把該項加進同刀後續單元的擬稿核對點，不只補舊顆。
- 收刀彙記類 task 的派發前清冊逐顆核訊息字面，不以「各單元已記」之假設代證。
