LL-00011｜限定式允許清單按「節」列舉、同檔同事實的他節被鎖成清單外——agent 掃到也只能升級、主線收尾才改對

**徵狀**：002 刀 U8（run wf_5c891f3f-ac5）impl-1 依 T043 把 08 §8.4 改成「fork-delta as-built＝兩支新增型新檔」，同一事實在 05 §5.1 base-web 列與 §5.2 base-web 條仍寫「fork-delta 零／目前為零」；兩處落在允許清單第 1 項「只准 frontmatter §5 列／§5.1 rust-api 列／tools 列／§5.2 rust-api 段、其餘零改」之外，agent 依 RL-0022 不擅改、升級主線；規格對照與碼品質兩段各再報一次（同一 file×summary 跨段兩度進 `escalatedBlockers`），主線收尾直改。

**成因**：主線組 U8 允許清單時照 T043 條文逐「節」列舉可改處，沒有先對「本單元要改變的事實」跑 `docsync errata`／grep 枚舉其同檔各家；RL-0011 的枚舉義務是給 agent 的，主線寫清單時自己沒做。LL-00006 抓的是「改對一節、漏掃同檔另一節」；本坑多一層：清單本身把另一節鎖成清單外，agent 即使掃到也只能升級，多花兩段審查輪。屬 LL-00006 再犯（`recurrence_of`）。

**處置**：主線 U8 收尾同批改對 05 兩處（指針形指 §8.4、不在 05 造第三個家）、errata「目前為零」「fork-delta 零」現在式面零殘留。

**晉升面**：none——RL-0014 已寫「答『碰得到什麼』、寧可多列」；本坑是主線寫清單的作法缺口、不新增條文（RULES-VERSION 一改、未發射腳本全重組），守法補在下段。

**再犯面與守法**：凡允許清單項帶「只准 §X／§Y…其餘零改」形，寫清單前對該單元 tasks 點名的每個「要改變的字面」跑 `python3 tools/docsync errata <詞>`，命中落在同檔他節者一律納入只准面；清單寫好後以「事實×家」矩陣自檢一次（每個事實在同檔的家全在只准面內），而非以「tasks 條文列了哪幾節」為準。
