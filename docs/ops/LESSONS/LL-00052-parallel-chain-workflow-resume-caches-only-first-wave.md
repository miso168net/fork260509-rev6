LL-00052｜平行鏈 workflow 以 resumeFromRunId 續跑只省得了首波——快取依呼叫序前綴比對，平行鏈第二波起的呼叫序與原跑不同，其後全數 live 重跑、不重複 agent key 逾看門狗 runaway 底線（006 刀 plan 期；2026-10-01）

**徵狀**：plan 期 P2-A2（五條平行鏈：修訂→首審→fix→確認，再接評審→對帳→確認；單次執行保險絲 23 支）跑到 20 支時撞上 session 用量上限，確認輪五支失敗（transcript 模型欄為 `<synthetic>`＝失敗訊息、不是換了模型；五支皆唯讀、零半寫入）。重置後以同 script、同 args `resumeFromRunId` 續跑，預期已完成 15 支走快取；16 分鐘後看門狗告 RUNAWAY（不重複 agent key 26＞25）。實查只有首波修訂 5 支命中快取，首審、fix、確認與評審段全部 live 重跑；已修過的檔又走一輪審→修→確認（續跑共 107 分鐘、子 agent 4.88M tokens）。

**成因**：resume 快取比對的是 agent() 呼叫序的最長不變前綴。平行鏈的第二波呼叫在原跑依各鏈首波的完成先後發出；續跑時首波五支自快取瞬間回傳、第二波改依鏈序發出——呼叫序自第二波第一支起即與 journal 不同，其後一律 live。單一 serial 鏈不受影響（呼叫序固定）。

**處置**：當次判正當超標（扇出型；script 單次執行未破保險絲），依規 `--rearm` 補回長尾腿、Monitor 腿續盯，跑完照常分流。同日 P2-B（五鏈起草＋審查，16 支）又因 session 上限中斷，改不用 resume：手寫續跑 script，把 journal 已完成之結果烤成常數（writer 產出與自述、首審 findings、fix 處置；入口逐欄斷言形狀），各鏈自其失敗點起跑（兩鏈自首審、三鏈自確認輪；確認輪烤入前輪 findings 與處置＝RL-0071），再接跨檔評審→對帳→確認；保險絲依結構重推為 12、乾跑五案綠後發射，12 支零錯跑完。

**晉升面**：RL-0010 已定「需某階段重跑＝新開只跑該階段的 run、寫清已完成結論」，本坑補其在平行鏈下的必要性——故障續跑亦然；不改條文、形制記於本檔。被外力中止的是寫入型 agent 時另見 LL-00023（半成品留在工作樹）。

**再犯面與守法**：續跑含 `pipeline()`／`parallel()` 平行鏈的 workflow 之前，先依 journal 估「快取只到首波」下的不重複 agent key 總數；逾 runaway 底線或重跑成本不可接受時，改手寫續跑 script（烤入已完成結果、各鏈自失敗點起、確認輪帶前輪紀錄、保險絲依結構重推、乾跑後發射），不走 resume。只有 serial 鏈或首波即中斷者，resume 才省得到。
