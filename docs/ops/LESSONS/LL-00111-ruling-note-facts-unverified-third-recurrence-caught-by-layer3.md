**徵狀**：
1. tasks T167 之★U18 派發前裁定註⑥寫「重設後 query 不含清空欄之鍵」；實際稽核頁搜尋卡之請求經 qs 序列化，清空欄（值 null）照樣送出 `key=`。
2. 同支裁定註③所寫之觀察窗與重新整理鈕判準，與頁面實作不符。
3. 兩則皆由 U18 第三層清冊 run（RL-0008 第三層＝單元定義與主線腳本另加之驗證步驟）於 CDP 派發前抓到並直改 tasks。該 run 之 lens 射程由主線臨時寫入「裁定註新步之可執行性」，RL-0008 字面並未要求。

**成因**：同 LL-00083、LL-00109：裁定註是派發前烤進 prompt 之不可違反項，主線寫入事實前未逐條回碼面或實跑取證。前兩次之守法皆落在撰寫者自律（逐條附碼錨）；撰寫者與核對者同一人＝盲點相同，第三次照樣寫錯。

**處置**：tasks T167 註③⑥依碼面直改（qs 之 null 序列化、觀察窗與重新整理鈕），CDP 生成器同步改判準。user 2026-10-28 裁定機制晉升：擴寫 RL-0008——派發前新增之★裁定註所述事實（碼面行為、命令輸出形、所引 ADR 原句）與新步驟亦入清冊、一事實一列附碼錨或實跑命令，由非撰寫者之清冊 agent 核。

**晉升面**：rules（RL-0008 擴寫；主線派發前 checklist）。

**再犯面與守法**：
- 派發前補寫★裁定註後，其中每一事實與新步驟入派發前清冊（一事實一列），由清冊 agent 讀碼或實跑核；不以撰寫者自核代之。
- 裁定註凡述前端請求形（query 序列化、空值處理）或頁面判準（觀察窗、按鈕），以讀碼得之實作處為錨；推想之形一律標「待實證」。
