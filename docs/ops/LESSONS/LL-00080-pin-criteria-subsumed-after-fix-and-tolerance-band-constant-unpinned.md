LL-00080｜源碼次序釘與上界案之 doc 宣稱仍逾判準射程；fix 新增判準吞掉既有判準之獨占射程（停用該判準零案轉紅）；行為案以容差區間量常數、容差內改值無逐值釘——LL-00078 守法已烤入，碼品質審查仍跑四輪（007 刀 U12b）

**徵狀**：007 刀 U12b（T112）改了三件事：改密節流之判讀與推進移入帳號鎖；`incr_with_window` 改為一發 EVAL 腳本並含壞值自癒；鎖內兩次快取往返各以 1 秒為上界。規格對照 1 輪零 blocker。碼品質 4 輪：fix 3 輪跑滿上限，確認輪零 blocker。共 9 支 agent，牆鐘約 5.8 小時。各輪 blocker：
- 第 1 輪：次序釘 doc 宣稱「外殼零讀桶」「帳號鎖持有期內之快取往返只經兩支有界件」，判準卻只數 `precheck`／`record_failure` 字面處數與內層 `cache` 字樣。外殼直呼快取原語之變異（開交易前讀桶、成功臂 commit 前往返）全綠存活。
- 第 2 輪有兩項：
  - user 裁定之上界 1 秒無逐值釘。行為案之實耗區間為 [1 秒, 1.5 秒)，常數改成 1.4 秒照綠；測試常數 doc 卻全稱宣稱上界常數一被放寬即由實耗上界斷言轉紅。
  - 模組 doc 之公開面清單漏列新 pub 型 `WindowedCount`（RL-0011 枚舉表）。
- 第 3 輪：停用 `BUCKET_STEPS`（判讀件／推進件於外殼、內層、其餘三處之處數）後全綠。原因是第 1 輪 fix 新增的 `CACHE_USES`（快取字樣三處處數）與錨恰一判準，把該判準原有的自證形全數一併判紅，該判準因此零獨占射程。前一輪同類停用變異之所以紅，是因為當時「成功臂經本檔包裝件推進」只有它判得出。

**成因**：
1. LL-00078 之守法 (a)～(d) 已烤入單元定義，組裝時也核過關鍵字在場；implementer 自跑 13 支判準變異。但 doc 的正面宣稱仍以概括語寫成（「零讀桶」）：沒有逐途徑（經判讀件、直呼原語、經本檔包裝件、經他檔件）列舉，也沒有各配變異——LL-00076 的全稱句問題換個面再現。
2. 判準逐輪累加：fix 為新形加判準時，只驗新判準的變異轉紅，沒有重跑「逐判準停用」。新判準的射程一旦涵蓋舊判準的自證形，舊判準就退成冗餘，日後被改壞也不會有案轉紅。
3. 行為案以容差區間量常數效果時，容差內的改值必綠。同檔既有門檻與窗長之逐值釘（語意案以常數本身參數化、對值恆真，故值另釘），新常數沒有比照。

**處置**：
- fix-1：判準擴為 `CACHE_USES`，（外殼, 內層, 其餘）恰為 (3, 2, 1)；記憶體變異 17→20 支。
- fix-2：
  - 增逐值釘 `the_lock_held_cache_bound_is_pinned_at_one_second`。
  - `BOUND` doc 改逐形射程：縮窄＝實耗下界紅；放寬達餘裕＝實耗上界紅；放寬不足餘裕＝逐值釘紅。三形各以變異實證。
  - 模組 doc 補 `WindowedCount`。
- fix-3：補四支只有 `BUCKET_STEPS` 判得出之形（句柄不含快取字樣之桶件呼叫），記憶體變異 20→24 支；並以收集式變異逐判準自證——停用某判準時，恰其獨占形存活。
- 確認輪實跑 25 支變異，零存活。

**晉升面**：rules——user 2026-10-15 裁定本族守法擴寫入 RL-0080（射程宣稱逐途徑配變異、逐判準停用變異、容差常數逐值釘），並把 fix 納入該條範圍。原判（裁定前）：判準已在 RL-0080，與 LL-00036／LL-00076／LL-00078 同族，併入 007 刀收刀前之升 RULES 提請。提請時一併附兩例：LL-00076 守法自 007 刀 U12 起、LL-00078 守法自 U12b 起烤入單元定義，其後 U13 與 U12b 之碼品質審查仍各跑四輪（皆 fix 跑滿上限）——作為「單元定義烤句不足以擋此族」之實證。

**再犯面與守法**：寫源碼次序釘、上界案等機器守時：
- (e) 判準多於一條時，逐判準做停用變異：停用任一判準，至少一支自證形須轉綠（＝該判準有獨占射程）。每加一條判準（含 fix 輪），重跑全部判準之停用變異；被吞者補獨占形，或於 doc 寫明分工並收窄其宣稱。
- (f) 行為案以容差區間量常數效果時，常數另立逐值釘；doc 逐形寫明縮窄、放寬達容差、放寬不足容差各由何者判紅。
- (g) doc 宣稱「零某行為」時，逐途徑列舉，並各標判準或射程外承載。
