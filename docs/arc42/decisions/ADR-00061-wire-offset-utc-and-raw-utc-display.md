## 背景

wire：rust-api 的時間欄以 chrono `to_rfc3339()` 輸出（rev5 同），讀自 timestamptz 之值偏移恆為 `+00:00`（sqlx 解碼）；小數位數隨值為 0／3／6 位（例：多數列 `2026-09-29T13:56:56.123456+00:00`、整秒列 `2026-09-29T13:56:56+00:00`）。各刀契約只寫「RFC3339 帶 offset」、未定偏移值；sys_menu facade 之真 DB 讀端測試以含 `+00:00` 之字面逐字比對，附帶釘住偏移。

顯示：base-web 目前唯一顯示時間欄的是 IP 規則頁，原樣顯示 wire 字串（rev5 同頁同形）。前代慣例之「以瀏覽器時區顯示」款，rev5 未實作、rev6 未承載；rev5 之使用者頁與稽核頁同樣原樣顯示時間。

## 決策驅動因子

- 與 rev5 之 UI 與 wire 同形（CDP 對照驗收），零改動。
- 消費端需要確定的偏移值。

## 考慮過的替代案

1. **依瀏覽器時區顯示（加或不加時區標示）**——多國使用者看當地時間較直覺，但畫面與 rev5 不同；否決（user 2026-09-30 裁定維持 UTC 原樣）。
2. **統一小數位數（前端裁到秒，或後端固定到秒）**——前者破 rev5 畫面同形，後者改 wire 並失去秒以下精度；否決（user 裁定完全照舊）。
3. **契約允許任意偏移**——消費端須處理各種偏移；否決（user 裁定明寫 +00:00）。

## 決定

1. wire 時間欄一律 RFC3339、偏移恆 `+00:00`；小數位數隨值（chrono `to_rfc3339` 行為）＝已知態、不統一。
2. 管理頁時間欄原樣顯示 wire 字串（UTC）、不做時區換算；後續顯示時間之頁面同此。
3. `docs/arc42/08-crosscutting-concepts.md` §8.2 API 慣例載明本款並指向本 ADR。

## 後果

- 正面：與 rev5 的 UI 與 wire 同形、零改動；消費端偏移值確定。
- 負面：各地使用者皆看到 UTC、須自行換算當地時間；小數位數不齊。
