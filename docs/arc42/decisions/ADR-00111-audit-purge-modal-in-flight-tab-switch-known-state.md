## 背景

- 稽核頁之清理浮層為四分頁共用之單例；請求在途時，取消鈕、點遮罩與 Esc 皆可關閉浮層；在途再按確認由在途守衛擋下（同刀 spec 刻意分岔登記表「清理請求在途再按」列）。
- 在 A 分頁送出清理後關閉浮層、改於 B 分頁開清理，A 之請求回來時，成功收尾（關浮層、刷新清單、成功提示）作用在當下之浮層與標的（B）：B 浮層被關、B 清單被刷新、跳出成功提示；A 清單未刷新。
- 資料面正確：只清了 A、清理自記列只記 A。rev5 同形；CDP 三方對照已於 008 刀 U18 凍結。

## 決策驅動因子

- 資料正確性與稽核自記不受影響。
- 與 rev5 UI 一致；修正須改前端行為（與 rev5 分岔）並對稽核頁重跑 CDP（含 dev 庫寫入放行）。

## 考慮過的替代案

1. **本刀內修正並登記刻意分岔**（結果綁回發起之分頁、只在浮層仍為同一次請求時關閉，或在途停用取消）：畫面歸屬正確，但多一輪前端改動、全量閘與 CDP。棄（user 2026-10-28 裁定記已知態）。
2. **記為已知態**（選）。

對所選方案跑同一反例（RL-0013）：「使用者依 B 之成功提示誤判 B 已清理」——B 清單刷新後列數未變，與提示矛盾、可察；重新整理或切回 A 分頁即見 A 已清；稽核自記只記 A，事後可查，成立（誤導只在畫面、不在資料）。

## 決定

1. 不改碼；本競態登記為已知態，索引列入活書 11 技術債表。
2. 日後改動清理浮層之在途收尾時，同批移除本已知態並檢視 rev5 對照。

## 後果

- 特定操作序下，成功提示與清單刷新歸屬到後開之分頁；資料與稽核自記正確。

## 翻案觸發器

- 稽核頁或清理浮層改版（含與 rev5 對照之 CDP 重跑）時重審。
- 使用者回報依提示誤判清理結果時重審。
