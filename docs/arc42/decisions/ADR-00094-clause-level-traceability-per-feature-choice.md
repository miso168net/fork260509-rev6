## 背景

- 007 刀依 user 2026-10-06 裁定，把 spec 的驗收場景、SC、FR、Edge Cases 拆成「可單獨被違反的最小陳述」（子句）：每子句在 tasks.md 掛逐字錨，單元收尾填入測試名或走查紀錄，收刀前逐列核（LL-00071）。
- 成效：`/speckit-analyze` 報需求覆蓋 100％ 之後，逐子句稽核仍揭 253 個部分斷言或零斷言之子句（blocker 1／major 179／minor 73；唯一 blocker 落在 FR）；收刀前 1308 列、測試名不符 0。
- 代價：007 刀 tasks.md 1875 行中追溯段佔 1319 行（005／006 刀之逐條形約 40～50 行）；分支 61 顆 commit 中 46 顆改到 tasks.md；檢核工具 9 檔約 1657 行，只住 gitignored 工作區、路徑寫死 007、零自測，曾漏出 138 個空字串錨而誤判通過；RULES 主線類 51／52、治理閘 12／12、docsync 行數已超預算。
- RULES 無子句層追溯規則；BL-00146 之觸發＝下一支治理維護批或 008 刀 brainstorm 起手前（先到者）。

## 決策驅動因子

- 子句層追溯對寫端多、跨域多之刀實證有效，但成本隨刀量級放大；通則化須先把工具入庫、補自測與變異自證，且吃滿 RULES、閘數與 docsync 預算。
- 只拆驗收場景與 SC 之限定形，以 007 刀實數回推只涵蓋 253 個缺口中的 68 個，會漏掉 FR 與 Edge Cases 之缺口（含唯一 blocker）。
- 不設規則時，下一刀起手若無提醒，可能默默回到逐條形——承載點須落在可觀測的檢查點，不寫無人監看的自由門檻（BL-00142 之觸發器成立 16 日無人察覺即實證）。

## 考慮過的替代案

1. **工具入庫並立 RL 通則化**：落點三擇一皆有代價——`tools/` 頂層碼面閘（第 11 支）、docsync 治理閘腿（閘數已滿、行數已超）、手動工具（無 pre-commit 守）；RULES 主線類 51→52 滿額；008 刀起手延後，此後每刀 tasks.md 依 007 刀比例膨脹。棄。
2. **限定射程後通則化（只拆驗收場景與 SC）**：表量縮為約三成，但漏掉 FR 127 個與 Edge Cases 58 個缺口、含唯一 blocker。棄。

對所選方案跑同一反例（RL-0013）：「008 刀 brainstorm 未想起此題、默默回到逐條形」——決定 3 由 `docs/ops/NOTES.md`「下一步」承接一題，翻案觸發器再綁 008 刀收刀承載體檢一行，起手與收刀兩端各有承載點，成立；「沿用之刀的檢核工具失準（空錨恆命中）」——決定 2 要求沿用之刀自證空錨與錨不符一律計不符，成立。

## 決定

1. 子句層需求追溯不入 RULES、不設碼面閘或治理閘腿；是否沿用與射程由各刀 brainstorm 一題自定。
2. 參考判準（非強制）：寫端多、跨域多之刀宜沿用全四類（驗收場景、SC、FR、Edge Cases）子句表；沿用之刀自備檢核工具（可自工作區前例改寫），並自證空錨與錨不符一律計不符、核數對得上總錨數（LL-00071 守法）。
3. 008 audit-settings-pages 刀之 brainstorm 列一題「本刀是否沿用子句表、射程取哪幾類」，由 `docs/ops/NOTES.md`「下一步」承接。

## 後果

- BL-00146 刪列（收單 `backlog_done`）；LL-00071 之 rule_id 改述指本 ADR。
- 檢核工具續住 gitignored 工作區、不入版控；RULES、閘數與 docsync 預算不動。
- 代價：沿用之刀自付子句表維護成本與工具改寫；不沿用之刀回到逐條形，追溯粒度只到 task。

## 翻案觸發器

- 008 刀收刀承載體檢加一行：若 008 刀沿用子句表，於該刀收單時重審「工具入庫與通則化」（即本 ADR 替代案 1）。
- 任一沿用子句表之刀，其收刀前逐列核或審查揭出檢核工具誤判（空錨恆命中、錨不符漏報等）時＝重審工具入庫。
