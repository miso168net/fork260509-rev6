## 背景

- 002 刀落 casbin enforce seam 時宣告「boot 一次載入即終態、運行期不重載」，理由子句＝當時沒有治理寫端、政策在運行期不會變。005 起刪除選單、刪除角色與編輯選單之按鈕碼絕版三類寫端會在運行期把 `casbin_rule` 列移入授權歸檔 ⇒ 理由子句不成立、宣告連帶失效。若不同步：資料庫已歸檔而記憶體判定面仍持舊政策＝「資料庫已撤、記憶體仍生效」窗（島 H2 之記憶體半邊破口）。
- ADR-00014 決定 4 已預告「casbin 政策集本身 boot 一次 `load_policy` 即終態（運行期重載屬後刀）」——本 ADR 為該預告之**兌現**、不 supersede ADR-00014——決定 4 之終態句自限「於本刀之語意」並括註「運行期重載屬後刀」，本 ADR 落地之運行期重載即該括註所指、非推翻其 002 刀語意。
- 前代刪角色家族「免同步」論證（`rev5:ADR 0050` §2：in-use 守門保證零掛載 ⇒ 殘留列無授權效果）只對刪除當下成立：角色代碼只在未刪範圍唯一 ⇒ 刪 R_X → 同代碼重建 R_X → 指派使用者，舊 R_X 之記憶體授權即被繼承（`rev5:B-093`；前代至使用者域刀才以指派寫端自帶同步閉合，並把「改由 deleteRole 觸發」列為被棄替代案）。rev6 user 拍板採後者（R1-Q2）。

## 決策驅動因子

- 失手模式＝對現役判定面清空後載入失敗 ⇒ 空政策＝含 R_SUPER 全域拒絕、唯重啟可救——最高風險件，必須結構性不可達。
- 同步必須全有或全無、失敗不中斷服務。
- 觸發條件以「實際歸檔」為門：新建選單零授權、零歸檔是常態路徑，「成功即觸發」屬出生即誤（`rev5:B-104`）。

## 考慮過的替代案

1. **對現役實例清空後逐條重載**：非原子、中途失敗半載；棄。
2. **版本號比對丟棄舊快照、免互斥**：需在判定引擎外另立版本面、仍要序列化「讀 DB 之時點」；棄。
3. **背景週期輪詢同步**：引入延遲窗、違 H2 即時失效；棄。
4. **刪角色家族維持免同步、窗留給使用者域刀**：帶已知繼承窗入憲後運作兩刀；棄（R1-Q2）。
5. **互斥件入 AppState**：觸 ADR-00036 恰七欄封條、收益零；棄。

對所選方案跑同一反例（RL-0013）：「互斥件住函式內 static」遇測試建多個 AppState 時，是否讓不同 state 的同步互相阻塞？會——但測試容器內全程 serial、阻塞只延後不死鎖，且生產面恆單一 AppState；成立。「實際歸檔才同步」遇批刪合計零歸檔時是否漏同步？合計零＝判定面零變化、無可同步之差；成立。

## 決定

1. **翻案標的**：`auth/enforce.rs` 檔頭與 `init_enforcer` doc、`main.rs` 連線段註解、`state.rs` 判定面欄 doc 之「boot 載入即終態」「不提供運行期重載」「運行期只有讀鎖」諸句——改寫為「判定面由授權真相全量導出；移除面寫端 commit 後以全新重建後一步換上同步（ADR-00043）」。日後再見「不再重載＝終態」殘句＝文檔漂移、以本 ADR 為準。
2. **重建後一步換上**：`rebuild_enforcer(db)` 另建全新實例——模型 → 轉接器 → 建構 → 載入四步（鏡像 boot 初始化；boot 亦委派同一 fn）；任一步失敗整體失敗、不產出實例；成功才於判定面寫鎖臨界區**一行賦值**換上。判定面容器＝AppState 既有欄（零新欄）。
3. **全程互斥**：`reload_enforcer` 以函式內靜態互斥件包住重建＋換上＋重試全程，使較晚 commit 之結果不被較早開始、較慢完成之重建以舊快照蓋回；鎖序恆「互斥件 → 判定面寫鎖」、無反向取得。交錯時序以測試專用注入點機器證（換上之前可被測試卡住之 await 點；整段測試門控、生產建置零存在）。
4. **失敗契約＝保留上一份**：`RELOAD_MAX_ATTEMPTS = 3`、`RELOAD_RETRY_BACKOFF_MS = 50`（線性退避、末次失敗後不退避；寫死常數、絕不取自輸入、以編譯期斷言自證）；每次失敗（含第 3 次）結構化告警（帶 cause）＋`retry` 計數、耗盡時另計 `exhausted`（三次全敗＝retry 3＋exhausted 1）；同步結果計數 `casbin_reload_total{outcome=ok|retry|exhausted}`（開機預註冊三值；既有告警規則 `obs016-casbin-reload-anomaly` 之錨字面）；耗盡仍失敗＝維持舊面、持續告警、服務不中斷。**絕不空窗、絕不半載、絕不全域拒絕**。該計數為同步結果計數、非降級序列。
5. **★硬禁令＋版本鎖**：**絕不對現役判定面就地呼叫載入**。casbin 2.20.0 之 `Enforcer::load_policy` 為先清空再載入（前代 ADR 與碼註所引、rev6 以特性鎖定測試承擔）——載入失敗即留空政策、在本 repo 模型下＝含 R_SUPER 全拒。升版 MUST 重核其重載語意（縱改為 append 語意、重建後換上仍安全，惟註記須同步更新）。
6. **呼叫端紀律**：同步 MUST 於交易 commit 之後；呼叫時 MUST NOT 持有判定面讀鎖（tokio 讀寫鎖不可重入、持讀鎖再取寫鎖＝永久互鎖；名冊守恆對此形無感、由 review 承載）。
7. **觸發矩陣（恰五支、以實際歸檔列數為門）**：

   | 寫端 | 觸發條件 |
   |---|---|
   | deleteMenu | 軟刪成功且實際歸檔 ≥1 列 |
   | batchDeleteMenu | 整批成功且整批合計實際歸檔 ≥1 列（至多一次） |
   | updateMenu | 按鈕碼絕版實際歸檔 ≥1 列 |
   | deleteRole | 軟刪成功且實際歸檔 ≥1 列 |
   | batchDeleteRole | 整批成功且整批合計實際歸檔 ≥1 列（至多一次） |

   被拒／無作用／標的不存在／標的零政策列／無按鈕碼變更／非絕版移除＝早退結構性不觸發；addRole／updateRole（含停用）／updateRoleHome／addMenu／restoreMenu／選單啟停＝零觸發（角色與選單之啟停由每請求之授權讀端即時濾除）。★不得寫成「成功即觸發」。授權治理刀之授權寫端屆時純消費同一支 `reload_enforcer`、零新機制，其觸發列由該刀 ADR 增列。
8. **無 ABBA 論證**：選單域 advisory 鎖與既有 per-user advisory 鎖共用 PostgreSQL 64-bit key space，結構性無 ABBA＝①key space 不碰撞（域鎖＝高位自描述 ASCII 常數、per-user＝uid）②鎖集合零交集（登入交易不取域鎖、域內寫端不取 per-user 鎖）。★**三失效條件**（任一出現＝論證失效、該刀 MUST 重核鎖序並復核本 ADR）：①角色寫端連動撤會話（觸 per-user 鎖域）②使用者域寫端須進選單序列化域（或反向）③同 key 跨交易嵌套重入（域內 fn 再開新交易並重取域鎖＝自等待死鎖）。
9. **前提與殘窗**：本同步之前提＝**單一 rust-api 行程**；多行程或多實例部署時其他行程之判定面不會同步＝翻案觸發（屆時須比照 IP 規則門鈴補跨行程通知）。**耗盡窗**：重試耗盡期間已歸檔之授權仍留在記憶體面、同路由名重建之選單或同代碼重建之角色可經殘留面繼承（＝島 H2 條文所載之唯一已知降級窗）；恢復＝下次任一成功同步或重啟 rust-api（RUNBOOK §13 處置）。
10. **機器守**：失敗注入（壞連線 ⇒ 舊面續放行 R_SUPER＋retry／exhausted 計數）／「改寫為就地載入必轉紅」負向自證／觸發條件特性鎖定（含零政策列刪除＝零同步、計數零增）／五支移除面端到端（資料庫＋判定面雙斷言；刪除前先斷言判定面確實命中）／成功路徑換上＋ok 計數／三支併發同步全數完成／交錯時序案／三道名冊守恆（同步呼叫點檔集、判定面寫鎖檔集、重載與建構 token 只許家檔；判準見 specs 本刀 `contracts/code-gates.md` §2.1）。

## 後果

- 島 H2 記憶體半邊於本刀起有機器證；授權治理刀之 grant 面純消費本機制。
- ADR-00014 決定 4 之括號預告自此兌現（該 ADR body 不動、讀時併讀本 ADR）。
- 代價：每次移除面寫端成功且有歸檔即全量重建一次判定面（治理 QPS≈0、成本可忽略）；轉接器建構每次重跑建表檢查（PG NOTICE 屬預期）。

## 翻案觸發器

- 多行程或多實例部署（含水平擴展、藍綠並行）⇒ 補跨行程同步通知、重寫前提款。
- casbin 升版 ⇒ 重核 `load_policy` 語意與硬禁令註記。
- 上列 ABBA 三失效條件任一出現。
- 判定面規模使全量重建成本不可忽略（例如政策列數量級上升）⇒ 評估增量同步（須另證原子性）。
