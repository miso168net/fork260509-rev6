## 背景

- ADR-00078（007 刀 plan 期起草、user 2026-10-06 親決、本刀 U0 轉 accepted）拍板設密冷卻與改密舊密節流分家；其決定 2 之判定序為「`precheck` 於開交易之前純讀、結果暫持 → … → ④舊密不符＝交易回滾後 `record_failure` 推一格」，寫入原語 `cache::incr_with_window` 為 MULTI／EXEC 包 INCR＋EXPIRE。
- 本刀 U12 依該序落地後，碼品質審查留下兩則觀察（BL-00144）：
  1. **並發爆量過預檢**：判讀（開交易之前）與推進（回滾之後）皆在帳號鎖之外——同一帳號之並發請求可在任何一筆推進落地之前全數讀到同一舊計數、通過預檢，再於帳號鎖後逐一比對舊密；單窗可猜次數因而受同時在途請求數（連線池與取連線逾時）左右、可遠超 5。前提＝攻擊者已持該帳號有效 access token；每次嘗試另付兩次 argon2（新密雜湊生成＋舊密驗證）。
  2. **壞值鍵不到期**：桶值不可遞增時 INCR 於 EXEC 內失敗而 EXPIRE 照刷——壞值鍵在持續猜測下永不到期，判讀又把不可解析視同 0，該帳號節流形同停用（只人工寫入方生；每次計降級、告警即紅）。
- 前代同形（rev5 as-built 亦於開交易前預檢、回滾後推進），故兩則皆非 rev6 移植走樣，而是承襲之設計缺口；且前形之③以開交易前之預讀定拒，字面上即與憲法島 I1「一切守門判定 MUST 鎖內重驗（lock-then-redecide、永不信 pre-read）」有張力（contracts 端點 2 把③列為守門序之一格）。
- user 2026-10-12 裁定本刀內修（不延後、不立 won't-fix）。順查所見之登入節流同類並發窗（預檢於驗密之前、失敗列寫於驗密之後、帳號鎖更晚）另記 BL-00145、user 裁定延後重評——本 ADR 不涉登入節流（決定 5 射程照舊）。

## 決策驅動因子

- 上界之意義：「窗內至多 5 次舊密比對失敗」須對同一帳號之全部在途請求合計成立，否則門檻只擋得住逐筆送出之猜測者。
- 承憲法島 I1（lock-then-redecide、永不信 pre-read）：③為守門序之一格，判讀入帳號鎖即合 I1 字面。
- 承 ADR-00078：拒絕不得推進計數、不得耗舊密驗證之 argon2（否則持續打即可鎖死任何人之改密）；降級代價不對稱（fail-open）；零 DDL。
- 既有鎖序與收場紀律：帳號鎖＝交易首個動作、早於任何列鎖（`sys_user::advisory_lock_user`）；拒腿一律顯式 rollback、成功一律 commit 後才動快取之清桶。
- 最小改動：既有帳號鎖已把同帳號之 changePassword 排成單列（步序①）——只要判讀與推進都落在其持有期內即嚴格，毋需新鎖、新載體或新 DDL。

## 考慮過的替代案

1. **保留開交易前之預檢、鎖內另加一次重讀**：前一次讀之結果無消費者——節流拒判不得早於①②（本刀 U12 審查已以變異釘死外殼不得據預檢早退），多一次往返、零收益。否決。
2. **鎖內重讀、推進仍在回滾之後**：回滾即放鎖，後到者取得鎖後之重讀與前者之推進競速——窗口縮小但不為零、上界仍非嚴格。否決。
3. **預約式計數**（判讀時先遞增預占一格、舊密驗真後退回）：不靠帳號鎖亦嚴格，但「計失敗」變成「計嘗試再退款」——①②與⑤～⑦之拒腿、故障腿皆須退款，任一漏退即誠實使用者被自己的嘗試鎖住；退款本身又是一次可失敗之快取寫入。否決。
4. **壞值改從嚴（視同已達門檻）**：壞值鍵若無存活期即永久鎖死該帳號改密，且無解鎖端點。否決。
5. **壞值自癒置於呼叫端、以錯誤類別分流**（遞增失敗且屬伺服器回覆錯誤者覆寫為 1）：須在 Rust 側區分「伺服器拒絕命令」與「連線故障」兩類錯誤，分錯即把連線抖動誤當壞值而重置計數（低估）；且覆寫與遞增分屬兩次往返。改在寫入原語內、於伺服器端同一原子單位判斷與重置較精確。否決。
6. **鎖內快取往返不設時間上界、只記代價**（本 ADR 初稿）：快取失聯時連線管理器之重連退避可達數秒，每筆最壞約兩倍退避持帳號鎖與列鎖、並佔一條庫連線於開啟中之交易——已登入者於快取失聯期間連送改密請求即可壓滿庫連線池（池上限為 sqlx 預設、未實測），登入與管理頁隨之變慢或卡住。user 2026-10-12 裁定否決、改設 1 秒上界（決定 2「鎖內快取往返上界」款）。

對所選方案跑同一反例（RL-0013）：

- 「並發爆量」：N 筆同帳號請求皆於①排隊；第 k 筆取鎖後才讀桶，前 k−1 筆之推進皆已於各自放鎖前落地 ⇒ 第 6 筆起讀到 5、拒於③。成立（嚴格）。
- 「成功改密之清桶在 commit 之後、已放鎖」：與之交錯之他請求的推進可能先落地、隨即被清掉一格。被抹去者係於密碼已換之後才比對舊密，觸發清桶者持正確舊密——不放大猜測上界。接受（記於後果）。
- 「快取往返落入帳號鎖持有期」：快取層為自動重連之連線管理器（`cache::connect`：預設退避、無回應逾時）——不設上界時，快取失聯每次往返可能等滿重連退避（數秒）才回錯誤，③④各一次即每筆持帳號鎖、列鎖與一條庫連線達數秒（同形前例：換發〔`handler::auth::refresh`〕於列鎖交易內讀寫閒置時鐘與寬限窗）。所選方案以 1 秒上界收束：每筆最壞約 2 秒、逾時照降級放行；成立（殘餘記於後果）。
- 「壞值自癒被利用」：只有能寫 redis 者造得出壞值；自癒把桶重置為本次失敗＝1，與「不可解析視同 0」同向——不放寬、不從嚴。成立。
- 「可解析整數之人工鍵」（替代案 4 之反例回跑）：無存活期之人工整數鍵（例：5，或 64 位元整數上限）於③照計數判讀＝達門檻即拒、永遠到不了④之推進與自癒＝與替代案 4 同後果。此形屬計數語意本身（人工寫入任何 ≥5 之值皆然、ADR-00078 前形亦同），本 ADR 不處置、記於後果（須人工刪鍵）；遞增溢位之自癒因此只在寫入原語面成立、經端點不可達。

## 決定

（決定編號與 ADR-00078 一一對應：1、3～6 照錄續行；2 改寫〔★標示之四款〕；7 新增。）

1. **設密冷卻（業務政策、走設定鍵）**：
   - 門檻＝設定鍵 `password_change_min_interval`（秒；registry [0, 86400]、seed 60），於消費當下讀現值；`0`＝停用（早退、不查經手表）；缺列、軟刪、不可解析或越 registry 界＝退出廠值 60＋warn 一則（不從嚴、不放行；與密碼政策單鍵異常之取態同向＝ADR-00079 決定 4）。
   - 維度＝（標的 id, 操作者 id）；料源＝`sys_pwd_custody` 該對之 `created_at`（表內零密碼材料）；寫入＝`sys_pwd_custody::touch` upsert 該對時戳，MUST 與密碼欄 UPDATE 同一交易（標的 advisory 序列化域內——分兩交易即有「密碼改了、冷卻帳沒記」之縫）；只 upsert、不刪他列（rev4「本人自改即全刪他人經手列」不帶回）。
   - 三入口一體適用、零豁免：addUser 之初始密碼照落 touch（新標的對無前次、結構上不拒；不落則「建帳後立刻重設」白得一次）；resetUserPassword＝（標的, 操作者）；changePassword＝（本人, 本人）。
   - 未滿＝`2222`＋`biz.user.pwdSetTooFrequent`、`data.remainingSeconds`＝`min(max(I−⌊Δ⌋, 1), I)`（rust `u64`；I＝冷卻設定值、Δ＝距該對上次設密之經過秒數；下限 1、時鐘回撥上限 I——照提示秒數重試必過；明細形與受眾判準＝ADR-00076）；判定件＝`model/password.rs::cooldown_remaining_secs(conn, target_id, operator_id) -> Result<Option<u64>, AppError>`（`None`＝不擋）；判定位次＝政策驗證之後、寫入之前（逐端點步序見本刀 contracts）。
2. **改密舊密節流（安全參數、走碼內常數）**：
   - 門檻＝`throttle/change_pwd.rs` 之 `CHANGE_PWD_MAX_FAILS = 5`、`CHANGE_PWD_WINDOW_SECS = 900`；不入 `system_settings`；與登入節流之同值常數不共用（調參理由不同）。
   - 載體＝redis 計數桶 `cpwd:{uid}`（`cache::CHANGE_PWD_KEY_PREFIX = "cpwd:"`、builder `cache::change_pwd_key`；`cache` 仍為全 crate 唯一鍵渲染點）。寫入原語 `cache::incr_with_window`＝INCR 與 EXPIRE 於伺服器端同一原子單位執行、每次失敗把存活期刷滿 900 秒——以「最後一次失敗後 15 分鐘無新失敗即自癒」實作之滑動窗；拆成兩步則 INCR 成而 EXPIRE 敗會留永不過期之鍵＝該使用者改密永久鎖死。
   - ★**壞值自癒**（本 ADR 改寫）：寫入原語之遞增若遭伺服器以三類錯誤之一拒絕（型別不符、值非整數、遞增溢位），同一原子單位內先除去壞值再遞增（結果＝1）並刷窗——與判讀時「桶值不可解析視同 0」同向；其餘伺服器錯誤（記憶體上限、唯讀等）與連線故障一律不觸發自癒、照本決定末款降級。寫入原語之回值須讓呼叫端分辨此次為自癒，呼叫端（`record_failure`）落 warn 一則（target `security.throttle`）、不計降級（自癒本身不是快取故障）。經端點之可達面：非整數字串＝③判讀視同 0、④推進自癒；非字串型別＝③讀取即錯誤＝照末款降級放行（error 一則、降級一格），④推進自癒；可解析之整數（含 64 位元上限）照計數判讀——達門檻即於③拒、到不了④（遞增溢位之自癒只在原語面成立）。決定 4 表「門檻與壞值」列之「無壞值面」指門檻來源——碼內常數無設定壞值；桶值之壞值歸本款。前形（MULTI／EXEC 內 INCR 失敗而 EXPIRE 照刷）使壞值鍵在持續猜測下不到期、該帳號節流形同停用＝BL-00144 後半。
   - ★**判定序**（本 ADR 改寫；逐步全文＝本刀 contracts wire-user-center 端點 2）：開交易 → 新密雜湊生成（取鎖前＝島 I5）→ ①本人帳號鎖（交易首個動作）→ 本人現役列鎖讀（查無＝`biz.user.notFound`）→ ②兩次輸入一致 → ③節流：於帳號鎖內現讀，`precheck(cache, uid) -> Result<(), Throttled>`（純讀 `cpwd:{uid}`、計數達門檻＝`Err(Throttled)`、不構造 `AppError`；handler 以 `biz.user.changePasswordThrottled` 構造拒因、純 key、不下發剩餘秒數或已用次數）→ ④舊密比對（鎖內；不符＝帳號鎖仍持有、交易回滾之前 `record_failure` 推一格＝唯一推進腿，再回滾、回 `biz.user.oldPasswordMismatch`）→ 後續步。開交易之前不讀桶。
   - ★**並發上界**（本 ADR 改寫）：判讀與推進皆在帳號鎖持有期內——同一帳號之並發請求於①排成單列、後到者於③讀得到先到者已落地之推進 ⇒ 窗內舊密比對失敗對同一帳號之全部在途請求合計至多 `CHANGE_PWD_MAX_FAILS` 次。前形（判讀於開交易之前、推進於回滾之後）使並發請求可在任何推進落地之前全數讀到同一舊計數＝BL-00144 前半。
   - ★**鎖內快取往返上界**（本 ADR 新增；user 2026-10-12 裁定）：③之讀桶與④之推進各以碼內常數 1 秒（`throttle/change_pwd.rs` 之 `CHANGE_PWD_CACHE_TIMEOUT`）為上界；逾時＝視同快取讀寫失敗、照本決定末款降級放行（error 一則、降級一格），不得因逾時拒絕或升 `5000`。逾時之推進可能稍後仍於伺服器端落地（多計一格＝從嚴側、可接受）。清桶（commit 後、已放鎖）不在本款射程。
   - 節流拒絕路徑零舊密 argon2 驗證、零稽核、零計數推進；成功改密於 commit 之後 `clear`（清在前而交易回滾＝白清一次桶）。
   - 窗自癒、無解鎖端點。降級＝redis 讀寫失敗即放行（不計數、不拒）並經既有出口 `throttle::warn_degraded("redis_change_pwd")` 落一則 warn、計數一格；快取層自始缺席（測試 seam）＝整層跳過、不計降級。
3. **觀測**：`THROTTLE_DEGRADED_SOURCES` 增 `redis_change_pwd`（10→11）、開機預註冊 0；名冊雙向守照舊——名冊→發射端（出口逐值增長案）、發射端→名冊（obs 測試對 `warn_degraded` 字串字面引數之全樹掃描；經既有出口發射即自動在射程內，此為不另立第二出口之理由，前代則自成出口、不經該函式）。告警規則 `obs016-throttle-degraded` 不設 source 篩選、自動涵蓋新值、規則本體零改動。
4. **不建通用節流 seam**（BL-00124；rev6 形四面比較）：

   | 面 | 登入節流（島 E／F；ADR-00038） | 改密舊密節流（島 I；本 ADR） |
   |---|---|---|
   | 判定鍵 | 帳號維＝送出之帳號名原文（未驗身、請求端自選）；來源維＝來源位址桶 | uid（已驗身、取自身分注入、請求不可指定） |
   | 判定真源與載體 | PG 滑動窗：`sys_login_attempt` 失敗列於每次嘗試重算；redis 只承載驗證碼標記與解鎖標記 | redis 計數桶本身即真源；無 PG 列 |
   | 語意分區與解除 | 三區（自由／需驗證碼／鎖定）；窗出界、帳號維成功重置、管理員解鎖端點 | 兩態（過／拒）；窗自癒、成功即清；無解鎖端點 |
   | 門檻與壞值 | 每維設定三鍵、每次嘗試讀現值；壞值整組退常數＋告警 | 碼內常數；無設定鍵、無壞值面 |

   抽一個同時容納三區與兩態、PG 真源與 redis 真源之 seam＝為兩個不同形之消費者硬造抽象（`throttle::precheck` 之簽章將被迫長出「要不要驗證碼」「真源在哪」之參數）。共通者只有觀測序列（同名冊、同出口；決定 3），不構成 seam。004 刀 spec Out of Scope 首條之通用化 seam 判 won't-fix；翻案觸發＝出現第三個消費者且與既有兩者之一同形。
5. **ADR-00038 射程釐清**（不翻案、不 supersede）：該 ADR 為登入節流判定面（標題與 provenance 皆指 004 刀之登入兩維）；其決定 2「redis 在節流面只承載兩種鍵」之「節流面」讀作登入節流面，決定 1「PG 定案、無負快取」亦只對登入兩維。改密節流桶屬島 I 之常數面（前代島 I 常數列即含「改密節流之窗與次數」；rev6 條文字面由 ADR-00074 親決）、不屬島 E；憲法島 E「redis 於本島只承載…」之「本島」已自限、續真。改密桶是計數真源、不是負快取（沒有第二份會落後的真相）。
6. **不觸發者**（複核結論）：ADR-00069 款 5 之翻案觸發「新增不可自癒之 redis 狀態」不成立——改密桶遺失＝窗提前自癒；ADR-00037 翻案觸發器首條不成立——changePassword 為 Authed、判定鍵為 uid、不讀來源位址（spec FR-031）。
7. **現在式面改指**（本 ADR 新增）：現在式面——rust-api 碼註、活書、RUNBOOK、告警規則錨註、本刀 spec／contracts／data-model／quickstart 之現行句——引用 ADR-00078 之處改指本 ADR 同號決定（決定編號一一對應、只改 ADR 號）；史料面（brainstorm、research 之 ADR 配號與親決時點表及當期論證、tasks 已勾 task 之施工紀錄、已 accepted 之他 ADR 本文、events）不改。ADR-00082（proposed）款 5 之射程讀法句與背景句同改指本 ADR。

- **親決紀錄**：決定 1、3～6 照錄 ADR-00078（user 親決 2026-10-06：逐款一題一問、皆照文定稿）。決定 2 之改寫＝user 2026-10-12 裁定 BL-00144「本刀內修」（裁定前之提醒已列明修法須改規格，例：鎖住帳號後再讀錯誤次數）；判讀入鎖、推進改於回滾之前、壞值於原語內原子自癒且不計降級＝主線工程判斷（已向 user 報備）；鎖內兩次快取往返各以 1 秒為上界、逾時照常放行＝user 2026-10-12 裁定（提醒列明快取失聯時每筆佔庫連線數秒、可加短逾時）。決定 7＝ADR 形制（承 ADR-00068 之現在式面改指前例）。

## 翻案觸發器

- 出現第三個節流消費者且與既有兩者之一同形 ⇒ 重評通用 seam（決定 4）。
- 改密失敗須留可稽核之持久紀錄（安全審查、事故鑑識）⇒ PG 載體＋DDL，複核決定 2 與 ADR-00038 之射程關係。
- redis 狀態遺失成為可被利用之實際事故、或改密桶改為不可自癒之形 ⇒ 複核決定 6 與 ADR-00069 款 5。
- 支援面出現「替使用者解除改密節流」之實際需求 ⇒ 複核「無解鎖端點」。
- 節流門檻出現第二個合理答案（組織差異之實際調參需求）⇒ 依判準改設定鍵。
- 冷卻出現豁免需求、或維度須改為標的單維 ⇒ 複核決定 1。
- fail-open 於事故中被實際利用 ⇒ 複核降級方向。
- 登入節流判定面改形（ADR-00038 翻案）⇒ 複核決定 4、決定 5。
- 1 秒上界下仍見帳號鎖長持或庫連線池壓力之實際事故（同帳號登入或使用者域寫端排隊逾時）⇒ 複核上界值與「判讀與推進在帳號鎖內」，或為快取層設全系統回應逾時／縮短重連退避（另立 BL 或 ADR）。
- 登入節流之同類並發窗（BL-00145）改形落地 ⇒ 複核決定 4 之四面比較（兩者判定序是否趨同、可否共用序列化形）。
