## 背景

- ADR-00032（2026-09-15）定碼面閘名冊＝`docs/ops/RUNBOOK.md` §12 碼面閘表（四欄人寫），成員集由 GT-12 腿雙向機器對賬；其翻案觸發器①寫「碼面閘 ≥8 支、或『守什麼／觸發時機』欄需由工具 docstring 機器抽取時＝另立生成檔並翻案」。
- 第 7、8 支於 2026-09-20（004 刀）同顆進場，觸發器①當日成立；004 與 006 刀增閘時皆未複核，007 刀 plan 期（2026-10-06）才揭出並記為 BL-00142。現況碼面閘 10 支。
- 成員集早已由 GT-12 機器守；真正靠人維護的只剩「守什麼」「觸發時機」兩欄描述文字。

## 決策驅動因子

- 支數門檻與「名冊是否該機器生成」無因果：支數增加不使人寫描述更易漂移，成員集又已機器守。
- 翻案觸發器須綁可觀測的檢查點，否則成立後無人察覺（BL-00142 即實證；RULES 與 docsync 對翻案觸發器皆無監看面）。
- docsync 行數已超預算；另立生成檔須重寫十支工具說明、增生成器與自測。

## 考慮過的替代案

1. **另立生成檔並翻案**：十支工具檔頭說明改成可機器抽取之段、docsync 增生成器（入 GENERATED_FILES）、GT-12 改對生成檔、RUNBOOK 表改指針；描述欄零漂移，但估中、docsync 行數再增，收益只及兩欄描述。棄。
2. **維持現觸發、不動**：BL-00142 之觸發「下一支治理維護批起手前」已於本批到期，不動＝違反條目自述時序。棄。

對所選方案跑同一反例（RL-0013）：「描述欄與工具實況漂移而無人察覺」——本 ADR 翻案觸發器首條即以審查揭出漂移為條件，刀內審查、規格對照輪與獨立輪本有比對工具實況之面；成員集漂移仍由 GT-12 當場紅，成立。

## 決定

1. ADR-00032 決定 1～3 原意續行，現行依據＝本決定：名冊唯一權威＝`docs/ops/RUNBOOK.md` §12 碼面閘表（人寫）；GT-12 腿雙向對賬 S_tools 與表首欄路徑集；RULES 名詞段碼面閘定義不變；新碼面閘進場同刀入表。
2. 不另立生成檔；不以碼面閘支數為翻案條件。
3. 現在式面引用 ADR-00032 之處（RULES 名詞段碼面閘定義、RUNBOOK §12 碼面閘表 schema-gate 列「根據 ADR」欄、README 查詢表）改指本 ADR；accepted ADR body 內之引用不動，讀時併讀本 ADR。

## 後果

- ADR-00032 整顆轉 superseded（`superseded_by` 由 generate 回填）；GT-12 腿、碼面閘表與 `NON_GATE_TOOLS` 行為零改動。
- BL-00142 刪列（收單 `backlog_done`）。
- RULES 名詞段之改指不入 agent 規則塊（RULES-VERSION 只雜湊規則表）。

## 翻案觸發器

- 審查（刀內審查、規格對照輪或獨立輪）揭出碼面閘表「守什麼／觸發時機」欄與工具實況漂移時。
- 「守什麼／觸發時機」欄需由工具說明文字機器抽取時（例：工具以結構化檔頭自述觸發時機、表與之重複）。
- ADR-00010 對 GATES.md 收錄範圍改判時一併重審（承 ADR-00032）。
