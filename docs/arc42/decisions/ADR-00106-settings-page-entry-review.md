## 背景

- 設定頁進場觸及四支既有 ADR 之觸發器或射程：ADR-00079（密碼政策矛盾之前端提示或擋送出）、ADR-00054（界值唯一權威）、ADR-00057（宣告集外列讀得到、寫回 2222）、ADR-00064（封死集）。
- rev5 前端手抄五鍵界值（`rev5:B-160`）；另五鍵越界送後端拒（clarify Q1 查證）。
- 密碼政策 hook 只增不清（007 刀已知態）。

## 考慮過的替代案

1. **擋送出矛盾組合**——ADR-00079 決定 2 定後端逐鍵驗、不新增組合守門；擋送出須另立 ADR 翻案；否決（D2）。
2. **前端照 rev5 逐鍵鉗界**——回到手抄鍵集之老問題；否決（clarify Q1）。
3. **宣告集外列可編**——寫回必 `2222`；否決（工程判斷③）。

對所選方案跑同一反例（RL-0013）：「誤打越界值被靜默存成界值」→成功提示、框內數值與操作日誌舊→新三處可見；成立而接受（clarify Q1 代價、分岔表登記）。

## 決定

1. **ADR-00079 觸發器重評**：前端即時提示三對嚴格不等式矛盾（`password_min_length` ＞ `password_max_length`、`login_throttle_captcha_after` ＞ `login_throttle_max_fails`、`ip_captcha_after` ＞ `ip_max_fails`），警示落該組卡片並寫後果、不阻存；相等合法；ADR-00079 決定 2（後端逐鍵驗、不新增組合守門）維持、不 supersede。
2. **ADR-00054 觸發器不成立**：界值由讀端 wire 下發（`rangeMin`／`rangeMax`、取 REGISTRY）；前端不抄鍵集；10 個 number 鍵一律鉗界（越界失焦即改界值後送出）。
3. **ADR-00057 之呈現**：讀 wire 下發 `declared`；宣告集外列唯讀、排組尾、標示後端 description；寫回仍 `2222`（ADR-00057 不變）。本刀 CDP 實測：宣告集外列以唯讀值＋「唯讀」標籤呈現、排所屬組尾（依鍵前綴歸組，前綴皆不符者歸工作階段組尾；同組多列保伺服器相對序）、label 與懸停說明取後端 description（無 description 者 label 顯鍵名、不出說明圖示）、點擊零寫入；某組全無列時該組卡片不渲染。
4. **ADR-00064 不下放**：設定兩端點續為封死集；選單維可見性可授（ADR-00103 款 10）。
5. **密碼政策快取**：寫入政策七鍵任一成功即清同分頁快取（hook 增清除函式）；其他分頁仍須重新整理（RUNBOOK §11.3 改設定頁首選）。本刀 CDP 實測（寫入 `password_min_length`、`password_require_digit` 兩鍵；七鍵集＝FR-048、碼同集）：七鍵任一寫入成功後，同分頁再開重設密碼浮層、個人中心改密卡或隨機密碼皆重讀政策一次並用新值；七鍵外之鍵寫入與寫入被拒皆不清（不重讀、沿舊值）；其他分頁不重新整理即沿舊值；清除當下在途之舊政策回應不回填快取。
6. **刻意分岔**（對 rev5 HEAD；spec 刻意分岔表為單一出處；各項 rev6 畫面效果＝本刀 CDP 三方對照實測〔⑥之步進鈕與上下方向鍵路徑依碼與分岔表；⑤之 zh-tw 改字後字面經 user 抽查〕；rev5 側括注之後端結果出自分岔表 rev5 欄與 rev5 凍結碼〔22080 非 GET 一律攔截〕）：①跨鍵矛盾提示——三對嚴格大於時該組卡片出一則警示並寫後果、相等不警示（rev5 無提示）；②政策快取清除——見決定 5（rev5 同分頁沿舊政策至重新整理）；③宣告集外列唯讀——見決定 3（rev5 依型別呈現：number 型為可編數字框、二值 enum 型為開關，改值即送、寫回 `2222`；其他型別兩側皆唯讀顯原值，rev6 另加「唯讀」標籤）；④數字框五鍵（`ip_captcha_after`、`ip_max_fails`、`ip_window_minutes`、`password_change_min_interval`、`session_idle_timeout`）由「送出被拒」改「鉗界存檔」——越界失焦即送界值（rev5 此五鍵送越界原值、後端拒；其餘五鍵兩側皆鉗界）；⑤節流說明——`ip_max_fails`／`ip_captcha_after`／`login_throttle_max_fails`／`login_throttle_captcha_after` 四鍵 help 於 rev5 原句末補不承諾嚴格上限之註（zh-cn「（并发首波不严格）」、en-us「(not strict under concurrent first bursts)」；zh-tw 無 rev5 原句，同位補「（並行首波不嚴格）」＝決定 7 之分岔面）；⑥數字框送出被拒或清空——以 Enter（或步進鈕、上下方向鍵）發值遭拒、或清空後按 Enter（不送、只回讀）：回讀落定後框內即回退為伺服器現值、焦點離框、只回讀一次（rev5 框內停在使用者輸入、失焦後才回退——被拒形於失焦時以同值重送一發、清空形於失焦時再回讀一發）；送出成功不回退＝同 rev5。
7. **說明文案**：16 鍵 label＋help 三語全映射；帳號登入與 IP 源登入兩組不承諾嚴格上限（BL-00145 約束）。

## 後果

- 誤打越界值會存成界值（clarify Q1 代價）；可由操作日誌追溯。
- 四支既有 ADR 皆不 supersede（觸發器重評結論與呈現面住本 ADR）。

## 翻案觸發器

- 出現擋送出矛盾組合之需求 ⇒ 新 ADR 翻 ADR-00079 決定 2。
- REGISTRY 新增非 number 有界型 ⇒ 重評讀 wire 界值欄。
- 出現設定頁下放之需求 ⇒ 重評 ADR-00064 封死集。
