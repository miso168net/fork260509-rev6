## 背景

- 憲法 §I.3 的 13 碼矩陣條寫「4 保留碼（`7778`/`8889`/`9998`/`9999` 組內後端從不發出者）僅前端 `.env` 分組認得、**contract test 斷言後端從不發出**」。
- 002 刀 as-built 實際把該守恆放在 `rust-api/server/src/error.rs`：型別層以 enum 全變體窮舉（新增變體即編譯期失敗）＋`#[cfg(test)]` 矩陣斷言雙錨；`rust-api/server/tests/contract.rs` 對這四碼零命中，且其檔頭自述「本檔不重寫第三份」（避免同一事實三處鏡像）。
- 實質守恆未失——四碼確實有機器面在守，而且型別層比 contract test 更早失敗；失準的是憲法指名的**承載點**。

## 決策驅動因子

- 凍結權威指名了一個不存在的承載點，讀者依字面去 `contract.rs` 找會找不到，且無從得知真正的守法在哪。
- 型別層窮舉是更強的保證（編譯期 vs 執行期），把它記進憲法比反向補一個較弱的測試更誠實。
- `contract.rs` 自述的「不重寫第三份」是刻意的設計取捨（避免鏡像），反向補案會推翻它。

## 考慮過的替代案

1. **在 `contract.rs` 補一案兌現憲法原文**：棄——需動 rust-api 子庫（commit＋pin bump＋容器內跑 test），超出本輪範圍；且與該檔自述的設計意圖相左，等於製造第三份鏡像。
2. **轉 BL、下一支動 error 矩陣的刀再處理**：棄——凍結權威的字面失準是現行缺陷，且此改動零行為風險。

## 決定

1. **憲法 §I.3 該句改為**：「4 保留碼（`7778`/`8889`/`9998`/`9999` 組內後端從不發出者）僅前端 `.env` 分組認得、**型別層全變體窮舉＋`error.rs` 矩陣斷言雙錨守其從不發出**」。
2. **零行為變更**：不動 `error.rs`、不動 `contract.rs`、不新增測試。本 ADR 只把凍結權威的承載點字面對齊 as-built。
3. 13 碼矩陣本身、HTTP status 例外、`5000` 一律 200 信封等其餘條款皆不動。

## 後果

- 憲法版本隨本輪 Amendment 一併 bump（§V.3 PATCH：釐清；本輪合併 commit 取最高級別 MINOR）。
- 讀者自憲法可直達真正的守法處；`contract.rs` 的「不重寫第三份」設計意圖得以保留。
- 代價：憲法句自此帶實作細節（型別層／檔名），較原本的「contract test」抽象；換得的是字面為真。

## 翻案觸發器

- `error.rs` 的錯誤碼表改為資料驅動（不再是 enum 變體）時，型別層窮舉不再成立，須重審承載點。
- 保留碼集合變動（4 碼增減）時一併重審本句。
