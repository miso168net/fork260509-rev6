## 背景

007 刀 U0 兩顆親決（T002 Amendment 顆、T003 施工前提顆）沿用「ADR 決定節逐款一題一問」，共呈約 130 題：T002 49 題（被憲法條文指向之他 ADR 決定款 18、ADR-00074 親決題索引 30、連動 1）、Amendment 自擬文字覆核 10 題、T003 73 題（十一支 ADR 決定款 72＋連動 1）。實得：

- user 選非建議項者 2 題（I-d1、T-a），皆屬 ADR-00074 親決題索引——plan 期已標為待決之題。
- 其餘約 100 題「照文／照擬」確認題，零題由 user 提出改動；唯一改字（ADR-00086 決定 5 與其翻案觸發器連動行）由主線提出，起因為 T002 先改憲法致該款過時。
- T003 之 72 款自 plan 定稿（`b35ee2c`）至 U0 前（`728c4cb`）只 1 款改動（ADR-00084 決定 7）：「plan 期就決定、其後草稿還會變」之顧慮在本刀幾不成立。
- 以各款標題粗分，72 款約三分之二屬工程層（錯誤變體形狀、常數、測試清單、機器守、遷移語句、簿記改指），約三分之一屬拍板級（行為、範圍、schema），後者多數可追至 brainstorm 答覆、spec 條目或既有 accepted ADR 之續行；款內標出 user 決定出處者僅 9 款。
- 成本：問答牆鐘約 4 小時；出題錯字 6 起（T002 至 T003 合計）、長預覽未回傳 1 起，皆隨題數放大。72 題全選建議項，無從分辨「草稿皆對」與「格式引不出異議」；且到 U0 時 tasks 與子句表已建於草稿之上，改一字須連動改 tasks，格式本身偏向照文。

憲法 §I.8 只要求拍板級項（schema／scope／破紀律／user 可見行為）經 user 親決，並載明「逐 diff 親讀非必要條件」；CLAUDE.md §5 定純工程「怎麼做」由主線自拍、回報備查——逐款全問之射程超出兩者所要求。逐款出題另有一項附帶收益須保留：出題前主線逐款對照現況核實，I-d1 與 ADR-00075 決定 4 之不一致即由此抓到。

user 2026-10-06 問「plan／tasks／analyze 已多輪確認，為何仍要親決」。主線答：前幾輪確認的是文件一致與需求追溯，未逐款確認 ADR 內容，親決補的是真缺口，但問得太晚、題目太多；並提五點改法。user 裁定採行、現在改，以 007 刀 T103 為首次驗證點。落字時主線補寫有兩處超出核可原文，當場各呈一題：射程（user 取「只套 SDD 刀 plan 期 ADR」）與承決出處終點（user 取「spec 條目可直接當出處」），兩題皆取非建議項。

## 決策驅動因子

- user 的注意力只花在真正要選的題；同一決定不問兩次。
- 決定在出現當下最便宜（tasks 尚未建於其上）。
- 讀與選分流：通讀用文件、選擇用問題。
- 減題不得讓主線起草之拍板級內容不經出處核對即 accepted。
- 保留出題前之現況核實。

## 考慮過的替代案

1. **維持逐款全問**——成本與錯字隨題數放大、格式偏向照文（背景）；user 裁定改制；否決。
2. **只刪工程款、其餘照舊逐款問**——承決款仍重問 user 已做之決定，決定仍延至 U0；否決。
3. **整支 ADR 一題批准、不分類**——待決被捆入一題，違反一題一問；否決。
4. **分類由起草者自標、不經獨立核對**——誤標與出處偏差無人察覺；否決。
5. **一律套用至全部 ADR（含維護批、review 輪）**——規則單一，但小 ADR 每支多一支核對 agent 與一題；user 取「只套 SDD 刀 plan 期 ADR」；否決。
6. **承決出處終點限 user 決定紀錄、spec 條目只作中途指標**——spec 中標主線判斷之內容若涉拍板級即升待決、較保守；user 取「spec 條目可直接當出處」；否決。

## 決定

1. **射程**：SDD 刀 plan 期起草之 ADR（含 Amendment ADR）。維護批與 review 輪之 ADR 維持現行——user 於對話裁定後由主線寫成 accepted，不建分類表、不派核對 agent；刀內非 plan 期起草之 ADR（例：收刀前 PATCH Amendment）依該刀 tasks 所定之親決形。已 accepted 者不回溯。
2. **三類**：決定節每款（含款內表列項）標一類；一款混有多類內容者取最高類（待決＞承決＞工程）。
   - **待決**：新出現之拍板級內容（判準＝RULES 名詞段「拍板級」）且無可承之出處。
   - **承決**：轉錄 user 已做之決定。出處終點須為 user 決定紀錄（brainstorm 之答覆與經核可之設計節、AskUserQuestion 答覆、accepted ADR、憲法、載明 user 裁定之 events／NOTES／commit 訊息）或 spec 條目（FR、SC、驗收場景、Edge Cases 等；user 2026-10-06 裁定可直接充出處）；plan、research、tasks 只作中途指標、不得充終點。
   - **工程**：怎麼做（碼形、命名、測試、機器守、簿記）；涉拍板級者不得標工程。
3. **對照表**：ADR 設「## 親決分類」節，列「款｜類別｜出處或理由｜白話一句」；表即出處之單一住處（款文不另標）；隨草稿維護，accepted 後與本文同不可變。
4. **待決當場問**：plan 起草時已知之待決，於 plan 期以 AskUserQuestion 一題一問，不延至 U0；其後新出現者最遲於該 ADR 轉 accepted 前逐題問（實作期依 CLAUDE.md §2 停點①）。答覆與作答時之 commit 記入該 ADR 親決紀錄。
5. **獨立核對**：草稿完成時（plan 期草稿於 plan 期）由非起草者之 fresh-context 審查 agent 逐款核四事——①誤標（工程或承決款含拍板級新內容）②出處相符（承決款內容對其出處多寫、少寫或寫偏）③白話與款文相符 ④現況（款文所述之碼、文件、他 ADR 款與 repo 現況相符，同批 ADR 間無矛盾）。①②不符或拿不準即升待決；③④不符則改正。核對結果記親決紀錄。
6. **轉 accepted 前收尾**：①待決款以作答時 commit 對 HEAD 之 `git diff` 核款文，作答後改過者重問 ②自上次獨立核對後改過之款依決定 5 復核 ③對照表一次呈 user：AskUserQuestion 一題（照表定稿〔建議〕／拉出款號），拉出之款逐款一題一問 ④status→accepted，親決紀錄載各類款數、核對結果、實問題數、拉出款與其結果。
7. **Amendment ADR**：§V.2 之 user 親決照舊；條文內容之待決依決定 4 逐題問；主線自擬之銜接字面（差異申報、版本級句、Amendment log 列等）以一份 diff 一次呈 user，不逐項問。
8. **首次驗證＝007 刀 T103（ADR-00081／ADR-00082）**；比對量記入該顆 commit 訊息：①實問題數（待決＋拉出＋收尾）對舊制等價題數（兩支決定節編號款＋已知態款，T103 當下現算；本 ADR 落地時＝4＋20＋2＋8＝34）②user 自對照表拉出之款數與其中改字數 ③獨立核對升級數（誤標、出處不符）與改正數（白話、現況）④出題錯字起數 ⑤user 改動（非建議項或改字）是否全落待決集合 ⑥親決輪牆鐘。基準＝007 刀 T003（73 題、user 提出之改動 0、約 3 小時；錯字與 T002 合計 6 起）。plan 期當場問之部分首次實施於 008 刀 plan。
9. **前制**：SDD 刀 plan 期 ADR 之「決定節逐款一題一問」由本 ADR 取代；拍板級問題一題一問之通則（CLAUDE.md §5）不變。

- **親決紀錄**：user 2026-10-06 於主線對話裁定採行五點改法並「現在改」；AskUserQuestion 兩題——射程＝「只套 SDD 刀 plan 期 ADR」（非建議項；決定 1）、承決出處終點＝「spec 條目可直接當出處」（非建議項；決定 2）。本 ADR 依決定 1 屬現行形（對話裁定後由主線寫成 accepted），不建分類表、不派核對 agent。

## 後果

- 正面：同一決定不重問；題數集中於待決；決定前移至出現當下；出題錯字之暴露面隨題數縮小。
- 負面：每批 plan 期 ADR 增一道核對 agent 成本；承決「相符」由 agent 判，細微偏移可能漏網（防法＝決定 5 拿不準即升待決、user 可自表拉出任一款）。
- user 知情採行之風險：spec 條目可直接充承決出處，spec 中標「主線工程判斷／主線定案」之內容若涉拍板級，可不經逐款親決而 accepted；射程外之 ADR（維護批、review 輪）之補寫內容無獨立核對。
- 無機器守：對照表完整性（每款入表）靠主線自律與獨立核對，未設 lint 腿。
- 007 刀同批改：tasks 之 U22 Purpose 句與 T103、`contracts/code-gates.md` §8.1 ADR-00081 列、quickstart 已知態段一句；T104（收刀前 PATCH）非 plan 期起草，依決定 1 不改。

## 翻案觸發器

- T103 或其後實施中，user 自對照表拉出之款經改字 ≥1（分類藏了決定）⇒ 檢討決定 2 判準。
- 實施中有款未入表、或白話與款文不符而未被獨立核對抓到 ⇒ 增 lint 腿或改核對形。
- T103 比對量①實問題數未明顯少於舊制等價題數 ⇒ 重估本制。
- spec 條目充承決出處後，出現未經 user 決定之拍板級內容被 accepted ⇒ 重議決定 2 之出處終點。
- user 要求擴大射程或恢復逐款全問 ⇒ 新檔 supersede。
