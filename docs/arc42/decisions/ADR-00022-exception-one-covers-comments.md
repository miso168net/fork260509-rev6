## 背景

- 憲法 §I.5 對 rust-api 全樹下四款紀律：讀允許、拷貝禁止、**註解一律重寫**、防回歸。例外①（`sea-orm-adapter`／`xdb` 工具性 crate 整檔拷貝）只豁免「拷貝禁止」，對第 3 款無任何豁免字樣。
- 實況與字面相左：`rust-api/sea-orm-adapter` 63 行註解中 50 行與 rev5 凍結樹逐字同文。maint-backlog-25 建的自證腿 `tools/docsync/vendored.py`（`vendored-check`）**刻意剝除整行註解後才比對**，等於在工具層預設了「註解面不受例外①管轄」，但該口徑只住工具 docstring 與收單事件，無凍結權威背書。
- 兩種讀法並存且皆可自圓：「整檔拷貝」是否自動含註解。000-r2 的 L2-06 把它記為規則承載缺口。

## 決策驅動因子

- 例外①的立意是「工具性 crate 承 rev5 已驗證成果、不重寫」；註解逐行改寫與該立意矛盾——改註解等同部分重寫，反而製造與上游 diff 的雜訊。
- 例外②（資料形狀契約三件）明文採「註解依語意判準重寫」，兩個例外的註解口徑不同是刻意的：例外②是 rev6 自家資料契約、要 rev6 語境；例外①是外部工具移植、要與上游可比。
- 工具已按此運作（`vendored-check` 去註解比對），缺的只是凍結權威的一句話。不補則工具口徑與憲法字面永久相左。

## 考慮過的替代案

1. **不豁免，逐行核 50 行同文註解**：把例外① 納入 RULES 名詞段「隨遷工具」的四型失效引用判準。棄——與「整檔拷貝」直覺相左，且每次上游 rebase 都要重核。
2. **轉 BL、留待下一支動 sea-orm-adapter 的刀**：棄——`vendored-check` 已入 bootstrap 3c 步每台機器跑，口徑無權威背書是現行狀態的缺陷、非未來的事。

## 決定

1. **憲法 §I.5 例外① 句補「含註解」**：例外①的整檔拷貝射程含註解，豁免同節第 3 款「註解一律重寫」。
2. **例外②不受影響**：資料形狀契約三件仍採「註解依語意判準重寫（四型失效引用必改、前代出處帶 `rev5:`）」——兩例外的註解口徑刻意不同，理由見決策驅動因子。
3. **`vendored-check` 口徑就此有權威來源**：其「去整行註解後逐位元比對」＝程式面自證；註解面隨例外①豁免、不另設判準。工具 docstring 引本 ADR。
4. 例外①自證射程現為 `rust-api/sea-orm-adapter`；`xdb` 兩樹皆無實例，進場時須同批擴 `tools/docsync/vendored.py` 之 `VENDORED_DIR`（RUNBOOK §12 已載）。

## 後果

- 憲法版本 1.1.0 → 1.2.0（§V.3 MINOR：§I 例外清單射程擴展、規則方向不變）。
- `vendored-check` 行為零改動——本 ADR 是把既有實作補上權威來源，不是改實作。
- 代價：兩個例外的註解口徑不同，讀者須分辨；已由憲法句與本 ADR 決定 2 明寫。

## 翻案觸發器

- 例外①的 crate 需要 rev6 語境的行為變更（非純移植）時，該 crate 應退出例外①、回歸全新寫紀律，本 ADR 隨之失效。
- `xdb` 進場而其註解含 rev5 專屬事實（埠、分支名、路徑）時，重審是否需對例外① 另立四型失效引用的最小判準。
