## 背景

本刀把角色頁與選單頁接真，但授權治理（選單維／按鈕維授予、授權回收桶）、使用者域與稽核頁皆在後續刀。其間有若干畫面行為是**刻意選擇之現況**而非缺陷；不集中立案，審查輪與 CDP 對照會一再當 finding 重報。各款一律寫成「觀察路徑→症狀」，並於 CDP 走查**實際操作觀察**後定稿（推論不得代替觀察）。

## 決策驅動因子

- 已知態單一出處、每款可到期（附翻案觸發器）。
- 目標零新 BACKLOG：本刀已知態以本 ADR 承載，真有後續工作者指向既有條目。

## 考慮過的替代案

1. **逐款各立 ADR**：八款同屬一刀一域、拆開只增索引噪音；棄。
2. **授權治理刀前隱藏角色頁兩顆授權鈕**：須改兩顆彈窗入口所在檔之授權外行為、且使 CDP 對照多一差；棄（R1-Q9）。
   對所選方案跑同一反例（RL-0013）：合併立案是否讓單款翻案變難？不會——翻案時新 ADR 以 `supersedes` 指向本檔並聲明「某款翻案、其餘續行」；成立。

## 決定（草稿；「症狀」欄於 CDP 實際觀察後逐款定稿）

1. **角色頁兩顆授權彈窗**：「菜單權限」彈窗開啟即取真選單樹與真首頁下拉選項，但首頁現值恆寫死 `home`、勾選為寫死 id 1～21（不代表真授權）、送出假成功零寫入；「按鈕權限」彈窗全為假資料。兩顆彈窗一行不動（用途 (ii) 明文不入名單）。觀察路徑＝角色列表→編輯→點兩顆授權鈕→勾選並送出→資料庫零寫入。
2. **policy-archive 選單項為死項**：側欄可見、點擊之症狀以實測定稿（若與 BL-00045 描述不符、以 errata 改該條文）。
3. **新建或復原之選單側欄不現（含 R_SUPER）**：新建零授權（兩步流第一步）、復原不回灌 ⇒ 授權治理刀前無法授予側欄可見性；管理列表可見可編。觀察路徑＝新增選單→側欄與直打網址。
4. **新增或復原之按鈕碼無人持有（含 R_SUPER）**：`getUserInfo` 之按鈕碼取自判定面、前端 `hasAuth` 無超管旁路 ⇒ 對應按鈕不現。
5. **新建選單於治理清單顯原始 i18n 鍵字面**：`route:` 樹零新增、`$t` 查無鍵回退字面。
6. **治理清單三列顯路由裸鍵**：system-settings／policy-archive／audit 三列（各頁進場刀帶入譯文時解除；BL-00045 條文補「選單管理頁」曝光面）。
7. **getAllRoles 之既有 UI 消費者＝upstream 使用者頁新增抽屜**：自本刀起下拉顯示真角色、提交仍假成功（使用者域刀接真）；roleHome 兩端點零 UI 消費者。★`rev5:B-145`：getAllRoles 只回活性且啟用 ⇒ 使用者頁看不到其持有之停用角色——使用者域刀進場時複核。
8. **治理清單分頁列凍結＋無 size 全取**：分頁列位置不動、頁碼 1、每頁 0、整列停用、前綴顯真實筆數（`rev5:ADR 0060` 形）；後端無 size 回全部頂層 ⇒ 前代「頂層 >100 列截斷且無從翻頁」殘餘消解；前端把回應 size 回寫每頁筆數、首載與頂層列數增減時各多一發重取（畫面不變；CDP 排除請求次數維度）。

## 後果

- 審查輪與 CDP 對照遇上列八款，指向本 ADR 即結案；新發現之同類現象不自動適用、須個案判斷；走查期新發現之已知態直接併入本草稿。
- 款 2／款 6 由 BL-00045 承載後續工作；其餘款之解除點＝各自翻案觸發器。

## 翻案觸發器

- 款 1／款 3／款 4：授權治理刀落地（三顆授權彈窗接真、選單維與按鈕維授予）。
- 款 2／款 6：policy-archive、設定、稽核各頁進場刀帶入頁面與譯文。
- 款 5：選單新增流程改為同時登記 `route:` 譯文、或改以 `menuName` 回退顯示。
- 款 7：使用者域刀接真使用者頁（含複核 `rev5:B-145`）；roleHome 出現 UI 消費者。
- 款 8：決定改走治理清單真分頁、或頂層列數使全取回應成本不可忽略。
