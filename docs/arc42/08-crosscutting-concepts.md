## 8.2 API 慣例

紀律上位＝憲法 §I.3（`Res` 三欄信封、13 碼矩陣整組凍結、id 序列化逐欄位忠實 typings、2^53 fail-loud 守衛）。碼表 as-built＝可發 9（`0000`／`1000`／`2222`／`3333`／`7777`／`8888`／`4040`／`5003`／`5000`，各對應 `AppError` 恰一變體）＋保留 4（`7778`／`8889`／`9998`／`9999`，無變體＝構造層不可發出）＝13；HTTP 例外恰二＝4040→404、5003→403，其餘（含 1000／2222／3333／7777／8888）皆 HTTP 200 信封。`5003`（msg `system.forbidden`）的發出面＝授權拒絕（§8.3）、IP 存取閘阻擋、登入端點的轉發鏈逾限拒絕（後二者＝§6.1 島 F 情境與會話情境①；皆沿用既有碼與鍵、不另立新碼新鍵，逾限拒絕之拍板＝ADR-00037 決定 1），三者同為 `AppError::PermissionDenied`、wire 上不可分辨。auth 三分碼語意（拍板＝ADR-00026 後果段；碼註＝`auth/enforce.rs` `verify_access` 與 `handler/auth/refresh.rs` 檔頭）：`3333`＝**僅**簽章有效而 access `exp` 已過（前端據此走靜默 refresh 後重放原請求）；`8888`＝標頭缺席・非 Bearer 形・簽章不符・已撤銷・refresh 鏈失效（refresh 端點自身任何驗章失敗恆 8888、絕不 3333＝防自動 refresh 死迴圈）；`7777`＝被 single-session 頂替（前端彈 modal、按確認回登入頁）。契約機器化五件：①base-web typings（抽取面＝`tools/wire-schema.py` 之 `TYPINGS_GLOB`，涵蓋 `src/typings/api/` 與 `src/typings/common.d.ts`）＝wire 權威，`tools/wire-schema.py extract` 抽 draft-07 JSON Schema 快照至 `rust-api/server/tests/fixtures/wire-schema.json`（`check` 重抽 byte 比對＝碼面閘、名冊＝RUNBOOK §12 碼面閘表）；②`rust-api/server/tests/wire_schema.rs` 以快照裁判兩面——讀端 DTO 的序列化輸出，與寫端請求型的快照側判準（required 集合恰等／逐欄型別／`$ref` 真解析到封閉值域）及其反序列化落點（`Api.SystemManage.UpdateSystemSettingReq` 為三態〔有值／null／缺席各落不同 rust 值〕、`Api.IpRule` 三支寫端請求型為兩態〔null 與缺席同落 `None`〕）；清單 query `Api.IpRule.IpRuleListQuery` 另走查詢串**真路徑**（`FromRequestParts` 內包 `axum::extract::Query`＋`serde_urlencoded`，非 JSON body 那條 deserializer）錨其落點與壞形整串收斂；③`rust-api/server/tests/contract.rs`＝case registry×`ROUTES` 雙向覆蓋閘（缺 case 指名 route、殭屍 case 指名 case_key）＋fallback 兩案（未註冊路徑／方法不符皆 HTTP 404＋4040、標頭鍵集全等零存在性洩漏）；④route 真表 `docs/generated/reference/routes.md` 由 generate 自 `ROUTES` 重算；⑤`rust-api/server/tests/wire_i64_guard_lint.rs`＝全樹靜態掃描，釘住每個 `derive(Serialize)` 型的 `i64`／`Option<i64>` 欄都掛了 2^53 守衛 serializer、走 string 形、明示不序列化、或列於具名豁免名冊——①～④皆看不見「守衛有沒有掛上」（拆掉 `serialize_with` 後 serde 照發 JSON number、快照逐位相同、裁判案照綠），該盲區由本件承擔（ADR-00040 款 6、BL-00092）。

13 碼矩陣整組凍結的機器承載住 `rust-api/server/src/error.rs`——`code` 常量 mod 與同檔 `#[cfg(test)]` 之 table-driven 矩陣逐列同序同值斷言（碼×msg key×HTTP 對映、表長恰 13）；保留碼零發出另有雙錨＝`AppError` 無對應變體之全變體窮舉見證（cargo 型別層）＋同一矩陣斷言，`tests/contract.rs` 不重寫第三份。

部分更新三態（欄缺席＝不動／JSON null＝清空／有值＝設值）＝ADR-00015，後端承載＝`Option<Option<String>>`＋`tristate` 反序列化、body 取用失敗一律 2222 信封。

msg 名冊後端側閉環＝`rust-api/server/src/error.rs` 之 `MSG_KEYS` 單一常數陣列（鍵數以該陣列型別長度為準、本文不抄；發出點一律取同檔 `msg_key` 常數形、不直書字面）＋contract 雙向斷言（實發 ⊆ 名冊、名冊每鍵 ≥1 發出點）；跨端閘＝`tools/msg-key-gate.py`（現行依據＝ADR-00039：閘形制續行 ADR-00029 之原意；譯文之家＝三檔 locale 各自的 `backend` 子樹、各為該語譯文的唯一權威、不另立譯文表，鍵數一律以 `MSG_KEYS`／閘輸出為準、文件與碼註不手抄）：`MSG_KEYS` ⇔ base-web `src/locales/langs/{en-us,zh-cn,zh-tw}.ts` 各自 `backend: {` 子樹逐檔雙向全等（子樹為封閉集、無白名單；ADR-00017「雙向必恆紅」指整本字典、不指子樹）＋Biz 構造點守衛（字面形或 `msg_key::NAME` 常數形、動態構造即紅）＋前端 msg 字面消費點名冊（base-web `src/**/*.{ts,vue,tsx}`〔排除 `locales/`〕剝註解後之 wire 字面 ⇔ 工具內 `FRONTEND_MSG_CONSUMERS` 逐項雙向全等且每鍵 ∈ `MSG_KEYS`；安全前綴＝`MSG_KEYS` 頂層前綴 − locale 頂層鍵、程式現算；不等 rc 1 指名檔:行、掃描面空 rc 2）；接線＝pre-commit msg-key-gate 段、名冊＝RUNBOOK §12 碼面閘表。

## 8.3 授權慣例

紀律上位＝憲法 §I.2（menu 權限 casbin enforce、DB-first 寫入、寫後全量重載）。判定單點＝`rust-api/server/src/auth/enforce.rs` 之 `enforce_role_path_method`（全服務唯一判定進入點；每次判定記 `casbin_enforce_total{decision}`、取值恰三 allow／deny／error）；每請求 DB-fresh＝`require_policy` 經 facade `roles_of_user` 現查角色（兩道濾網＝未軟刪且 `status = 1`；不快取、不採信 token 帶的角色）；驗證器 `enforce_mw`＝真驗章單一段碼（`rust-api/server/src/auth/enforce.rs`；★debug 與 release 走同一段碼——002 刀那支 `cfg(debug_assertions)` 圈界的查表驗證器 `dev_identity.rs` 已整檔汰換、`cfg` 分岔一併收掉，任何建置下唯一能過驗章的就是以 `AppState.jwt` 秘鑰簽出的真 token、release 二進位據此可跑；掛法＝`from_fn_with_state`、Authed／Policy 兩子 router 整體套用、Public 不掛）：自 `Authorization` 取 Bearer→`jwt::verify_access`（access 秘鑰、HS256、`leeway=0`、驗 iss／aud；驗章錯誤型原樣上浮）→本檔收斂三分碼（僅簽章有效而 `exp` 過期→3333；標頭缺席・非 Bearer 形・簽章不符・亂碼・iss／aud 不符→8888；已撤銷 8888 與被踢 7777 由下一段 denylist 決定、不在驗章）→denylist 四級降級（權威碼註＝`enforce_mw` fn doc；每級方向皆拍板＝憲法 §I.7 島 C、翻轉屬 MAJOR）：①redis 答得出且**命中**→依 reason 二向：`kicked`→7777 modal、其餘（`revoked`、未知字面、空字串）→8888 靜默（萬用臂落 8888＝刻意保守側），計 `denylist_hit_total{source="redis"}`；②答得出且 **nil**→權威語意「未撤」放行；③**答不出**（連線 `Err`）→fail-closed 改問 PG 權威源 `sys_token::has_active_in_chain`，鏈上無 active→8888（reason 已不可得、kicked 與 revoked 同碼＝降級同碼非語意互換），入分支即計 `{source="pg"}`；④PG 亦 `DbErr`→`unwrap_or(false)` 視為無 active→8888、絕不盲放；②③分野全靠 `cache` 模組 nil↔Err 的回值型別分流→放行後 best-effort 推進 `session:{sid}:last_activity`（TTL＝refresh 全壽命）→注入 `Identity{uid, user_name: ""}`（帳號名以 uid 經 `sys_user` facade 現查＝已知態）。降級雙軌可觀測：軌道②＝上列 `denylist_hit_total{source}` 二值（redis／pg）；軌道①＝第 3、4 級各發一筆結構化事件（`target: "security.session"`、`degraded` 欄＝`denylist_read`／`denylist_pg_fallback`、指名 sid；token 本體絕不落 log）。拒絕語意四條＝ADR-00014：無權＝5003＋HTTP 403＋msg 純 key `system.forbidden`；未認證＝8888（HTTP 200 信封、`auth.session.reLogin`）；政策求值失敗＝5000（先落 log、不偽裝成無權）；不揭露政策明細與角色集。no-escalation 掛點＝`no_escalation_check`（空掛點；簽章預留 async 與 DB 句柄、`enforce_role_path_method` 為唯一呼叫點；ADR-00014）；no-escalation 本體、三維授權治理與回收桶＝憲法 §I.7 島 G／I 承襲指針。
