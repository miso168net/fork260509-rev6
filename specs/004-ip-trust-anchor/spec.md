## Clarifications

### Session 2026-09-15

- Q: 既有會話的來源被新建立的阻擋規則命中後，系統要只擋住後續請求、還是同時撤銷該來源的活躍會話？ → A: 只擋請求、不撤會話（承 rev5 形）：阻擋只作用於請求層，會話與 token 不動、不寫 denylist；規則解除後該來源無需重新登入即恢復（FR-024、US2 場景 8）。
- Q: 超管對「其實沒被鎖定」的帳號或來源執行解鎖時，系統要不要照樣寫一列操作稽核並寫解鎖標記？ → A: 不查鎖態、一律寫稽核列＋解鎖標記（承 rev5 形）：解鎖＝「自此刻重新計數」的冪等動作，回 `0000`；副作用＝尚未達門檻的失敗計數自此不計（FR-041、US5 場景 5、SC-009）。
- Q: 管理頁與 rev5 同頁（22080）對照時，「無實質差異」要用什麼判準驗收？ → A: 結構清單逐項全等才綠（表格欄位集合與列序／搜尋器項目／按鈕集合與權限顯隱／抽屜欄位與校驗訊息／分頁／回收桶流程／toast 文案）；截圖之間距／字體／顏色差異只記入走查紀錄、不擋收刀（SC-010、US3 Independent Test、FR-070）。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 稽核紀錄記下真實來源與來源信心 (Priority: P1)

稽核者翻閱登入與會話紀錄時，看到的來源位址是**真實使用者的位址**、而非最近一跳代理的位址；每一列都標明該位址是怎麼判定出來的（直連觀察／CDN 背書／轉發鏈推導／回退／
「鏈過長未被推理」），使「這筆紀錄能不能當證據」成為可讀的事實。攻擊者即使偽造轉發標頭，也無法讓系統把別人的位址記成自己的來源、或把自己的位址藏起來；同一個會話在登入紀錄與
會話事件（登出、換發重放）上記下的來源一致。

**Why this priority**: 這是整個 IP 域的地基——存取閘擋誰、節流鎖誰、稽核記誰，全部取決於這一步還原出的位址。它單獨交付即有價值（稽核真實性立即提升），且下游四個故事都以它為前提。

**Independent Test**: 直接對後端注入各種「傳輸層對端×轉發鏈×信任設定」組合，斷言還原出的位址與來源信心逐案正確；實際登入、換發、登出後查三張稽核面的來源欄如實落庫且彼此一致；
對登入端點送超長轉發鏈，斷言被拒且仍留下一列帶「鏈過長」標記的稽核。

**Acceptance Scenarios**:

1. **Given** 信任模型未宣告任何可信轉發層（設定缺席或全空），**When** 使用者登入，**Then** 真實來源＝傳輸層對端位址、來源信心＝`direct`，轉發標頭一概不採信。
2. **Given** 信任模型已宣告某 CDN 網段且請求經該 CDN 進來，**When** 使用者登入，**Then** 真實來源＝CDN 標示的訪客位址、來源信心＝`cdn_anchored`（另帶邊緣驗證標記且四前置全中時升 `cdn_verified`）。
3. **Given** 攻擊者繞過 CDN 直連、在轉發鏈裡偽造一段公開可查的 CDN 邊緣位址當錨，**When** 請求進來，**Then** 錨**不成立**（錨右側存在不受信任的一跳）、判定退下一層解出**攻擊者自己的位址**、
   來源信心＝`proxy_clean`——偽造的來源位址完全落空，存取閘與節流照常對其生效。
4. **Given** 轉發鏈帶 IPv4-mapped IPv6 形位址，**When** 還原完成，**Then** 存取判定／節流計數／稽核落列拿到同一個正規化形，不分裂成兩個身分。
5. **Given** 信任模型設定檔存在但內容整體損壞，**When** 服務啟動，**Then** 服務照常啟動並發出降級告警、信任集合退為全空（等同全直連）——**不擴大**信任、不當機。
6. **Given** 信任模型某一集合寫了 IPv4-mapped 網段字面（如 `::ffff:10.0.0.0/104`），**When** 服務啟動，**Then** 發出指名該集合與壞字面並附改寫建議的結構化告警、**清空該集合**、其餘集合照常
   （該類網段在判定側永遠比不中，保留等於設定看似生效、實際失效）。
7. **Given** 開發環境已掛載最小信任模型（反向代理容器網段列入內網預設集），**When** 走查者經反向代理發出帶構造轉發標頭的請求，**Then** 系統依轉發鏈推導真實來源、來源信心＝`proxy_clean`
   ——開發環境得以模擬任意公網來源，阻擋、來源維計數隔離與防自鎖三者自此端到端可驗。
8. **Given** 轉發鏈跳數超過推理上界，**When** 該請求打**登入端點**，**Then** 在密碼驗證與節流判定之前拒絕（`5003`／`system.forbidden`／HTTP 403），仍落一列稽核（來源信心＝`chain_rejected`）；
   該列**不計入**帳號維失敗計數、**計入**來源維計數；**When** 同形請求打其他端點，**Then** 照常服務、請求上下文標記 `chain_rejected`。
9. **Given** 同一使用者完成登入、換發、登出，**When** 查登入稽核列與會話事件列，**Then** 兩者記下的來源位址皆為信任錨推導結果（非各自讀取不同標頭）。

### User Story 2 - 超管以 IP 規則阻擋或放行特定來源 (Priority: P2)

超級管理員可以宣告「這些來源一律擋下」與「這些來源一律放行」，規則一存檔就立刻生效、不需要重啟服務。放行永遠贏過阻擋；本機與內網等基礎設施網段永遠不會被規則擋在門外。
規則資料庫暫時讀不到時，判定面沿用上一份已知良好的規則，而不是清空成無防護。被擋下的來源在瀏覽器上看到的是介面語言的人話提示，而非英文原始錯誤字串。

**Why this priority**: 這是 IP 域對外可見的第一個防護能力；它必須建立在 US1 還原出的正確位址之上（擋錯位址比不擋更糟），故排在 P1 之後。

**Independent Test**: 建立阻擋規則後以該來源請求斷言被拒；建立同來源的放行規則後再試斷言放行；對本機位址建阻擋規則斷言仍放行；令規則來源暫不可讀斷言沿用前一份規則；
以構造來源在瀏覽器觸發阻擋、斷言提示為譯文。

**Acceptance Scenarios**:

1. **Given** 對某網段建立阻擋規則，**When** 該網段的請求進來，**Then** 回權限不足類回應（`5003`／HTTP 403），並留下一筆帶命中網段的可查紀錄。
2. **Given** 同一網段同時存在放行與阻擋規則，**When** 該網段請求進來，**Then** **放行**（與規則建立先後無關——規則是集合、沒有優先序）。
3. **Given** 對本機／內網網段建立阻擋規則，**When** 該來源請求進來，**Then** 仍然放行（結構豁免；★只豁免「阻擋」、**不**豁免來源維節流）。
4. **Given** 服務正在運行且已有規則生效，**When** 超管新增／修改／刪除／復原任一規則，**Then** 判定面無需重啟即更新，後續請求依新規則判定（多副本經通知管道收斂）。
5. **Given** 兩袋規則皆未命中，**When** 請求進來，**Then** 放行（預設放行）。
6. **Given** 健康檢查與觀測端點，**When** 任何來源請求，**Then** 一律不受 IP 規則影響。
7. **Given** 某來源被阻擋規則命中且使用者以瀏覽器操作（含登入頁），**When** 前端收到 HTTP 403 信封，**Then** 提示為 `system.forbidden` 在當前語系的譯文；
   無信封的錯誤（斷線／逾時／非 JSON）維持原始訊息。
8. **Given** 使用者已登入且其來源隨後被新建立的阻擋規則命中，**When** 其後續操作，**Then** 每個 API 呼叫得 403、但會話與 token **不被撤銷**（畫面仍為登入態、不觸發被踢流程）；**When** 該規則被刪除或改為放行，**Then** 該使用者**不必重新登入**即恢復。

### User Story 3 - 超管在管理頁維護 IP 規則 (Priority: P2)

超級管理員從側邊欄進入「IP 規則管理」頁，看得到規則清單（含類型、網段、備註與建檔／異動軌跡，操作者以帳號名呈現），可依網段模糊搜尋、依類型與是否已刪篩選，並以抽屜表單新增與編輯；
刪除為可復原的軟刪、回收桶內可一鍵復原。**若一條規則會把操作者自己鎖在門外，系統當場拒絕寫入並說明原因**。

**Why this priority**: 沒有這一層，US2 的五支端點是零消費者的斷頭交付，且「防自鎖」這個 fail-closed 例外無法在真實操作流程中驗證（brainstorm Q1）。與 US2 同級。

**Independent Test**: 以超管身分在瀏覽器完成「列表→搜尋→新增→編輯→軟刪→回收桶復原」全程並與前代同頁（22080）依 SC-010 之結構清單逐項對照（視覺差異只記不擋）；另以「建立一條涵蓋自己來源的阻擋規則」驗證當場被拒。

**Acceptance Scenarios**:

1. **Given** 超管已登入，**When** 開啟側邊欄的「IP 規則管理」，**Then** 頁面正常載入（此前該選單點擊得 404、展開態標題顯裸鍵＝已知態自此解除）並顯示規則清單與操作按鈕；側邊欄標題顯譯文。
2. **Given** 清單有多筆規則，**When** 以網段片段搜尋、以類型或刪除狀態篩選，**Then** 結果正確且分頁資訊一致；每列之建檔／異動者顯示帳號名（查無者為空）。
3. **Given** 新增表單填入帶主機位元的網段（例 `203.0.113.7/24`），**When** 送出，**Then** 落庫為正規化網段（`203.0.113.0/24`）。
4. **Given** 已存在某網段＋類型的有效規則，**When** 再建一筆完全相同者，**Then** 以業務錯誤拒絕並提示衝突（非伺服器錯誤）。
5. **Given** 操作者當前真實來源落在某網段，**When** 嘗試建立涵蓋該網段的阻擋規則（或刪除使自己失去放行的規則），**Then** **拒絕寫入**並說明「此規則會使你自己無法連線」、規則列與稽核列皆零寫入。
6. **Given** 一筆已軟刪的規則，**When** 於回收桶按復原，**Then** 規則回到有效狀態並即時生效。
7. **Given** 規則備註欄填入含 HTML 標記的文字，**When** 清單渲染該欄，**Then** 顯示為純文字原文。
8. **Given** 使用者無新增按鈕權限碼，**When** 開啟該頁，**Then** 表頭不出現任何新增或批次刪除入口（含共用表頭元件自帶之備援按鈕）。

### User Story 4 - 來源維登入節流生效＋節流判定每次由資料庫定案 (Priority: P3)

同一個來源在短時間內大量嘗試登入（即使每次換不同帳號名）時，系統先要求圖形驗證碼、再鎖定該來源至時間窗滑過為止；此判定與既有的「同一帳號連續失敗」判定**並行**，任一方觸發即生效。
系統設定中兩組節流參數**每次登入嘗試都讀現值**：超管放寬門檻後，被鎖者下一次嘗試立即依新值判定；設定未變時，時間窗一滑過即解鎖、不多擋。設定值缺失、壞值、越界或互相矛盾時，
該組整組退回預設常數並發告警，而不是鎖死全站或讓節流失效。

**Why this priority**: 補上「輪換帳號名」這個帳號維擋不住的攻擊面，並兌現憲法跨島總則「節流三鍵於每次登入嘗試讀現值」（BL-00066）；依賴 US1 的位址還原，故排 P3。

**Independent Test**: 以同一構造來源輪換帳號名連續失敗登入，斷言軟門檻要求驗證碼、硬門檻鎖定；穿插一次成功登入斷言來源計數不重置；鎖定後放寬門檻斷言下一次即依新值；
把門檻寫成越界或矛盾值斷言整組退常數且告警遞增。

**Acceptance Scenarios**:

1. **Given** 某來源在時間窗內失敗次數達軟門檻，**When** 再次嘗試登入（即使帳號名從未失敗過），**Then** 要求圖形驗證碼。
2. **Given** 某來源在時間窗內失敗次數達硬門檻，**When** 再次嘗試登入，**Then** 拒絕並提示鎖定；拒絕發生在密碼驗證**之前**，且**不留稽核列、不消耗計數**。
3. **Given** 某來源已累積失敗次數，**When** 攻擊者以一組有效帳密穿插一次成功登入，**Then** 該來源的失敗計數**不重置**（帳號維成功即重置是正確的、移植到來源維即破口）。
4. **Given** 帳號維與來源維同時判定，**When** 任一維硬鎖，**Then** 結果為鎖定；皆未鎖定但任一維進入軟區，**Then** 要求驗證碼；否則放行。
5. **Given** 某來源命中**顯式放行規則**，**When** 該來源嘗試登入，**Then** 跳過來源維節流；**Given** 某來源只是落在結構豁免網段，**Then** **不**跳過。
6. **Given** 使用者以 IPv6 位址請求，**When** 計數，**Then** 以 `/64` 聚合前綴計桶；IPv4 以單一位址計桶。
7. **Given** 帳號 `User` 已因 5 次失敗被鎖（門檻 5／窗 15 分），**When** 超管把帳號維硬門檻放寬為 10、`User` 再試，**Then** 該次即依新門檻判定（計數 5＜10、進軟區要求驗證碼），不再被舊鎖擋。
8. **Given** 設定不變、失敗列落在 t=0,1,2,3,14 分，**When** t=15 分之後再試，**Then** 最早一筆出窗、計數 4＜5 ⇒ 不再鎖定（無額外鎖期）。

### User Story 5 - 超管手動解鎖被鎖的帳號或來源 (Priority: P3)

當某個帳號或某個來源被節流鎖定，超級管理員可以立即解除，不必等待時間窗滑過；解除動作本身留下稽核紀錄，且**稽核先於生效**。本刀提供 API 端點、不提供 UI 按鈕（按鈕的家在使用者管理頁）。

**Why this priority**: 補上帳號維「有鎖無解」的缺口，並讓來源維鎖定（含開發環境走查誤觸）在誤傷時有自癒手段（brainstorm Q2）。

**Acceptance Scenarios**:

1. **Given** 某帳號已被鎖定，**When** 超管對該帳號解鎖，**Then** 該帳號立即可再次嘗試登入。

### Edge Cases

**信任錨**

- 轉發鏈長度超過上限（極長鏈或洪泛）→ 只保留**最右側**固定數量的段（真實來源在鏈的右端；方向寫反即開出「以左端洪泛把真實位址擠出視窗」的攻擊面）；**登入端點**另依 FR-016 拒絕。
- 轉發鏈含無法解析為位址的段 → **丟棄該段**（＝該跳不存在），鏈的相對次序不變、判定不塌陷；帶連接埠、IPv6 區域識別或方括號包裹的合法寫法先正規化再解析。
- CDN 位置錨成立但錨左側找不到非 CDN 段 → 錨不適用、退回退態（`fallback`）。
- 帶邊緣驗證標記但傳輸層對端不在「掛驗證閘的我方出口集」內 → **不得**升等；標記為真但推導結果與訪客標頭不一致 → 降為 `cdn_mismatch`，**只動信心、不動位址**。
- 信任模型設定檔缺席 → 沿用扁平環境變數退路；存在但整體損壞 → 全空（★**不**套用退路）；單一集合含無效網段或 IPv4-mapped 網段字面 → 只清空該集合。
- 請求上下文缺席（直打後端、未經 make-service 植入傳輸層對端之測試形）→ 閘門放行、來源維整層跳過；IP 規則寫端與解鎖端點拒寫（`5000`）；登入／換發／登出退回標頭轉錄途徑
  （缺 `X-Real-IP`→`5000`；在場→轉錄、來源信心 `fallback`、對端欄空、判定窗空）並發降級告警（FR-013）。
- 稽核轉錄欄的複驗性帶兩個成立條件（真實來源由鏈推導、判定窗未逾字元上限）——不得宣稱為無條件保證（FR-015）。

**存取閘**

- 規則來源在服務啟動時讀不到 → 空集合放行；運行中暫時讀不到 → **沿用上一份已知良好規則**、不清空。
- 熱重載通知管道故障（發佈或訂閱）→ 本機已生效者照常、跨副本待重連後補讀收斂、放行方向並告警；訂閱連線建立有逾時上限、斷線指數退避、重連（含首次）後補讀一次。
- 規則表被以非正常途徑塞入未知類型的列 → 該列略過並告警，不使整份規則集失效。
- 既有會話的來源被新阻擋規則命中 → 後續請求 403、會話與 token 不動（不寫 denylist、不觸發被踢）；規則解除即恢復、免重新登入（Clarifications Q1）。
- 健康／觀測端點恆不受規則影響。

**規則管理**

- 同網段＋同類型且皆有效 → 唯一性衝突、業務錯誤；舊列已軟刪 → 可建立新列。
- 網段字面帶主機位元 → 落庫前正規化；字面不可解析 → 寫前拒、零寫入。
- 對不存在或狀態不符的規則執行更新／刪除／復原 → 業務錯誤；復原後與現有有效列衝突 → 業務錯誤。
- 操作者真實來源落在結構豁免網段 → 豁免段本就擋不住，不判為自鎖；操作者來源位址取不到 → 拒寫（`5000`）、不以佔位位址補稽核列。

**節流與解鎖**

- 快取整體不可用（或解鎖標記讀取故障）→ 視為無解鎖標記（可能仍在鎖定中）、該次軟區驗證碼要求整層停用、續驗密碼、密碼錯仍計數。
- 單次驗證碼消耗標記寫入瞬斷（快取健康）→ 拒但不罰（既有島 E）。
- 對未被鎖定的標的解鎖 → 不先查鎖態、照寫稽核列與標記、回 `0000`（Clarifications Q2）。
- 失敗計數查詢失敗（任一維）→ 計數視為 0 放行、快取健康時強制要求驗證碼（既有島 E 補償）；原本已鎖的帳號在此部分故障窗內改為要求驗證碼而非直接鎖定（Q7 已知可見差異）。
- 資料庫整體故障 → 驗證帳號即失敗、回 `5000`；無論節流如何皆無法登入。
- 兩組設定越界或矛盾 → 各自整組退常數＋獨立告警；帳號維與來源維互不牽連。
- 開發環境走查未帶構造轉發標頭 → 所有瀏覽器流量收斂為同一來源桶（`fallback` 態、位址落結構豁免段）＝易誤觸來源鎖、以解鎖端點自癒；該位址擋不到 ⇒ 阻擋與 403 轉譯之瀏覽器驗收 MUST 以構造標頭模擬公網來源、位址落在結構豁免段之外。
- nginx 邊緣層 `auth_limit`（每來源 5r/s、burst 40、`429` 無信封）先於後端生效；走查勿秒內狂打；contract test 走 oneshot 不經 nginx。

**管理頁與前端**

- 備註欄含標記字元 → 純文字呈現。
- 使用者無對應按鈕權限碼 → 該操作入口不呈現；表頭插槽不得因「內容只剩註解節點」而退回渲染共用元件的備援新增／批刪按鈕。
- 前端收到非業務碼分支的 HTTP 錯誤（403／404）且回應帶信封 msg → 轉譯；未命中鍵以原文回退；無信封 → axios 原文。
- demo 頁 `/auth/error`（4040）之 toast 同步變為譯文；demo 頁本身去留不在本刀。

**測試基建與走查**

- dev 庫有 CDP／手動真登入殘列時跑全量 → 不得連坐；各案只清自己寫的列、runtime-append 表序列不復位。
- `sys_ip_rule` 為業務表（gate2 逐列比對、序列值精確比對）→ 測試與走查寫入須清列並還原序列；稽核列以 `entity_id` 對應規則 id ⇒ 稽核斷言一律以水位／窗形寫、不寫絕對計數（否則序列復位後 id 重用、走查孤兒稽核列誤紅）。
- 既有 oneshot 形測試不經 make-service ⇒ 上下文恆缺席、走 FR-013 退路；既有 `X-Real-IP` 注入案（36 處）零改形。
- 走查工具 restore 對非空基準仍拒跑（安全帶）；seed 基準模式不依賴基準檔、以凍結 seed 為目標態。
- CDP 走查以瀏覽器網路層 extra header 構造 `X-Forwarded-For`（既有 CDP 工具具通用命令通道、零工具改動）；對照 22080 時逐項剔除前代後刀改動造成之差異。
- rev5 側唯讀：一切讀取對凍結 worktree、不寫入、不動其 stack；走查工具只准指向 rev6 dev stack（3xxxx）。

**信任錨——真實來源還原（US1）**

- **FR-003**: 真實來源位址與來源信心的**政策判定 MUST 只存在於單一純函式**；請求層只負責抽取標頭與傳輸層對端、呼叫該函式、組成請求上下文，零內聯重複判定；
  下游（存取閘、來源維計數、稽核落列、防自鎖）一律消費同一結果（憲法島 F 之 F4）。
- **FR-004**: 還原 MUST 依固定三層序：①**對端閘**——傳輸層對端不屬受信集即直取對端、忽略轉發鏈、`direct`；②**Tier-1 CDN 位置錨**——以鏈中**最右側**的 CDN 段為錨、取其左鄰第一個非 CDN 段、
  `cdn_anchored`；錨左無非 CDN 段 → `fallback`；③**Tier-2 最右非受信**——由右往左跳過受信集，第一個不屬者即真實來源（`proxy_clean`；經 dual-role 公開出口或綁定內網不符 → `proxy_soft`）；整鏈受信 → `fallback`。
- **FR-005**: **Tier-1 錨 MUST 附傳輸層背書**（F6）：錨右鄰起、直到傳輸層對端的每一段皆屬受信基建，否則錨不成立、退 Tier-2；受信判定 MUST 與 Tier-2 跳過集由**同一 helper** 導出（不得另立第三集合）。
  合法 CDN 路徑下結論與無硬化時逐位元相同（零誤傷）。
- **FR-006**: 兩層覆蓋 MUST 依前代已驗證形：①**通道回退**——基礎為 `fallback` 且對端屬通道來源集時採信通道訪客標頭、**信心不升**；②**邊緣驗證升等**——四前置全中（對端屬掛驗證閘的我方出口集／
  驗證標記為真／訪客標頭有值／基礎信心屬可升等集）升 `cdn_verified`，推導不一致降 `cdn_mismatch`；兩者**只動信心、不動位址**。
- **FR-007**: 來源信心 MUST 為八態小寫底線字面：`cdn_verified`／`proxy_clean`／`direct`／`cdn_anchored`／`proxy_soft`／`cdn_mismatch`／`fallback`／`chain_rejected`；
  全八態 MUST 經同一字面出口產出（全 repo 無其他路徑寫出值域外字面）。前一刀的單一字面 `nginx_peer` 退役；append-only 稽核表之既有列**不遷移**、查詢端容忍新舊並存。
  文件面寫態名一律以反引號碼識別字並冠「來源信心態」，與活書既有流程層術語「fallback（降級輪廓實採行為）」區分、兩詞不互用（brainstorm 工程判斷 11）。
- **FR-008**: 還原結果 MUST 於注入請求上下文**之前**正規化（IPv4-mapped 折為 v4），存取判定／來源維計數／稽核落列／防自鎖全下游同一形。
- **FR-009**: 轉發鏈正規化 MUST 固定兩步：①**右端取窗**（由右往左至多固定數量非空欄、丟棄左端溢出；取窗先於解析）②**逐欄正規化**（剝連接埠、區域識別、方括號）後仍不可解析者**丟棄**、永不當機；
  丟棄語意＝「該跳不存在」。「丟欄／遇壞中止整鏈／保留為佔位跳」三種語意 MUST 有區辨性測試。
- **FR-010**: 信任模型 MUST 於啟動時一次載入、之後唯讀共享；預設全空＝全直連。失敗語意三層、一律不當機且必發結構化告警：設定檔缺席→沿用扁平環境變數退路／整體損壞→**全空**（不套退路）／
  單一集合含無效網段→**只清空該集合**。開發環境最小設定（僅容器網段入內網預設集）與其 compose 掛載既已在位，本刀 MUST 使之成為真實消費面並作為部署樣例之活體。
- **FR-011**: 信任模型任一集合含 IPv4-mapped 網段字面時，載入面 MUST 發結構化告警（指名集合、壞字面、改寫建議）並**清空該集合**（與 FR-010 第三層同形、只縮小信任；`rev5:B-074`）；
  判別 MUST 取位址本身而非遮罩後網段（遮罩會抹掉映射前綴）、且只認 IPv4-mapped 形不誤清 IPv4-compatible 以外的合法集合。
- **FR-012**: 請求上下文 MUST 維持既有三欄與取值器簽名、欄位私有與其編譯期守門不變：`real_ip` 改為信任錨推導之正規化字串、`ip_confidence` 值域改八態、轉發鏈欄改為**判定窗**轉錄（FR-015）；
  handler 改由請求層注入取得上下文、絕不自讀轉發標頭；稽核表既有的**對端位址欄** MUST 開始寫入傳輸層對端。模組頭「三欄與消費面不動」之預告於落地時回填為現況。
- **FR-013**: 請求上下文缺席時 MUST 分腿處置（brainstorm §5 ① 定案、承 `rev5:004` T048 形）：存取閘放行、來源維節流整層跳過（fail-open、＝島 F F1②／F5 字面）；IP 規則四寫端與解鎖端點拒寫回 `5000`
  （F3① 輸入不可得同向）；login／refresh／logout 以**可缺席**形取上下文、缺席即退回既有標頭轉錄途徑——缺 `X-Real-IP` 仍依 003 形回 `5000` 不落列、在場則轉錄（來源信心 `fallback`、對端欄空、判定窗空）
  ——並發一筆降級告警＋降級計數。此腿於 production 結構性不可達（FR-014 保證恆有上下文）、實為「備線被拆」之偵測腿；既有 `X-Real-IP` 注入之 oneshot 測試（36 處）MUST 零改形。
- **FR-014**: MUST 以一支測試 lint 守住「`main.rs` 之服務啟動呼叫以帶傳輸層對端的 make-service 形起服務」（`rev5:B-075`）：判別取啟動呼叫的實參、不受鏈式優雅關閉呼叫影響；
  裸呼形與格式化折行形皆有反例格；拔除該接線即紅。
- **FR-015**: 稽核列的轉發鏈欄 MUST 轉錄**判定窗**（最右固定欄數、再以字元上限兜底），且 MUST 與判定軌**共用同一份切分實作**（F8）；複驗性 MUST 載明兩個成立條件：
  (a) 真實來源由鏈推導 (b) 窗未逾字元上限——不得寫成無條件保證。
- **FR-016**: 轉發鏈跳數逾推理上界者 MUST **於登入端點**在密碼驗證與節流判定**之前**拒絕（`5003`／`system.forbidden`／HTTP 403、零新碼零新鍵）；**其餘端點 MUST 標記**（`chain_rejected`）
  **但照常服務**（F7；標記全域、拒絕限登入）。判準取現行取窗上界本身、不另立門檻常數。
- **FR-017**: 鏈超長拒絕時 MUST **仍落一列登入稽核**（來源信心 `chain_rejected`）；該列 MUST 被**帳號維計數排除**、被**來源維計數納入**；來源維「刻意不加過濾」MUST 有一支釘住測試。
- **FR-018**: 鏈超長拒絕 MUST NOT 新增降級序列、MUST NOT 進降級矩陣（拒絕是明確處置）；可觀測面＝結構化告警＋稽核列。

**IP 存取閘（US2）**

- **FR-019**: 閘門判定 MUST 依固定六步序：①健康／觀測端點放行 ②請求上下文缺席放行 ③結構豁免網段放行 ④命中放行規則放行 ⑤命中阻擋規則拒絕 ⑥其餘放行。
- **FR-020**: 規則集 MUST 為 any-match 集合語意——白＞黑＞預設放行、無優先序欄、判定與載入順序無關。
- **FR-021**: 結構豁免 MUST 恰為本機與私有網段六段（v4 loopback／RFC1918 三段、v6 loopback／ULA），且**只豁免阻擋、不豁免來源維節流**（F5）。
- **FR-022**: 真相分層 MUST 為「資料庫規則表＝真相、記憶體判定面＝每請求零外部查詢」；執行中真相暫不可讀 MUST **沿用上一份已知良好規則集**；啟動初載失敗 → 空集放行（F2）。
- **FR-023**: 規則變更 MUST 無需重啟即生效：寫端成功寫入後重載並發佈失效通知；讀端以**專用訂閱連線**接收並換版（共用多工連線不可用於訂閱）；訂閱建立有逾時上限、斷線指數退避、
  重連（含首次訂閱成功）後補讀一次；通知管道故障 MUST 走放行方向並告警。
- **FR-024**: 阻擋回應 MUST 復用權限不足碼（`5003`／HTTP 403）、**不新增碼**；每次阻擋 MUST 留下帶命中網段之結構化可觀測紀錄（非降級序列）。
  阻擋 MUST 只作用於請求層：MUST NOT 撤銷該來源既有會話或 token、MUST NOT 寫 denylist（島 C 機制零觸碰）；規則解除後該來源 MUST 無需重新登入即恢復（Clarifications Q1、承 rev5 形）。

**IP 規則管理端點（US3 後端）**

- **FR-025**: 清單端點 MUST 支援分頁與三個可空篩選（網段模糊、類型等值、刪除狀態三態 active／deleted／all、缺省 all）、回應為既有分頁形；列資料 MUST 含建檔／異動時間與操作者帳號名
  （查無→空值；操作者名 MUST 以**單次批次讀**回填、不得逐列查詢）與布林 `deleted`；刪除時間與刪除者**不上線上契約**。規則 id 為 number 並掛 2^53 守衛。
- **FR-026**: 新增與更新 MUST 於寫入前守門：①類型二值封閉（allow／deny）→ 否則 `2222 biz.ipRule.invalidRuleType` ②網段解析並**正規化主機位元**後才落庫 → 解析失敗 `2222 biz.ipRule.invalidCidr`；
  皆寫前拒、零寫入。唯一性衝突 MUST 映 `2222 biz.ipRule.conflict`（MUST NOT 為伺服器錯誤）。
- **FR-027**: 刪除為**軟刪**（刪除時間與刪除者成對寫）、復原成對清空；唯一性只約束有效列；標的不存在或狀態不符 → `2222 biz.ipRule.notFound`；復原與現有有效列衝突 → `biz.ipRule.conflict`。
- **FR-028**: **防自鎖**（F3① fail-closed）：四寫端在生效前 MUST 以同一判定純函式模擬「變更後規則集對操作者當前真實來源」的判定（新增＝加入、更新＝移除舊加入新、刪除＝移除、復原＝加入），
  結論為拒絕即拒寫並回 `2222 biz.ipRule.selfLock`（零落庫、零重載）；操作者來源位址取不到 MUST 一併拒寫（`5000`）、不得跳過檢查、不得以佔位位址補足稽核列；結構豁免段不判為自鎖。
- **FR-029**: 規則四寫端 MUST 於**同一交易**內落業務列與一列操作稽核（FR-043）；成功後 MUST 觸發重載與失效通知。

**來源維節流與節流判定面（US4）**

- **FR-030**: 來源維與帳號維 MUST **並列判定、合成**：任一硬鎖 → `2222 biz.auth.locked`；否則任一軟區（或計數降級之強制驗證碼）→ 驗證碼閘；否則放行。兩維拒絕 MUST 共用同一組 msg key、
  不揭露觸發維度；皆於密碼驗證**之前**擋下、零稽核列、零計數桶。帳號維判定為硬鎖時可短路不讀來源維（合成語意不變）。
- **FR-031**: 來源維計數時間窗下界 MUST **恰兩源**（時間窗起點＋該來源解鎖標記），**MUST NOT** 納入「窗內最近成功登入」；帳號維維持三源（窗起點／窗內最近成功／解鎖標記）。
  來源維不重置 MUST 由**負向自證測試**守門（誤加第三源即紅）。
- **FR-032**: 計數桶粒度 MUST 為 v4 逐位址（`/32`）、v6 聚合前綴（`/64`、截斷主機位元）；IPv4-mapped 先折疊；未指定位址（`0.0.0.0`／`::`）→ 無桶、來源維整層跳過。
- **FR-033**: 命中**顯式放行規則**的來源 MUST 跳過來源維節流（直讀放行袋判定、**絕不經**完整閘門判定函式——否則結構豁免段會誤跳節流）；落在結構豁免網段 MUST NOT 跳過（F5）。
- **FR-034**: ★**節流判定面 MUST 每次登入嘗試讀兩組設定現值並以資料庫滑動窗計數定案**（BL-00066、brainstorm Q7）：兩維**皆不設**快取層負快取——刪除鎖定快取鍵族、其存活期計算與上限常數、
  「命中不續期」「存活期隨窗縮短」兩類測試與相應文件敘述；放寬門檻於下一次嘗試即生效；設定未變時最早計入之失敗列出窗即解鎖、無額外鎖期。解鎖端點因此只寫解鎖標記。
- **FR-035**: 兩組節流設定（帳號維 `login_throttle_*`、來源維 `ip_*`）之有效性 MUST 一致：任一鍵缺列、軟刪、不可解析、**超出設定 registry 宣告界值**（沿用既有 registry 宣告、不另抄一份）、
  或矛盾組合（驗證碼門檻＞硬門檻）→ 該組**整組**退活書常數（依「硬門檻／窗分鐘／驗證碼門檻」序：帳號維 `5／15／2`、來源維 `50／15／10`）並發一筆結構化告警（每次載入至多一筆；來源維用獨立標籤）；門檻相等為合法（brainstorm Q4、G4）。
- **FR-036**: 快取可用性 MUST 以**解鎖標記讀取**判定（Q7；brainstorm §5 ② 定案）：節流判定第一步讀兩維解鎖標記，**任一**讀取錯誤（或快取自始缺席）→ 該維視為無標記（fail-closed）＋本次嘗試判定快取不可用
  （軟區驗證碼要求整層停用、續驗密碼、密碼錯仍計數）；來源維因顯式放行或無桶而整層跳過時，只憑帳號維那次讀取判定。
- **FR-037**: 任一維計數查詢失敗 MUST 走既定補償：計數視為 0 放行、快取可用時強制要求驗證碼（且不計入軟區計數）；兩維降級標籤分流。
- **FR-038**: 設定寫端 MUST 維持零改動、不加跨鍵守衛（brainstorm Q4；與 003 clarify Q3 一致）；矛盾值由消費側 FR-035 承載。

**管理員解鎖（US5）**

- **FR-039**: 解鎖端點 MUST 支援兩維擇一（`user`＋帳號名／`ip`＋位址字面、由後端導出計數桶）；維度不明、標的不可解析、該維必填欄缺席 → `2222 biz.throttle.invalidUnlockTarget`，
  且**零稽核列、零狀態變更**（此判定先於一切稽核與狀態寫入）。
- **FR-040**: ★**稽核先於生效**：解鎖 MUST 先寫一列操作稽核、寫入失敗即 `5000` 中止且不寫任何快取狀態；稽核成功後寫該維解鎖標記（值＝unix 秒十進位字串；讀端不可解析視為無標記）。
- **FR-041**: 對未被鎖定的標的解鎖 MUST 回 `0000`（冪等；不以異碼洩漏鎖定狀態）；端點 MUST NOT 先查鎖態、MUST 一律依 FR-040 寫稽核列並寫解鎖標記——
  解鎖之語意＝「該標的自此刻重新計數」，副作用＝尚未達門檻的失敗計數自此不計（Clarifications Q2、承 rev5 形）。
- **FR-042**: 帳號維 MUST 補齊三件（解鎖標記鍵、讀取端、計數標籤）且帳號維計數查詢本體零改動（前一刀已預留參數位）；本刀 **API-only**——不建 UI 按鈕與前端包裝（按鈕碼已在 seed）＝已知態、
  收刀記 BACKLOG。解鎖 MUST NOT 帶前代後刀才加的 no-escalation 守門（BL-00048 射程）。

**稽核與契約**

- **FR-043**: 本刀為操作稽核表的**首個寫入者**：規則四寫端與解鎖 MUST 落列（含操作者、動作、標的表、標的 id、變更前後值、來源三欄）；動作字面 MUST 恰為 `add`／`update`／`delete`／`restore`／`unlock`
  並由單一宣告源產出（前代定案形）；解鎖列之標的表記節流子系統識別、標的 id 為空、變更後值含維度與標的。既有設定寫端**維持不落列**＝稽核覆蓋不對稱已知態（收刀登記）。
- **FR-044**: 契約 MUST 住本刀 `contracts/`（brainstorm G2、§5 ⑩）：新端點契約兩檔（`wire-ip-rule.md`＝規則管理五端點、`wire-throttle-unlock.md`＝解鎖端點）；login／refresh／logout 三端點之**增量列**
  單檔 `wire-auth-delta.md`（檔首明載基底＝003 契約快照）——補齊三表 `5000` 出口（資料庫錯誤／commit 失敗）與請求上下文缺席列（依 FR-013）、login 之鏈超長 `5003` 列、三端點來源位址改取信任錨；既有碼之 wire 行為不變。
  wire 活體權威＝碼＋contract test，不另立文件家（BL-00062「活體契約放哪」之回應）；設定檔契約 `trust-model-config.md` 與治理契約 `code-gates.md` 同住 `contracts/`。
- **FR-045**: logout 之 `5000` 出口 MUST 保留；資料庫故障窗內「簽章有效→5000／無效→0000」之弱 oracle MUST 立 won't-fix 已知態 ADR（brainstorm Q5）。

**可觀測與告警規則**

- **FR-046**: 本刀新增之降級類別 MUST 各有帶結構化欄位的告警與啟動即註冊基線值之序列（類別集合以 data-model 降級矩陣為單一權威）：信任模型載入失敗三層（含集合清空）／規則集載入失敗（初載＋執行中）／
  通知管道故障（發佈、訂閱）／解鎖標記讀取故障（兩維）／請求上下文缺席／來源維設定退常數與矛盾；帳號維降級源名冊 MUST 刪除快取鎖相關兩源、值集單一權威仍住既有名冊常數（新值名於 plan data-model 定）。
  ★阻擋（FR-024）、寫端自鎖（業務錯誤回應）、鏈超長拒絕（FR-018）**不是降級**、不新增降級序列。
- **FR-047**: 告警規則 MUST 刪除永不觸發之 `obs016-throttle-suppressed`（規則塊、其註解、檔頭「告警六組 13 條」數量詞與兩處引用；BL-00078）；`obs016-ipgate-degraded` 之事件錨與查詢欄位 MUST 對齊本刀 as-built；
  其餘錨向後刀模組或指標之規則不動。

**管理頁前端（US3 前端）**

- **FR-048**: MUST 交付 IP 規則管理頁三檔（清單／新增編輯抽屜／搜尋），以**新增檔**形式落地（新增型檔頭標記、免 ★ 授權）；藍本取前代 HEAD 形——含表頭插槽「無權時不得退回渲染共用元件備援按鈕」之修正；
  回收桶復原於頁內完成；備註欄純文字插值。
- **FR-049**: 線上型別以 `rev6-` 前綴**新檔**擴充（ADAPT 軌、入 wire-schema 快照面）、請求包裝以 `rev6-` 前綴**新檔**提供五支（WRAPPER 軌）；解鎖端點**不建**前端包裝。
- **FR-050**: 新頁所需 i18n 鍵落點 MUST 分兩類：①**後端訊息鍵**六支進三檔 locale 之 backend 子樹＋`app.d.ts` backend 型節＝既有 ★I18N-WIRING (ii)(iii) 授權內；②**路由標題鍵與頁面文案鍵**進兩語 runtime locale 之

  無信封（網路中斷、逾時、非 JSON）維持原始訊息；既有「被踢 modal」「token 過期換發」兩判斷面零影響（BL-00077、前代 `rev5:B-117` 形）。

- **SC-002**: 硬化有效性可證——同一組偽造輸入（鏈中填公開 CDN 邊緣位址當錨、其右側為攻擊者位址），硬化前得「CDN 錨＋偽造位址」、硬化後得「攻擊者真實位址＋`proxy_clean`」；
  合法 CDN 路徑之判定結果（位址與信心）硬化前後完全相同。
- **SC-003**: 鏈超長拒絕可證——登入端點逾上界之請求在密碼驗證與節流判定之前被拒（源序守與行為案各一）、恰落一列 `chain_rejected` 稽核、該列不入帳號維計數且入來源維計數（刻意不過濾之釘住測試在案）；
  非登入端點同形請求照常服務且上下文帶標記；ConnectInfo 接線 lint 拔線即紅。
- **SC-004**: 存取閘判定矩陣全綠——六步判定序逐步各一案；白＞黑（含同網段兩類並存）；結構豁免段建阻擋仍放行；兩袋皆空與皆未命中放行；健康／觀測端點不受規則影響。
- **SC-005**: 熱重載與韌性可證——規則寫入後未重啟即生效（連續兩次請求判定反轉）；規則來源不可讀時沿用上一份（先建規則→令來源不可讀→判定仍生效）；啟動期初載失敗放行；通知管道斷線重連後補讀收斂。
- **SC-006**: 防自鎖可證——建立涵蓋自身來源的阻擋規則被當場拒絕且規則列與稽核列皆零寫入；改建不涵蓋自身者成功；操作者來源取不到時拒寫；結構豁免來源不判自鎖。
- **SC-007**: 來源維節流三區正確——同一來源輪換帳號名連續失敗於軟門檻要求驗證碼、於硬門檻鎖定；★負向自證：穿插一次成功登入後來源計數不重置；雙維合成四組合各一案；
  顯式放行規則跳節流、結構豁免段不跳各一案；IPv6 `/64` 聚合與 mapped 折疊各一案。
- **SC-008**: ★節流判定面由資料庫定案可證——鎖定後放寬硬門檻，下一次嘗試即依新值判定（變異自證：改為不讀設定現值即紅）；設定未變時最早失敗列出窗即不再鎖定；越界值（含硬門檻 0）與矛盾組合各使該組整組退常數、
  告警計數遞增且兩維標籤分流、門檻相等合法；src 與現在式文件面無快取鎖定鍵族與其常數殘留（史料面不計）；計數查詢失敗走補償（驗證碼強制、降級計數遞增）；解鎖標記讀取錯誤（任一維）使本次判定快取不可用且鎖定不被誤解。
- **SC-009**: 解鎖端點正確——帳號維與來源維各一案解鎖後立即可再試；參數畸形零稽核零狀態變更；稽核寫入失敗時解鎖不生效；未鎖標的冪等 `0000` 且稽核列與標記照寫（一案）。
- **SC-010**: 管理頁端到端可見——超管於瀏覽器完成「列表→搜尋→新增（帶主機位元網段落庫為正規化形）→編輯→軟刪→回收桶復原」全程；側邊欄標題顯譯文；與前代同頁（22080）對照之判準＝**結構清單逐項全等**
  （表格欄位集合與列序／搜尋器項目／按鈕集合與權限顯隱／抽屜欄位與校驗訊息／分頁／回收桶流程／toast 文案）、任一項不等即紅，截圖之間距／字體／顏色差異只記入走查紀錄、不擋收刀（Clarifications Q3）；
  備註含標記字元顯示為純文字；無新增權限者表頭無任何寫入口；被構造來源擋下時瀏覽器提示為譯文。
- **SC-011**: 契約與碼表自證——路由 16→22、契約覆蓋閘無缺案無殭屍案；六條端點政策保護與 seed 政策列逐條對應；13 碼矩陣可發碼與保留碼數量不變、零新 `AppError` 變體；
  `MSG_KEYS` 19 鍵、三檔 locale backend 子樹逐檔雙向相等且型節齊備；`contracts/` 五檔（規則管理、解鎖、auth 增量、信任模型設定、治理契約）在案且增量檔明載基底。
- **SC-012**: 治理面全綠——憲法 bump 1.4.0（島 F 八條＋島 E 四處＋新軌道＋I18N 三處＋五欄精確化）且 accepted 前 base-web 既有檔零 diff（git 史可證）；新軌道列被名冊載入器讀進（變異自證）；
  路由產物冪等檢查與「軌道列產物集＝實產出集」各以變異證非 vacuous；管理頁零原始 HTML 插值守以植入反例證；boot 接線靜態掃描以合成反例證；告警規則數＝12 且 `ipgate-degraded` 錨對齊；
  msg 譯文權威改寫面（憲法列、ADR、九處註解）零殘留「譯文權威＝凍結契約」與手抄鍵數；三支依賴以 `1.9.2`／`0.3.34`／`1.1.6` 全數字釘版且 lock 既有兩值不變。
- **SC-013**: 測試基建不連坐——dev 庫存在一列真帳號登入殘列時，容器內全量測試全綠；src 與現在式文件面無序列復位守衛殘留（史料面不計）；稽核斷言無絕對計數形；走查工具 seed 基準模式、擴面還原與序列存在性比對各有自測案；
  跑全量前後走查基準 diff rc 0；既有 auth 三端點之 `X-Real-IP` 注入測試（36 案）於缺席退路下零改形全綠。
- **SC-014**: 開發環境端到端可驗性成立——經反向代理帶構造轉發標頭模擬兩個不同公網來源，四項逐一通過：①兩來源各自失敗登入、來源維計數互相隔離 ②對其一建阻擋規則即得阻擋回應、另一來源不受影響
  ③對涵蓋操作者當下來源的範圍建阻擋規則觸發防自鎖拒寫 ④稽核列真實來源與來源信心為推導真值（非反向代理位址、非單一常數）。
- **SC-015**: 交付鏈全綠（FR-070）——後端全量測試容器內 serial 全綠、前端型別檢查綠、fork-delta／wire-schema／msg-key-gate／schema 三閘／entity 漂移閘／兩支新守／lint 全量零紅、release profile 起得動、
  手動端到端走查（入口 `http://127.0.0.1:32080`）全數通過、走查後 diff rc 0。
- **SC-016**（★收刀面子句於簿記 commit 後驗）: 治理帳本結清——ADR 全數 accepted 且 `feature_close.adrs` 列全；`backlog_done` 八條、條文改寫五條、`backlog_add` 兩條與 FR-069 相符；
  NOTES 下一步指 005；活書各節現在式更新且「來源信心」術語條與 AI「信心規格」消歧、來源信心態 `fallback` 與流程層「fallback」消歧皆在案；LL-00017 補述在案。

## Assumptions

- rev5 為本機可達之唯讀參考庫（凍結 SHA 由 bootstrap 斷言）；應用碼全程重打字消化、註解 rev6 語境重寫、前代出處帶 `rev5:`；藍本取前代 HEAD 形並逐檔剔除後刀能力增量
  （解鎖 no-escalation、改密節流、`Identity` 補 sid、存取軌跡 middleware、region GeoIP、HLL 廣度）；翻案四項（快取負快取、來源維逐鍵退與消費側不驗界、譯文權威、序列復位守衛保留設計）與提前帶入一項（HTTP 層信封轉譯）入 plan research 差異點表、烤入 implementer 防回歸清單。
- **零 migration、零 seed 變更＝事實非選擇**（FR-002；來源維計數索引既有＝再證）；本刀非一次性遷移、Risk／Guard／Rollback 三欄表免附。
- **原留給 clarify 之十項候選已於 brainstorm 第二輪 grill 定案（該檔 §5）、本 spec 直接採用、clarify 不再以此出題**：①上下文缺席退路＝FR-013；②快取可用性判定點＝FR-036；③降級源新值名與 `ipgate-degraded` 錨＝plan data-model 定名
  （原則＝兩維標籤分流、刪帳號維快取鎖兩源、值集單一權威住既有名冊常數）；④翻 ADR-00029 之 ADR 形＝FR-055；⑤走查工具 seed 模式退出碼＝FR-065；⑥三支依賴版本＝FR-062；⑦wire 裁判面嚴格模式維持不動＝FR-067 ⑦；
  ⑧CDP 構造來源＝瀏覽器網路層 extra header 帶 `X-Forwarded-For`（既有 CDP 工具零改動）、對照 22080 逐項剔除前代後刀差異；⑨水位清理守衛之家與兩表清理形＝FR-063；⑩契約增量檔形＝FR-044、島 E「越界」措辭＝FR-057。
- **信任模型設定源**＝以環境變數指向的 TOML 設定檔、六集合；開發環境最小設定與 compose 掛載已在位（創世承襲）。dev 經反向代理可達之來源信心恰兩態（`fallback`／`proxy_clean`），其餘五態由整合測試直餵信任模型覆蓋。
- **解鎖端點為 API-only**：按鈕歸屬使用者管理頁（尚未建立），本刀不建按鈕與包裝；「端點已備、按鈕待使用者管理頁刀」為已知態並記 BACKLOG。
- **稽核覆蓋不對稱屬刻意最小改動**：既有設定寫端維持不落操作稽核列（002 刀 spec FR-016），本刀只為新端點落列。
- **操作稽核落列與生效次序**：純資料庫路徑（規則四寫端）同交易原子；跨資料庫與快取之路徑（解鎖）稽核先於生效。
- **規則管理契約沿前代最小誠實形**：清單三篩選、審計欄上 wire（操作者名批次回填）、刪除時間與刪除者不上契約、id 為 number＋2^53 守衛。
- **前端語言面不擴**：沿用兩語 runtime locale＋繁中錨點檔；錨點檔只承載後端訊息鍵。
- **前端零測試框架**：前端執行單元之 TDD 迴圈退化為型別檢查＋兩段 review＋CDP 對照走查，以單元 `CONTEXT` 收窄、不動 RULES。
- **Amendment 流程時點**承 003 刀 Q5（draft 於 plan 期、凍結三步為 tasks 首個主線任務）。
- **TDD 發射前置**：各執行單元模型分派依 memory 通則，於發射前向 user 確認。
- **實作紀律引用**（非本 spec 新拍板）：rust build／test 容器內全程 serial；每單元 pin bump；review 只讀不寫；rev5 樹唯讀令烤入 agent prompt。
- **stakeholder 判定承 001～003 前例**：本刀 stakeholder＝admin 後台的超級管理員、稽核者與 workspace 維護者；spec 中的端點路徑／碼／政策座標／軌道名／閘與工具名／設定鍵名係交付物座標（WHAT）與治理設施引用，
  非實作技術選型（HOW）；依賴 crate 名與版本出現於 FR-062 係「釘版紀律」交付要求（選型早由「高度參照 rev5」拍定、版本由 user 於 brainstorm G7 拍板），非本 spec 選型拍板。

### Out of Scope

- **通用化節流 seam**：本刀只交付來源維本體；「可掛任意敏感端點的通用 seam」待第二個消費者出現時再做。
- **改密端點舊密節流**（007 user-password-admin）；`password_*` 設定鍵之跨鍵不變式（BL-00031 餘臂）。
- **稽核管理頁與其查詢端點、存取軌跡 middleware、`sys_access_log` 寫入面**（008 audit-settings-pages；BL-00043 access 面）。

- **地理區欄**：資料檔與查詢元件不搬、該欄維持恆空。
- **prod 資產**：本刀交付部署 checklist 文件、非 prod 配置檔；CDN 邊緣網段清單維持空集。
- **設定寫端跨鍵守衛**（brainstorm Q4）；**壓制麵包屑事件**（BL-00078 決定刪規則）。
- **全域 wire i64 守衛 lint**（`rev5:B-111` 同形；收刀記 BACKLOG）。
- **demo 頁去留**（BL-00064＋BL-00067）；本刀之 HTTP 層轉譯僅順帶改變 demo 頁 toast 文案。

- **BL-00042 原項**（跨刀 Day-1 契約抽出 spec 目錄）：本刀零 migration 不觸發、wire 契約活體權威維持碼＋contract test（brainstorm G2）。
