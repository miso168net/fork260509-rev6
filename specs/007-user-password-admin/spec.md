## User Scenarios & Testing *(mandatory)*

### User Story 1 - 超管使用者管理全套（清單／新增／編輯／刪除／回收桶） (Priority: P1)

超級管理員在使用者管理頁看到現役使用者清單（角色、狀態、會話政策、記事、審計欄），可依帳號名、暱稱、性別、狀態、手機、信箱六欄搜尋；可新增帳號（帳號名、初始密碼〔手輸或隨機產生〕、暱稱、性別、手機、信箱、狀態、角色、記事）、編輯既有帳號（帳號名不可改）、單筆或批次刪除、切到回收桶看已刪帳號並復原——復原後帳號零角色、須重新指派。所有寫入與操作稽核同交易落地，拒因以人話提示；同值送出不寫不記。

**Why this priority**: 本刀本體；rev6 至今使用者只能靠 seed 三帳號，沒有任何運行期帳號治理能力；觸發欄指名 007 之 BACKLOG 多數以「使用者寫端存在」為前提。

**Independent Test**: 以 Super 登入 → 新增帳號 alice（指派自建角色）→ 以 alice 登入成功 → 編輯 alice 改暱稱與角色 → 刪除 alice → alice 既有會話下一次請求即失效 → 回收桶復原 alice → alice 角色欄空白、以原密碼可登入但只得常量路由與個人中心。

**Acceptance Scenarios**:

1. **Given** Super 已登入、seed 三帳號存在，**When** 新增帳號（帳號名合形制且現役唯一、密碼合政策），**Then** 成功、清單出現新列（狀態預設啟用、角色可為空）、稽核一列 `add`；帳號名重複 → `biz.user.userNameExists`；信箱重複（不分大小寫、只比現役列）→ `biz.user.userEmailExists`。
2. **Given** 編輯抽屜，**When** 請求含帳號名欄，**Then** 出現即拒（純 key）；**When** 未改任何值或改成與現值相同即送出，**Then** 零寫入、零稽核、更新時間不動（缺席早退＋值 diff；Q15）；**When** 只改暱稱，**Then** 同交易寫入＋稽核一列 `update`；**When** 清空信箱或暱稱後送出（空字串），**Then** 成功、該欄存為空值（Q16）。
3. **Given** 編輯時送出角色集，**When** 角色欄缺席，**Then** 指派不動；**When** 帶陣列，**Then** 寫後角色集恰等於該陣列（去重）、差集以硬刪＋新增同交易落地；**When** 陣列含不存在或已刪之角色，**Then** 整筆拒（非靜默略過）；**When** 帶空陣列，**Then** 全撤；**When** 與現值同集合，**Then** 屬同值、不寫不記。
4. **Given** bob 持停用中之角色 R_X 與 R_USER_COMMON，**When** Super 開 bob 之編輯抽屜，**Then** R_X 以「（已停用）」灰色選項呈現：不可新選、可移除、送出時預設保留；Super 再加 R_ADMIN 送出 → bob＝{R_X, R_USER_COMMON, R_ADMIN}（Q13）。
5. **Given** 使用者 X 持角色且有多個有效會話，**When** Super 刪除 X，**Then** 同交易：X 軟刪（成對刪除時間與刪除者）、X 之全部角色指派列硬刪、X 之全部有效票撤銷、會話事件記 `revoked`／`user_deleted`、稽核一列 `delete`；X 下一次請求得 `8888`。
6. **Given** 批刪集合含任一 seed 帳號或操作者本人，**When** 提交，**Then** 整批拒（純 key、不指出是哪筆）、零變更；**Given** 空陣列，**When** 提交，**Then** 提前回成功、零變更。
7. **Given** 回收桶含已刪 X，**When** 復原，**Then** 鎖內重驗「同帳號名、同信箱皆無現役列」後清除軟刪標記（撞名回 `biz.user.userNameExists`、撞信箱回 `biz.user.userEmailExists`）；X 角色為空、狀態為刪除前原值；確認框明示「復原後需重新指派角色」；稽核一列 `restore`。
8. **Given** 已刪 X，**When** 對 X 呼叫編輯、踢除、重設密碼、會話政策或刪除，**Then** 一律 `biz.user.notFound`（只有復原認得已刪列）。
9. **Given** 清單與回收桶，**When** 開啟或切換，**Then** 共用分頁信封與固定穩定序；手機、信箱兩欄可以部分字串搜尋（搜尋卡不再擋格式；Q17）；已刪模式隱藏搜尋卡、操作欄換成復原、不加刪除時間欄；記事欄以純文字顯示。
10. **Given** 使用者頁七枚按鈕碼，**When** 以 Super 與 Admin 輪流登入（User 無此頁），**Then** 各按鈕依碼顯隱；Admin 於 seed 預設態（m0003 後）只見清單、無任何操作鈕（GR7）。

### User Story 2 - 斷權：踢除、停用、刪除、重設密碼即刻失效 (Priority: P1)

管理員對某帳號按「踢除下線」，該帳號所有裝置的既有登入立即失效、對方看到「此工作階段已被管理員結束」的提示並可立即重登；停用、刪除、重設密碼三種動作同樣即刻撤銷對方全部登入，對方只看到「請重新登入」，再登入時得到與帳密錯誤無差別的回應（不洩漏帳號被動過）。換發權杖時系統於鎖內重驗帳號仍啟用且未刪；系統不在每個請求查帳號狀態。

**Why this priority**: 沒有斷權的使用者管理是假的——現況下被停用者可持續換發權杖。

**Independent Test**: alice 於兩個瀏覽器登入 → Super 踢除 alice → 兩邊下一次請求皆得 `7777` 與管理員踢除專屬提示 → alice 重登成功；Super 停用 alice → 兩邊皆 `8888`、重登得 `1000`、換發亦被拒；Super 重設 alice 密碼 → 同 `8888`、以新密碼可登入。

**Acceptance Scenarios**:

1. **Given** alice 有多張有效票（含已輪替之歷史列），**When** 踢除，**Then** 全部有效票撤銷、已輪替列不動（重放仍走既有重用偵測）；會話事件 `revoked`／`admin_kick`；alice 下一次請求得 `7777`＋`auth.session.kickedByAdmin`；單一會話被頂替之既有 `7777` 文案 `auth.session.kicked` 不變。
2. **Given** alice 啟用中，**When** 停用，**Then** 同交易撤全部有效票＋會話事件 `user_disabled`；commit 後盡力寫入失效名單；alice 下一次請求 `8888`、換發於鎖內重驗活性後拒、再登入得 `1000`。
3. **Given** alice 啟用中，**When** 管理員重設密碼，**Then** 同上但原因 `password_reset`；以新密碼登入成功。
4. **Given** 操作者本人，**When** 踢除自己，**Then** 拒（純 key）；**Given** 已刪帳號，**When** 踢除，**Then** `biz.user.notFound`；**Given** 停用中帳號，**When** 踢除，**Then** 允許（清乾淨殘留會話）。
5. **Given** 帳號被停用、刪除或其列已不存在，**When** 以仍有效之換發票換發，**Then** 於票列鎖後、簽發前讀帳號判不活 → `8888`（Q12）；換發之鎖序不變、不另取 advisory。
6. **Given** 失效名單寫入失敗（盡力型），**When** 被撤者以既有存取權杖續打，**Then** 至遲於存取權杖到期失效、換發被鎖內重驗擋下（兩層兜底）；系統不新增每請求活性判定。

### User Story 3 - 密碼政策、自助改密與登入表單 (Priority: P1)

系統設定中的密碼政策鍵自本刀起生效：管理員設初始密碼、重設密碼與使用者在個人中心自助改密，三條路徑走同一個驗證點；不合規時逐條告知不符之處，設密過於頻繁時告知還要等幾秒。自助改密須驗舊密碼、新舊不得相同，成功後本人其他裝置登入失效、當前裝置保留；猜舊密碼過多次會被暫時拒絕。任何登入者（含零角色帳號）都進得了個人中心。登入路徑永不驗政策；管理員所設之合規複雜密碼可自登入頁直接登入。

**Why this priority**: 密碼政策鍵上架已久卻零消費者；寫端一進場，「設得進、登不進」即成真缺陷。

**Independent Test**: 以系統設定寫端（008 前無設定頁畫面）把最小長度調 12 → 新增帳號給 11 字密碼 → `2222`＋明細列出「長度未達下限」；alice 進個人中心改密（舊密正確、新密合規）→ 成功、另一瀏覽器之 alice `8888`、當前保留；alice 連猜錯舊密 6 次 → 第 6 次起被拒，15 分鐘後或改密成功後解除；Super 為 bob 設含特殊字元、超過 18 字之密碼 → bob 自登入頁輸入後直接送出並登入成功。

**Acceptance Scenarios**:

1. **Given** 政策最小長度 8 且要求數字，**When** 設密 `abcdefgh`，**Then** `2222`＋`biz.user.passwordPolicy` 攜違規清單（含「要求數字」；全部違規一次收集）；密碼明文與雜湊不出現於回應、稽核、日誌。
2. **Given** 政策「禁止密碼與帳號相同」開啟，**When** 密碼與帳號名不分大小寫相等，**Then** 拒（只含帳號名之子串不算違規）；**Given** 密碼超過 512 bytes，**When** 設密，**Then** 拒（字元數＋位元組數雙約束）。
3. **Given** 最小長度設定值大於最大長度（矛盾組合），**When** 任一入口設密，**Then** 一律拒（安全側）並落一則設定異常告警；登入不受影響（Q19）。
4. **Given** alice 已登入，**When** 自助改密（兩次一致 → 舊密正確 → 新≠舊 → 政策），**Then** 成功、撤銷本人其他有效票並保留當前會話、會話事件 `password_changed`、稽核一列 `change_password`；任一步失敗即回該步拒因、零寫入。
5. **Given** Super 於 T0 重設 alice 密碼，**When** T0＋30 秒再重設（冷卻 60 秒），**Then** `2222`＋`biz.user.pwdSetTooFrequent` 攜剩餘 30 秒；另一管理員同時重設不受限（維度＝標的×操作者）；冷卻設 0 即停用；新增帳號之初始密碼同計入。
6. **Given** alice 連續猜錯舊密碼，**When** 第 6 次（15 分鐘窗內），**Then** 於比對舊密之前即拒（`biz.user.changePasswordThrottled`、純 key）；改密成功即清零；窗自癒、無解鎖端點；計數存放處不可用時放行並計入節流降級計數。
7. **Given** 任一登入者，**When** 讀取密碼政策，**Then** 回七鍵投影（不含冷卻秒數）；個人中心改密卡與重設密碼浮層據以即時提示；讀不到時靜默退為必填、後端仍是唯一裁判。
8. **Given** 零角色帳號，**When** 登入，**Then** 路由含個人中心（自助路由白名單；Q11）、其餘管理頁不可見。
9. **Given** seed 三帳號之密碼短於政策下限，**When** 登入，**Then** 成功（登入路徑不驗政策）；三顆快速登入鈕照留（BL-00049）。
10. **Given** 登入表單，**When** 輸入任意非空帳號與密碼，**Then** 前端只驗必填、格式判定交後端；captcha 軟區零變更。

### User Story 4 - 委派治理：寫端下放＋包含規則、兩處解鎖入口、三頁按鈕碼、自鎖防護 (Priority: P2)

超級管理員以 006 之端點與按鈕授權彈窗，把使用者管理的部分寫端與對應按鈕碼授給其他角色（例如 R_ADMIN）。被授權者進使用者頁只看到被授之按鈕；對任何「持有自己沒有的角色」之帳號操作、或試圖指派自己沒有的角色，一律被拒——規則對所有角色一體適用，持 R_SUPER 者之角色集視為全集故恆過。帳號登入鎖定可在使用者列「解鎖登入」解除（套同一規則），來源 IP 鎖定在 IP 規則頁解除（不套規則）。角色頁與選單頁的新增、編輯、刪除鈕也依按鈕碼顯隱；超管名下角色與選單六碼受保護、撤不掉，選單編輯也不得移除尚有受保護授權之碼，超管不會把自己鎖在角色頁之外。

**Why this priority**: 下放載體（006 授權 UI）與守門本體（包含規則）合起來才是多層管理；預設 seed 仍為 super-only，屬可開關能力、不是預設態，故次於 P1。

**Independent Test**: Super 以授權彈窗把使用者頁選單可見性、清單讀端、updateUser 端點與 `user:edit` 碼授給自建角色 R_DEL，並指派給自建帳號 dora（持 R_DEL）→ dora 可編輯持 {R_DEL} 之帳號；對 Super 編輯 → `5003`；把某帳號指派 R_SUPER → `5003`；Super 再於「按鈕權限」彈窗取消自身之 `role:edit` → 整批拒、零變更；於選單頁自角色管理選單之按鈕清單刪除 `role:edit` → 整筆拒。

**Acceptance Scenarios**:

1. **Given** 操作者現役角色集 A、標的全部指派列 T、寫後角色集 N，**When** 任一使用者寫端（新增／編輯／刪除／批刪／復原／踢除／重設密碼／會話政策）或 unlockLogin 帳號維執行，**Then** 鎖內、寫入前判 T⊆A∧N⊆A，違者 `5003`（純 key、不洩漏差集）、零變更、零稽核；持 R_SUPER 之操作者 A＝全集、恆過。
2. **Given** Super（只持 R_SUPER）與持 {R_ADMIN} 之帳號 Y，**When** Super 編輯 Y 並指派 R_USER_COMMON，**Then** 成功（A＝全集之正向案；照字面 A＝{R_SUPER} 會誤拒）。
3. **Given** 標的所持某角色被停用，**When** 未持該角色者操作標的，**Then** 仍 `5003`（T 不濾角色狀態）；**Given** 操作者所持某角色被停用，**When** 該操作者操作持該角色之標的，**Then** 該角色不計入 A（`5003`）。
4. **Given** 持相同角色集之甲與乙，**When** 甲停用、刪除或踢除乙，**Then** 允許（同級互管）、稽核記甲。
5. **Given** 回收桶中曾持 R_SUPER 之 X（指派已隨刪除硬刪、T＝∅），**When** 被授復原者復原 X，**Then** 允許、X 復原後零角色。

### Edge Cases

**使用者寫端**

- seed 帳號結構保護：id 1／2／3 不可刪（批刪含之整批拒）；Super（id 1）恆禁停用、恆禁解除其 R_SUPER 指派；拒因純 key。
- 本人五不：不得刪除、停用、踢除、改自身角色指派、以管理頁重設自己密碼；本人可改自己的非角色欄與會話政策；前端本人列之狀態與角色控制項停用、操作下拉不列重設密碼。
- 零角色帳號：可建立、可登入；只得常量路由＋個人中心（自助路由白名單）；N＝∅ 恆滿足包含規則。
- 前超管復原：回收桶中 T＝∅ ⇒ 任何被授復原者皆可復原；復原後零角色；要回超管須持 R_SUPER 者指派。
- 併發：同一標的之兩個寫端於 per-user advisory 序列化、lock-then-redecide；新增帳號無既有標的、不取 advisory，同名並發由現役唯一索引兜底；角色指派寫端與刪除角色併發時，以角色列鎖之鎖內重判避免指派到已刪角色（工程判斷②）。
- 信箱唯一：不分大小寫、只比現役列；已刪列與現役同信箱並存合法；復原時鎖內重驗帳號名與信箱兩腿。
- 空字串：可空文字欄（暱稱、手機、信箱、記事）之空字串新增與更新皆＝清空存空值；值 diff 於歸一後比對（Q16）。
- 角色 id 界外：不存在或已刪之角色 id → 整筆拒、非靜默略過（角色是指派主體、不是候選集過濾；與 006 授權彈窗之略過不同形）。
- 持停用角色：清單帶持有角色之 id、代碼與名稱；抽屜灰色保留選項；角色欄只在改動時才送（Q13）。
- 值域：狀態讀向二值收斂（存 1＝啟用、其餘＝停用）、寫向恰二值嚴格解析（值域外與 null＝缺席；ADR⑦）；會話政策三值（inherit／single／multi、必填、值域外拒）；帳號名形制 `^[A-Za-z0-9_-]{1,64}$`、建後不可變；密碼 ≤512 bytes；手機不守長度（`rev5:ADR 0069` 形）。
- 同值 no-op：使用者域寫端「缺席早退＋值 diff」、會話政策寫端「值 diff」（`sessionPolicy` 必填——缺席、null、空字串、值域外一律拒，同 rev5 HEAD 與 ADR-00047 決定 1）——同值零寫入、零稽核、不動更新時間；角色選單域續 ADR-00047 決定 3（同值照寫照稽核）＝逐域差異由 ADR⑦ 明文。
- 並行編輯：兩位管理員同時編輯同一帳號時，抽屜之狀態與角色只在改動時才送（舊值不會把他人剛停用之帳號啟用回來、也不覆蓋他人之指派）、會話政策改動時另打其端點；其餘恆送欄（暱稱、性別、手機、信箱、記事）後送出者為準＝已知態（rev5 HEAD 同形；落點＝ADR⑦）。
- 請求上下文缺席（操作者不可得）→ 寫端拒寫 `5000`、不以佔位補稽核列。
- body 缺席或壞形 → 依既有 wire 慣例以共用件收斂為預設值（標的 id 預設值不對應現役列 → `biz.user.notFound`）；不新增錯誤碼、授權中介層不讀 body。

**包含規則與委派**

- 持 R_SUPER 者之 A＝全集：對任何標的與指派恆過；seed 保護與本人五不仍先判。
- 停用角色：計入標的 T、不計入操作者 A；停用角色之指派列不硬刪（只有軟刪使用者才硬刪指派）。
- 按鈕碼與端點授權各自獨立：碼有端點無＝鈕見而 `5003`；端點有碼無＝鈕不見而 API 可達。
- Admin 於 seed 預設態只見使用者清單（m0003 刪其 `user:edit`；GR7）；要讓 Admin 能編輯＝超管於角色頁同授端點與碼、由包含規則兜底。
- unlockLogin 授予非超管（006 已知態「授出後無帳號維守門」）：本刀起帳號維套包含規則、來源維不套。
- 包含規則違反（`5003`）與既有撤銷拒、封死拒之判定位次不互吞；違反記一則 warn 日誌（操作者 id、標的 id、端點；不含角色差集）、不新增觀測序列。

**斷權與會話**

- 管理員踢除（`admin_kick`、`7777`＋`auth.session.kickedByAdmin`）與單一會話頂替（`kicked`、`7777`＋`auth.session.kicked`）文案分立；撤銷（`revoked`、`8888`）靜默；三者不互換（島 C）。
- 失效名單為盡力型：commit 後寫入失敗只記警告、資料庫為權威（換發鎖內重驗兜底）。
- 換發重驗：帳號列已不存在＝不活；重驗讀不取 advisory、不改換發鎖序。
- 會話政策改為 single 不即時踢除，下次登入才生效。
- 自助改密成功撤本人其他會話、保留當前會話（身分帶會話 id）。
- 角色寫端（停用角色、改角色授權）不連動撤會話（ADR-00043 決定 8 失效條件記「已核未觸發」）。

**密碼面**

- 冷卻邊界：設 0 停用；剩餘秒數＝冷卻秒數扣除已過整秒數（已過秒數下取整）、下限 1、上限冷卻秒數（時鐘回撥）＝照提示秒數重試必過（rev5 HEAD 同形）；不同操作者互不影響；經手表只做 upsert、不做「自改即全刪」。
- 改密節流：計數存放處不可用時放行（不計數、不拒）並計入節流降級計數之新來源；成功改密即清；無解鎖端點（窗自癒）；與登入節流之鍵分離；同一帳號同時送出之多筆改密請求合計亦受同一上界（並發不得放大可猜次數）；計數值損毀（非整數或型別不符）時下一次失敗即自癒重新起算、自癒本身不計降級；帳號鎖內之讀桶與推進各以 1 秒為上界、逾時視同不可用（後三項為本刀 U13 期間增補＝BL-00144、ADR-00090）。
- 政策矛盾（最小長度＞最大長度）：設密全拒＋設定異常告警；設定寫端照舊不守；登入不受影響；與島 E「整組退回預設」方向相反＝跨島註入憲。
- 政策鍵只在消費當下讀現值（不快取）；密碼明文與雜湊三重不洩（回應、稽核、日誌）。
- 雜湊於交易內、不持列鎖時計算（島 I5 釐清）。

**前端與按鈕碼**

- 三頁按鈕碼：使用者頁七碼逐鈕、角色與選單頁依既有 add／edit／delete 碼（對碼表見 FR-048）；被授角色頁可見性之 Admin 只見所持碼之鈕。
- 非超管之會話政策欄停用＋提示；前端不預判包含規則（被拒走 `5003` 提示）。
- 錯誤明細只轉譯兩鍵（違規清單、剩餘秒數）；其餘錯誤仍純 key 提示。
- 搜尋卡手機與信箱接受部分字串；新增抽屜之手機照舊不驗格式。
- 已知態：使用者詳情頁續為佔位（seed-view-gate 對賬、佔位檔不可刪）；個人中心其餘卡位留白；三顆快速登入鈕刀期必留（BL-00049）；系統設定與稽核兩頁仍為死項（008、CDP 排除清單）。

**自鎖防護與 seed 基線**

- R_SUPER 名下角色與選單六碼受保護、撤不掉；其餘碼（`user:*`、`ipRule:*` 等）仍可撤，誤撤可經角色頁加回（`role:edit` 已受保護）。
- 選單編輯移除按鈕碼（含改碼＝移除舊碼）而該碼尚有受保護授權列 → 整筆拒；刪除角色管理頁或選單管理頁之選單本身已由受保護選單守門擋下。

**B. 使用者寫端語意（島 I1／I3／I4）**

- **FR-010**: 八支使用者寫端 MUST 依固定序判定：①活性標的鎖讀 → ②seed 保護 → ③本人規則 → ④包含規則 → ⑤業務守門；任一拒＝整筆 rollback、零變更、零稽核。逐支之空格 MUST 以測試釘住空格理由：

  | 寫端 | ①活性標的鎖讀 | ②seed 保護 | ③本人規則 | ④包含規則 | ⑤業務守門（舉要） |
  |---|---|---|---|---|---|
  | addUser | 無既有標的（不取 advisory；同名並發由現役唯一索引兜底） | 不適用 | 不適用 | N⊆A（T＝∅） | 帳號名形制與現役唯一、信箱格式與現役唯一、角色 id 皆存在且未刪、密碼政策、設密冷卻 |
  | updateUser | 鎖現役列 | Super 恆禁停用、恆禁解除其 R_SUPER 指派 | 本人之狀態與角色欄出現即拒、其餘欄可改 | T⊆A∧N⊆A | 帳號名出現即拒、信箱、角色 id、值 diff no-op |
  | deleteUser | 鎖現役列 | 三帳號不可刪 | 不得刪本人 | T⊆A（N＝∅） | —— |
  | batchDeleteUser | id 升序去重、同交易逐 id 鎖 | 含任一 seed 帳號整批拒 | 含本人整批拒 | 逐筆 T⊆A | 空陣列提前 no-op；任一違規整批 rollback、不指筆 |
  | restoreUser | 鎖已刪列 | 結構性不可達（seed 帳號不可刪） | 結構性不可達（本人不可刪） | T⊆A（T＝∅ 恆成立） | 同帳號名、同信箱皆無現役列（撞名 `userNameExists`、撞信箱 `userEmailExists`） |
  | kickUser | 鎖現役列 | 空（Super 可被踢） | 不得踢本人 | T⊆A | —— |
  | resetUserPassword | 鎖現役列 | 空 | 不得以本端點重設本人 | T⊆A | 密碼政策、設密冷卻 |
  | updateUserSessionPolicy | 鎖現役列 | 空 | 空（本人可改） | T⊆A | 三值收斂、值域外拒、值 diff no-op |

- **FR-011**: 交易與鎖序 MUST：handler 持交易、寫端之交易內主體首句取 per-user advisory（既有共用件）→ 使用者列 `FOR UPDATE`（活性濾軟刪、不看狀態；restoreUser 鎖已刪列）→ 角色列依 id 去重升序 `FOR UPDATE` 並於鎖內重驗未軟刪（工程判斷②；批次寫端整批聯集一次升序）→ 指派全量替換；lock-then-redecide、永不信 pre-read；指派寫端 MUST NOT 入選單序列化域；ADR-00043 決定 8 之無 ABBA 論證於 ADR 重核（角色域寫端不取 per-user 鎖、指派寫端不入選單域＝不成環）。
- **FR-012**: addUser MUST 收帳號名（形制守門、現役唯一）、初始密碼（走政策、走冷卻、寫經手表）、暱稱、性別、手機（選填、不守長度）、信箱（選填、簡式格式、現役唯一不分大小寫）、狀態（預設啟用）、角色集（可空）、記事；空字串＝空值（Q16）；密碼雜湊於交易內、不持列鎖時計算。
- **FR-013**: updateUser MUST 採部分更新三態（缺席＝不動、null＝清空、值＝設值），可空文字欄之空字串＝清空（Q16）；帳號名出現即拒；no-op 判準＝先全缺席早退、再於值域歸一（空字串＝空值、角色集以集合比）後比對現值——同值零寫入、零稽核、不動更新時間（Q15）；角色集 MUST 為期望全集、全量替換（缺席＝不動；陣列＝寫後角色集恰等於之、去重、含不存在或已刪角色 id 則整筆拒；空陣列＝全撤；差集以硬刪＋新增同交易落地；稽核一列 `update`）。使用者域此口徑與角色選單域（ADR-00047 決定 3）不同、MUST 由 ADR⑦ 明文逐域差異。
- **FR-014**: deleteUser／batchDeleteUser MUST 於通過守門後同交易：軟刪（成對刪除時間與刪除者）→ 硬刪該使用者全部角色指派列 → 撤銷全部有效票 → 會話事件 `revoked`／`user_deleted` → 稽核 `delete`；批刪任一違規整批 rollback、拒因純 key 不指筆、空陣列提前 no-op。
- **FR-015**: restoreUser MUST 鎖已刪列 → 鎖內重驗同帳號名、同信箱皆無現役列（撞名回 `biz.user.userNameExists`、撞信箱回 `biz.user.userEmailExists`）→ 成對清除軟刪標記；MUST NOT 回灌角色指派（復原後零角色）；狀態保留刪除前原值；稽核 `restore`。本條即 ADR-00044 觸發器①之答案（軟刪者已無指派⇒「使用中」口徑不必改）。
- **FR-016**: 對已軟刪標的之 updateUser／kickUser／resetUserPassword／updateUserSessionPolicy／deleteUser MUST 一律回 `biz.user.notFound`（活性判準＝未軟刪）；只有 restoreUser 認得已刪列。
- **FR-017**: seed 帳號結構保護 MUST 為碼內常數形：id 1／2／3 不可刪；id 1 恆禁停用、恆禁解除其 R_SUPER 指派；本人五不（刪除、停用、踢除、改自身指派、以 resetUserPassword 重設本人）各配純 key 拒因；本人可改非角色欄與會話政策。
- **FR-018**: updateUserSessionPolicy MUST 三值收斂（inherit／single／multi；`sessionPolicy` 必填——缺席、null、空字串、值域外一律 `2222`，同 rev5 HEAD 與 ADR-00047 決定 1）；同值 no-op（值 diff；本端點無全缺席早退）；改為 single MUST NOT 即時踢除（下次登入才生效）；對已刪標的 `biz.user.notFound`。
- **FR-019**: 記事欄 MUST 於清單以純文字插值顯示、抽屜多行編輯；MUST NOT 出現在下拉、引用或對外之其他 API。
- **FR-020**: 持停用角色之帳號（Q13；ADR⑧ 款 7＝`rev5:B-145` 結案）：清單列 MUST 帶持有角色之 id、代碼與名稱；抽屜 MUST 以「（已停用）」灰色選項呈現持有之停用角色（不可新選、可移除、送出時預設保留）；角色欄 MUST 只在改動時才送。

**C. 包含規則（島 I7）**

- **FR-021**: 八支使用者寫端與 unlockLogin 帳號維（共 9 個消費點）MUST 於鎖內、任何寫入前判包含規則：A＝操作者現役角色集（濾軟刪與停用角色、資料庫現讀；★持 R_SUPER 者之 A 視為全集）、T＝標的全部指派列所指角色（不濾角色狀態、濾已軟刪角色——生產等價：使用中角色不可刪，濾之只使直改庫殘列不致標的永久不可治理）、N＝寫後標的角色集；MUST T⊆A∧N⊆A，違者 `5003` 純 key、零變更、零稽核、記一則 warn 日誌（操作者 id、標的 id、端點；不含角色差集）、不新增觀測序列；判定位次＝固定序第④（FR-010）；同級互管允許；unlockLogin 來源維不套。
- **FR-022**: 判定 MUST 以具名純函式單點實作、9 個消費點共用、於 handler 路徑鎖內呼叫；中介層之 no-escalation 掛點續留恆放行（ADR-00014 決定 5 之掛點簽章無 body）；ADR② MUST 寫明兩實作位之射程分工、ADR-00064 觸發器首條與次條之複核結論（判定位次與拒因鍵不與撤銷、封死互吞；正交分工維持；授權回收桶復原不掛）；BL-00048 以兌現連動面收（enforce 模組註與掛點 doc 兩處預告、002 FR-013 讀法）。
- **FR-023**: 包含規則射程 MUST 只限使用者域與 unlockLogin 帳號維（Q7）：角色域、IP 域與授權回收桶復原續 ADR-00068 款 9 已知態；ADR② MUST 寫複核結論與不掛理由。
- **FR-024**: 前端 MUST NOT 預判包含規則（角色下拉全列、列級鈕只依按鈕碼顯隱）；只在非超管時停用會話政策欄（顯示現值＋提示、MUST NOT 發出必敗呼叫）、並停用本人列之狀態與角色控制項。

**D. 斷權（島 I2；島 B／C 用語）**
